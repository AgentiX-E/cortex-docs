The script below is the exact sequence that produced this file. Thirteen invocations,
each its own process, so the state has to be on disk for the next one to see it.
The only step that loads a model is `propose`.

The last four are the output side: `check <task> "<draft>"` runs O1 (the rule table),
O2 (citations) and O3 (verbatim echo) over a draft, using the same stores that wrote it.
