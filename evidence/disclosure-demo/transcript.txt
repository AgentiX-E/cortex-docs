The script below is the exact sequence that produced this file. Fourteen invocations, each its own
process, so the state has to be on disk for the next one to see it. The only step that loads a model
is `propose`.

The last three are the output side and the configuration failure:

  * `check <task> "<draft>"` runs O1 (the rule table), O2 (citations) and O3 (verbatim echo) over a
    draft, using the same stores that wrote it;
  * `propose c4 --llm remote` with no key **fails** -- it does not fall back to the checkpoint. That
    is the assertion the replay script makes, because a silent downgrade would let a transcript claim
    an API model while a 0.5B model produced every atom.

Two things to notice while reading. The profile line is printed before the proposal, because a
transcript that does not name its configuration cannot be compared with another one. And this
sentence yields **three** atoms: prompt v3 was tried here and produced one (docs/04 section 9.17
records both runs and why v3 was reverted).
