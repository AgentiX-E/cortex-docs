The script below is the exact sequence that produced this file. Eighteen invocations, each its own
process, so the state has to be on disk for the next one to see it. The only step that loads a model
is `propose`.

What each group shows:

  * `say` + `cards` + `propose` + `accept` -- a credential is never stored, a sentence the rules
    already answered never becomes a question, and a deferred sentence's atoms are published one at
    a time;
  * `check <task> "<draft>"` -- O1, O2 and O3 over a draft, using the same stores that wrote it;
  * `release <id>` -- the door out of the private store for a sentence a rule kept private. The first
    attempt has no token and is refused with the rule and its policy; the second carries the token and
    leaves a record in its own table;
  * `propose --llm remote` without a key -- an error, not a fallback to the checkpoint.

Two things to notice while reading. The profile line is printed before the proposal, because a
transcript that does not name its configuration cannot be compared with another one. And the release
warning names the rule and quotes the policy *before* the token is accepted: an override that is
merely a click is not an override, it is a mis-click.
