# P21 判决 —— 重试被证伪，而真正的瓶颈是答案会话的轮覆盖率

**一句话读法**：弃权重试完全按设计部署——在 500 中武装 413，触发 22，转化 **0**——因为它所依据的前提
在 MR 之外不迁移。它拦截的那些问题之所以拒绝，是因为**回答轮从未被检索到**，
而不是因为模型跳过。−1.40 pp 的要点数字**在统计上与运行间方差无法区分**，不可归因于
这一改动。调查重定向到真正的瓶颈，而它现在已被度量：**答案会话轮覆盖率**。

## 1. 改了什么，以及它建立在什么之上

`enableAbstentionRetry` **在构造上就是惰性的**，源于两处相互独立且
相乘的故障：

1. **范围** —— 只有 `answerSessions` 计算了该标志；其他每一个调用方都让它
   保持默认 `false`。
2. **检测器** —— `detectBareAbstention` 检验原始字符串，而 `parseQaAnswer`
   先剥离 `Answer:` 标签。因此 `Answer: UNANSWERABLE`，即提示词所请求的确切拼法，
   对重试是不可见的。

二者都是真实缺陷，二者都已在 `a3a354e` 中修复并验证（三个相互独立的
中性化：检测器 → 3 个失败，范围 → 4 个，ABS 选择退出 → 1 个）。该**修复**是
正确的；它所服务的**假设**不是，而本次运行度量了这一点。

该假设来自 MR：在 11 道弃权的 MR 问题中，**10 道在重问下恢复**。
这被读作"一个裸弃权是一次跳过——模型拥有证据，却拒绝花费 token"。§3 表明它是一个 MR 特有的
伪影。

## 3. 为什么它什么都没转化——前提不迁移

重试的前提预测第一遍*拥有*证据却扣着不用。我
检验了标准答案值是否甚至存在于提示词负载中
（`decision.retrieved`；检验是保守的——先精确子串，再数值
相等，再 ≥12 字符的逐字串）。

| 总体 | n | 负载中的标准答案值 |
|---|---|---|
| 那 22 道重问问题 | 22 | **5** |
| 其中，重问后仍拒绝的 | 21 | **5** |
| TR/IE **未**重试就答对的（对照类） | 231 | 123 (53.2 %) |
| 弃权，重试**未**触发 | 29 | 6 (20.7 %) |

对照类作了裁决。当 TR/IE 问题被**正确**回答时，标准答案值在
**53.2 %** 的情况下存在。当重试触发时，它在 **22.7 %** 的情况下存在——在统计上与重试正确留下不管的那些弃权（20.7 %）
无法区分。

因此重问并非拒绝作答；它读的是一个**不包含答案**的提示词。`Answer: UNANSWERABLE` 是检索阶段的**正确**输出。重问*同一个提示词*在构造上
无法修复这一点。唯一那一次 MR 触发 `8e91e7d9`，其值**确实**存在——这正是
MR 证据看起来如此强的原因。

**结论："一个裸弃权是一次跳过"是 MR 特有的伪影。** 在 TR 上 17 次触发中 0 次、在 IE 上 4 次触发中
0 次拥有标准答案值。重试把一个修复机制推广到了并不共享该失败模式的
能力上。

## 4. −1.40 pp 不可归因于这一改动

要点：426/500 = 85.20 % → 419/500 = 83.80 %，**−7 questions = −1.40 pp**。

| 能力 | n | 基线 | 修复 | Δq |
|---|---|---|---|---|
| IE | 150 | 96.00 % | 96.00 % | +0 |
| MR | 121 | 90.08 % | 85.95 % | **−5** |
| KU | 72 | 79.17 % | 80.56 % | +1 |
| TR | 127 | 70.87 % | 68.50 % | **−3** |
| ABS | 30 | 86.67 % | 86.67 % | +0 |
| | | | | **−7** |

重试的因果足迹占这 7 个中的 **1** 个。另外 6 个是问题上的翻转，其中两次运行都未弃权、重试也从未
触发。

**对 8 个在足迹之外的翻转做符号检验**（2 增益，6 损失）：精确双侧
p = **0.2891** —— 不显著。（在 n=8 时只有 ≥7–1 的划分才达到 p<0.05，因此这
排除的是*大*不对称，更小的什么都排除不了。作为一项限制陈述，而非辩护。）

**MR 的 −4.13 pp 对照其自身方差。** 8 次运行的相同配置 MR 面板是
均值 79.13 %，sd **3.12 pp**；两次独立抽取之差的 sd 为
4.41 pp，因此 z = **−0.94** —— 在一个 sd 之内。而且 90.08 % 这个"基线"是面板
**最大值**：仅向面板均值回归就预测 −10.95 pp，无需任何代码
改动。观测到的 −4.13 pp *小于*纯回归，因此这里没有 MR
信号需要解释。

**本次运行是一次负方差抽样。** 把 −1.40 pp 报告为重试的效应
将是把噪声读成结果。

## 5. 处置

**保留修复，丢弃预期。** 两处被修复的缺陷都是真实的；
回退将重新引入一个真实的 bug 以移除一个惰性功能。但重试
只在其前提成立之处才配得上它的存在，而那只有 MR。

| 选项 | 证据 | 成本 |
|---|---|---|
| **把重试限制到 MR** | 唯一有证据支持的范围；那唯一一次 MR 触发的值确实存在。每次运行移除 21 次空操作重问。 | 小；丢弃 3 次同样什么都没做的 TR/IE 触发 |
| 保持范围全局，不期待任何东西 | 22 次触发，0 增益——一次已度量的空操作 | 保留未度量的墙钟/token 成本 |
| 完全回退 | 被反驳——缺陷是真实的 | 重新引入一个对 `Answer: UNANSWERABLE` 视而不见的检测器 |

建议：**限制到 MR**，作为对一项未度量成本的行为保持式清理。它
不是一项性能主张，且不得被描述为一项。

**不要进一步迭代重试。** 第二次重问面对同一堵墙——提示词
未变，因此一次证据缺席的拒绝会确定性地重现。
全部 21 次仍然拒绝都返回了一个字节完全相同的 12–20 字符 `UNANSWERABLE`，这正是
一个稳定判断的样子，而不是跳过。

## 6. 真正的瓶颈，现已度量：答案会话轮覆盖率

我把两个此前被混为一谈的可达性检验分开了，因为它们回答的是
不同的问题，而二者之间的差距就是发现所在：

- **检验 A（会话可达）** —— 一个被标注答案会话的*文本*是否存活到
  `decision.retrieved` 中？（30 字符 shingle，跨每一轮采样。）
- **检验 B（值可用性）** —— *标准答案值*是否字面存在？

二者都正确。当 A=true 且 B=false 时，检索到达了正确的**簇**
却错过了**携带该值的轮**。分解全部 74 个失败：

| 判决 | n | 份额 |
|---|---|---|
| 会话到达，答案轮缺失（**TURN COVERAGE**） | **45** | **60.8 %** |
| 证据完整，答案错误（**DECISION**） | 28 | 37.8 % |
| 证据完全缺席（**SESSION RECALL**） | 5 | 6.8 % |

按能力看，TR 是质量集中之处（40 个失败）：**24 个轮覆盖率**、
12 个决策、3 个会话召回。

### 覆盖率几乎单调地预测正确性

| 答案会话的覆盖率 | n | 正确 | 准确率 |
|---|---|---|---|
| 0 %（什么都没存活） | 3 | 1 | 33.3 % |
| 1–49 % | 90 | 59 | 65.6 % |
| 50–99 % | 350 | 303 | 86.6 % |
| 100 %（全部轮在场） | 57 | 56 | **98.2 %** |

而且它以同样的方式预测**弃权**：弃权率在 0 %
覆盖率时为 66.7 %，在 1–49 % 时为 16.7 %，在 50–99 % 时为 8.3 %，在 100 % 时为 7.0 %。重试被建造来修复的那些裸弃权是
**轮覆盖率的输出**，不是
不情愿的输出——这与 §3 是同一结论的第二个方向。

### 这是一个排序问题，不是容量问题

| 检索到的 blob | n | 平均答案会话覆盖率 |
|---|---|---|
| <6k | 22 | 51.3 % |
| 6–9k | 152 | 52.7 % |
| 9–12k | 81 | 51.1 % |
| 12–18k | 89 | 58.9 % |
| >18k | 156 | 74.0 % |

覆盖率随提示词增长而**持平或上升**，且 corr(blob, coverage) 为
−0.14 (TR)、−0.02 (MR)、−0.06 (KU)——即本质上为零，而对 IE
为*正*（+0.53）。更大的预算买不到覆盖率，因此这**不是**截断。
回答轮输给了仅仅共享词汇的轮。`[truncated]`
出现在 500 个 blob 中的 268 个，因此截断是活跃的，但不是这里起约束作用的
限制。

最可执行的单个数字：**当答案会话完整在场时，
准确率为 98.2 %（57 中的 56）。** 唯一的例外是 `7a8d0b71`（IE），并且它是有教益的
而非反例：它的答案会话 100 % 在场，它的
blob 是语料库中最大的，为 **22,256 chars**，而它**还是弃权了**。
这是整次运行中唯一一次证据可用而
模型仍然拒绝的触发——重试被正确瞄准的唯一案例，而它
失手是因为提示词太长，不是太空。

### 稳健性：该排序在经过一个独立、更严格的检验后依然成立

98.2 % 这个数字使用了采样的 30 字符 shingle，因此它原则上可能是
一个宽松成员资格规则的伪影。用一个**更严格且独立构造**的规则重跑——每个答案轮必须包含 **3 个不相交的
40 字符窗口**，全部在场，不做采样——该排序成立，且
如果说有什么不同的话是更分明：

| 严格覆盖率 | n | 准确率 |
|---|---|---|
| full (all turns, 3 windows each) | 14 | **100.0 %** |
| partial | 479 | 84.1 % |
| none | 7 | 28.6 % |

单元格大小变化是因为更严格的规则更难满足，不是因为
现象脆弱。两个规则都给出 full > partial > none 的排序，因此该
结论不依赖于成员资格阈值。

## 7. 本遍发现的两处仪表缺陷

二者都是通过与一个真值来源交叉核对而被抓住的，且二者本都会
无声地污染结论：

1. **`p20_compare.mjs` `cap()`** —— `MR_diagnostics.json` 行**没有**携带
   `capability` 字段（只有那 379 行单会话行携带），因此 121 行 MR 落入了
   一个 `'multi-session'` 占位符，从未匹配 `'MR'`，打印出
   `NaN%`。修复方式是*从该行所来自的文件*取能力，再加上一个
   断言，即按能力分列的行对得上要点（现为 426/426 和
   419/419）。
2. **`answer_sessions_content` 不可用** —— 在全部 379 行单会话行上为 `''`，
   在 121 行 MR 行上是一个裸会话 ID 列表（最大长度 **5**）。任何
   建立在它之上的证据成员资格检验都是空洞的。我自己在 §3 的第一遍读了
   这个字段，产生了一个虚假干净的"21/22 缺席"，直到交叉核对
   抓住了它。真实负载是 **`decision.retrieved`**。早先"74 个失败中只有 2 个
   是召回失败"的读法同样是字段受限的，并被 §6 取代。
