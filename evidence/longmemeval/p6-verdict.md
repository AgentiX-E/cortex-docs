# P6 —— 修复后的第一次运行实际展示了什么

## 摘要

运行 `34586809021`（位于 `f470f5b`，答案缓存修复后的第一次运行）**部分**
成功，而诚实地读它改变了三个结论：

1. **答案缓存修复在它能起作用的地方起作用了。** IE（150 道）和 MR（121 道）达到
   **0 破坏 / 0 修复** —— 271 道题恰好配对。修复之前，那些块带有重新查询噪声。
2. **它并未覆盖一切。** KU 仍显示 **0 破坏 / 1 修复**，且那点残余有一个真实的原因：
   `completeStructured` 是一个独立的 LLM 入口点，从未被缓存。已在 `624e241` 中修复。
3. **剩下的 TR 不一致根本不是缺陷**，而我的不变量检查把它标记出来是错的。
   已在 `validate_fix.py` 中更正。

## 1. 三个发现中有两个是我的，而非代码的

在描述该运行展示了什么之前，先记录我弄错了什么：

| 我提出的主张 | 该运行展示的 | 更正 |
|---|---|---|
| 该修复清除了配对不变量。 | IE/MR 清除了；KU 没有。 | 已验证，然后妥善修复（`624e241`）。 |
| TR 的 `1 broken / 0 repaired` 是一次违规。 | 全部 16 次 TR 弃权都评为 `false`，而基线从不弃权。 | **不是缺陷** —— 是有意为之的弃权对比。工具已更正。 |
| 一个在*消融*实验臂上的结构化缓存测试证明了该修复。 | 只有一个 KU/TR 消融实验臂启用该路径，因此没有任何东西被去重。 | 测试是空洞的；已针对主基准重写，那里两个实验臂都运行它。 |

第三个是值得细想的那个。我写了一个测试，它通过了，而它**不可能失败** ——
KU 消融只在一个实验臂中启用双时间路径，因此对一次调用做“只发送一次”的断言
平凡为真。我之所以捕获到它，只是因为我对它做了变异测试，而非信任一个绿色的测试套件。
这与原缺陷是同一失效模式：一个为它并不检查的保证背书的测试。

## 2. 经测量的机制

违规位于**主**报告中，其两个实验臂只在弃权上不同。这很重要，
因为它决定了一个不一致对可以意味着什么：

| 方向 | 机制 | 它是缺陷吗？ |
|---|---|---|
| `baselineCorrectFeatureIncorrect` | 特征弃权了（评为 `false`）；基线从不弃权且回答正确。 | **否** —— 有意为之的弃权对比。 |
| `baselineIncorrectFeatureCorrect` | 特征在基线错的地方对了，且不涉及弃权。 | 视情况 —— 需要一个解释。 |

`34586809021` 中的按能力码计数：

| 能力码 | 总计 | 破坏 | 修复 | 特征弃权 |
|---|---|---|---|---|
| IE | 150 | 0 | 0 | 4 |
| MR | 121 | 0 | 0 | 0 |
| KU | 72 | 0 | **1** | **0** |
| TR | 127 | **1** | 0 | 16 |
| ABS | 30 | 0 | 28 | 28 |

TR 那一个被破坏的对坐落在 16 次弃权之内，全部评为 `false` —— 完全得到解释。
KU 那一个被**修复**的对在该能力码中**零**弃权，因此弃权机制中的任何东西
都无法解释它。那是一个真正的残余，也是本次运行实际在报告的那一个。

## 3. KU 残余的根因

`tryBitemporalKnowledgeUpdate` 返回时**没有经过 `respondWith`**，
因此它既不咨询弃权门也不咨询答案缓存。它是唯一一条既 (a) 绕过 `respondWith`
又 (b) 调用 `completeStructured` 的路径。

直接测量：在答案缓存共享、无结构化缓存时，一个 KU 抽取提示词在该次运行的
实验臂之间被发送了 **6 次**。接入结构化缓存后，**1 次**。两个方向都经变异验证。

这就是为什么 IE 和 MR 是干净的而 KU 不是 —— IE/MR 完全通过 `complete` 作答，
而答案缓存已经覆盖了它。这一划分干净到足以仅凭数据就能点出缺失的入口点。

## 4. 修复（`624e241`）

- `structuredCache`，以**完整提示词 + 序列化 schema**为键（提供方内联接收 schema，
  因此同一提示词在不同 schema 下就是不同的请求）。
- 失败**不**被缓存，因此回退从不依赖于哪个实验臂先运行。
- 所有结构化调用都经由一个辅助函数路由；接入每一对消融
  （6 处声明，12 个点位），与答案缓存完全对应。

测试（663 → 666），全部经变异验证：

| 测试 | 何时失败 |
|---|---|
| 主基准不重新发送任何结构化提示词 | 运行器停止传入 `structuredCache` |
| 只共享结构化缓存的两个系统只发出一次调用 | 缓存未被咨询 |
| 同上，带一个非空洞断言 | 上述任一情况 |
| 辅助函数记录结构化提示词 | —（这正是隐藏了原 bug 的工装缺口） |

## 5. 一个工具 bug，已更正

`check_pairing_invariant` 把**任何**非零不一致计数都当作违规，
这会把 TR 的弃权对比标记为缺陷，并夸大问题。它现在把每个能力码的弃权计数
计入 `broken` 方向，并把 `repaired` 方向视为需要解释。在更正后的逻辑下，
`34586809021` 报告**恰好一个**真正的残余（KU），这与独立的根因分析相符。

## 6. 验证 —— 已确认

运行 `34594513996`（位于 `624e241`）返回**成功**，该修复已端到端确认。

**配对不变量现在成立。** 在 470 道已诊断的题上，每一个非 ABS 能力码都是
0 破坏 / 0 修复：

| 能力码 | 总计 | 破坏 | 修复 |
|---|---|---|---|
| IE | 150 | 0 | 0 |
| MR | 121 | 0 | 0 |
| KU | **72** | **0** | **0** |
| TR | 127 | 0 | 0 |
| ABS | 30 | 0 | 26 |

KU 块是重要的那一个：它从 **0/1** 变为 **0/0**，这正是 `624e241` 所针对的
特定残余。ABS 的 26 修复在构造上就是有意为之的弃权对比
（`expected` 为 null，基线从不返回 null 因此得 0）。

修复之前，这个不变量在 4 次运行中的 3 次被违反。

**各守卫在该修复前后稳定。** 比较两次修复后运行：

| 守卫 | `34586809021` | `34594513996` | 噪声底 | 越过？ |
|---|---|---|---|---|
| `mr-cot-aggregation` | +50 | +43 | 13 | ✅ |
| `tr-deterministic-temporal` | +11 | +10 | 4 | ✅ |
| `ku-bitemporal-knowledge-update` | +2 | +3 | 3 | ❌ |
| `tr-extended-engine` | +0 | +0 | 4 | ❌ |
| `tr-time-window` | −3 | −1 | 4 | ❌ |

两个真实效应以一致的幅度复现，三个零结果保持为零，这正是只移除重新查询的
缓存修复所应产生的 —— 它不应移动任何增量，而它确实没有。

### 关于 KU 守卫：+2 和 +3 夹着它 3 的噪声底

在三次同批次运行上，KU 守卫现在读数为 +2、+3、+2，对照 3 的噪声底。
它**处在**边界上并横跨边界。诚实的读法与 `p5-requantification-verdict.md`
相比未变：n = 25 时区间跨度约 30 pp，2–3 道题的移动与重跑不可区分。
它既未被确认也未被证伪，且绝不能算作一场胜利。

## 7. 这关闭了什么，以及没有关闭什么

**已关闭：** P5 所开启的测量完整性工作。现在每一对消融都共享全部三个缓存
（`queryExpansionCache`、`answerCache`、`structuredCache`），
因此在这个基准上的配对比较不再携带 LLM 不可复现项。那是信任任何 McNemar 结果的
先决条件，而它现在是被验证的而非被假定的。

**未关闭：** 效应清单仍是两个特征（MR 聚合、TR 引擎）加三个零结果和一个未解决。
下一个实质性问题就是 `p5-mr-guard-verdict.md` 所点名的那个 ——
**在已经强制枚举的提示词下，MR 为何停在约 79–84%**。那是一个能力上限，
而非测量问题，且它现在是正确的着手点。

**在一次审查值得在更多消融之前审查的工具：** 评判器缓存是一个模块级全局，
以 `(question, predicted, expected)` 为键，在进程内每个系统之间共享，
没有淘汰也没有逐实验臂的限定范围。它对本基准是正确的 —— 键是完整的，
因此同键的两次调用必须一致 —— 但它是进程级全局状态，比任何单次运行活得更久，
这对测试工装而言是一个锋利的边角。
