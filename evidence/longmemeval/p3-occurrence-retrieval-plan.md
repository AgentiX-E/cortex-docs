# P3 — 事实级发生检索（Hindsight Tempr 完整复现）

状态：**已从 P2 负面结果根因定位；分阶段计划见下**

## 1. P2 负面结果的精确读法

P2 按**头部日期**追加窗口内回合（回合的 `[YYYY/MM/DD]` 前缀 =
用户*提及*该事件的日期）。该信号对时间题而言是错的，因为时间题问的是事件
*发生*于何时。两道受损的题把这一点说得确切：

**sports event**（问题“two weeks ago”，问题日期 07/01 → 目标 06/17）：
- 正确的 `charity soccer tournament`：回合说“participate … **today**”（06/17）→ 发生于 06/17
- 干扰项 `Midsummer 5K Run`：回合说“**just finished** … at the Midsummer 5K Run”（06/10）→ 发生于 06/10

两个头部日期（06/17 与 06/10）都落在 ±7 天窗口内，所以 P2 把两者都追加了，
而 LLM 挑错了。具有判别力的信号是**发生日期**，而非提及日期 —— 这正是 Hindsight 的
事实级发生区间 `[τ_s, τ_e]`。

## 2. P3 相对 P1/P2 增加了什么

| 层 | P1（已完成） | P2（已回退） | **P3** |
|---|---|---|---|
| 信号 | 相对时间锚点 | 头部日期窗口 | **发生日期** |
| 位置 | 仅确定性答案 | 召回 | **召回** |
| 粒度 | 每题一个事件 | 整个回合 | **事实级（事件 + 日期）** |

P3 对每个候选回合抽取**它陈述的事件及其发生日期**（将“today”/“yesterday”/
“just finished”/“last week”相对回合日期做规范化 —— 即 P1 的锚点机制，
现在应用于召回）。随后它用问题的 `resolveTimeRange` 窗口去匹配**发生日期**，
而非头部日期，因此一次窗口内的对窗口外事件的*提及*不再污染上下文。

## 3. 分阶段计划

### P3a — 发生日期召回实验臂（本次迭代）

1. `buildOccurrenceExtractionPrompt` + schema：从回合的证据窗口中，
   抽取 `{ name, date }`，其中 `date` 是该事件的发生日期
   （相对时间相对回合日期规范化；没有陈述任何事件的回合被省略）。
2. `extractOccurrenceDates`：在被召回的候选池上调用抽取器
   （扩宽到 2×topK），返回 回合索引 → 发生日期 的映射。
3. 在 `retrieveTurns`（timeRange 路径）中，仅当某回合的**发生日期**
   落在窗口内时才追加它（未抽取出发生日期时回退到头部日期）。保持仅追加、
   不重排的契约；弃权信号仍为 `hits[0]`。
- **成本：** 每道时间锚定的 TR 题一次结构化 LLM 调用（约 14 道锚定的
  eventLookup 题 × 4 次运行；有界，不是一次完整的 Retain 遍历）。
- **A/B：** TR eventLookup 端点 + 守卫。预期恢复那 2 道受损的题
  而*不*重新引入干扰项，并保住 P2 的 3 项恢复。

### P3b — MemoryGraph 扩散激活实验臂

从抽取的事实构建逐题实体图（共现的主语/宾语增强边），
把 `spreadingActivation` 作为召回实验臂加入，与语义 + 词汇 + 发生
做 RRF 融合。目标为多跳 MR 题以及答案实体距问题实体一跳的 TR 题。

### P3c — 交叉编码器重排（最后，仅在 P3a/P3b 交付不足时）

在融合后的 top-k 上运行本地 ONNX 交叉编码器或 LLM 作为重排器。此前的
交叉编码器审计把这项评为信号最重但依赖也最重；只在更便宜的实验臂被度量之后再做。

## 4. 各阶段的 go/no-go

每个阶段都是在 TR 机制端点上的同瞬 4v4 A/B。一个阶段只有在其 TR 端点以
精确置换 p ≤ 0.05 的真实效应移动、且守卫保持平坦时，才会被接受；否则它被回退，
下一阶段依据自己的证据重新评估。诚实的先验：单个实验臂已反复
落在噪声底之下，因此一个只恢复 2–3 道题的阶段可能是机制为真但在统计上不可见 ——
在那种情况下，科学性的答案是“信号是真的但低于噪声”，记录下来，并在任何 SOTA 主张之前，
把组合（P3a+P3b）作为一个整体来测试。
