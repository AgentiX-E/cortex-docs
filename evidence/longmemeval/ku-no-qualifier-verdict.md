## 1. 设计

| 属性 | 值 |
| --- | --- |
| 协议 | 同一时刻交错 4v4 A/B |
| 实验臂 | 4 次对照运行（`ku-no-qualifier-control` = `d793db4`），4 次处理运行（`master` = `4640c86`） |
| 数据集 | LongMemEval-S，全部 8 个产物的 `questionCount = 500` |
| 运行状态 | 全部 8 个为 `completed` / `success` |
| 主要端点 | KU `other` 限定词弃权率（机制端点） |
| 共同主要端点 | KU 准确率（描述性；准确率有噪声底） |
| 约束检验 | 对逐运行率做精确置换检验（4v4 ⇒ C(8,4)=70 种重标记） |

合并的两比例 z 检验仅为定位参照而报告。4 次运行 × 72 道题**并不**构成 288 个独立观测
（同一组 72 道题出现在每次运行中），因此合并检验是伪重复。逐运行的精确枚举才是真正
重要的证据。

## 2. 主要端点 — KU `other` 限定词弃权率

```
              control        treatment       delta        95% CI          z        p
KU:other      27/188 14.36%  8/188  4.26%    -10.11pp     [-17.92,-1.89]  -3.37   0.0007
```

逐运行率（分母为 47 道 `other` 题）：

```
control     8/47 (17.02%)  7/47 (14.89%)  6/47 (12.77%)  6/47 (12.77%)   mean 14.36%
treatment   2/47 ( 4.26%)  2/47 ( 4.26%)  2/47 ( 4.26%)  2/47 ( 4.26%)   mean  4.26%
```

**完全分离** —— `min(control) = 12.77% > max(treatment) = 4.26%`。精确置换检验：
**1/70 = 0.0143 单侧**（0.0286 双侧）。完全分离在构造上就是最极端的那一种重标记，因此
无需任何分布假设。

## 4. 挽回效率

```
abstentions removed : 31 -> 12  = -19 over 4 runs = 4.75/run
correct answers gained : 217 -> 229 = +12 over 4 runs = 3.00/run
efficiency           : 12/19 = 63.2% of recovered abstentions became CORRECT
```

其余 7 次（1.75/运行，36.8%）变成了错误答案。非 ABS 题上的弃权本就记 0 分，因此这些转换
没有代价——只有那 63.2% 的正确转换创造了价值。

## 5. 归因

该修复理应**只**作用于时间限定词为 `other` 的 KU 问题。这一变更必须能仅由该分层完全解释：

```
KU abstentions removed, all strata = 19
  other      27/188 ->  8/188    removed +19
  previous    4/40  ->  4/40     removed  +0
  current     0/60  ->  0/60     removed  +0
residual after subtracting every stratum = 0
```

与报告聚合数据交叉核对（独立于逐题诊断转储）：对照 31/31，处理 12/12——两个数据源完全
一致。残差 **0** 意味着该变更没有泄漏到走双时态路径的 `previous` 或 `current`。

## 6. 守卫（必须不变）

| 能力 | 对照 | 处理 | 判决 |
| --- | --- | --- | --- |
| IE 弃权 | 16/600 = 2.67% | 16/600 = 2.67% | 不变 |
| MR 弃权 | 51/484 = 10.54% | 49/484 = 10.12% | −0.41pp，z = −0.21，不显著 |
| TR 弃权 | 36/508 = 7.09% | 37/508 = 7.28% | +0.20pp，z = +0.12，不显著 |
| ABS 得分 | 120/120 = 100% | 119/120 = 99.17% | 1 次运行得 29/30 |

ABS 异常在该变更触及范围之外：`buildKnowledgeUpdatePrompt` 只在
`questionType === 'knowledge-update'` 时可达，而 ABS 不是。ABS 也没有逐题诊断转储，
因此那道出格的问题无法从产物中识别——这是一个可观测性缺口（见 §9）。

## 9. 混杂 — 处理臂同时携带 `4640c86`

处理臂与对照相差**两个**提交，而非一个。`4640c86` 为 `retryableFetch` 增加了 60 秒的
逐次尝试 `AbortSignal.timeout`。此处予以声明，而非隐藏。三条独立论证将其效应限定为零：

1. **方向。** 传输层截止时间只能把一个慢请求变成一个失败。它不可能减少弃权或创造正确
   答案。处理臂显示的却是弃权*减少*（KU 31 → 12）且正确性*上升*（217 → 229），与一个
   故障注入机制所产生的结果正好相反。
2. **能力特异性。** `retryableFetch` 是全部五个能力以及嵌入与 LLM 两条路径的共享传输层。
   观测到的移动仅限于 KU `other`，其他各处残差均为 0。传输层变更与能力无关，不可能产生
   这种形态。
3. **运行成功。** 全部 8 次运行均以 `questionCount = 500` 成功完成；该截止时间唯一可观测
   的效应（中止一个挂起请求）本应表现为运行失败或*更高*的弃权率，二者均未发生。

独立验证：`verify_retry_timeout_e2e.mjs` 确认截止时间只在真正停滞的 socket 上触发
（在 300 ms 截止时间下为 302 ms，默认 60 000 ms），且 41 个测试的 `retry.test.ts` 套件
全绿。

## 10. 指标自我纠正（诚实说明）

在量化下一个目标时，我发现我自己的"金标准逐字出现在上下文中"弃权质量指标存在**两种**
假阳性模式：

1. **裸数字** —— 像 `"4"` 这样的金标准会匹配任意位置的数字 `4`。
2. **拼写数字** —— `"Two"` 是一个普通的英文单词。

在同时控制这两者之后（把裸数字、拼写数字、带单位的数值答案、时间与日期都视为"可疑，不
予采信"），剩余的真正缺陷很小且异质，并不是刚被捕获的那块系统性的 KU 大收益。

---

## 11. 判决

**接受。** 该修复把 KU `other` 限定词弃权率降低 **−10.11pp**，且完全分离（精确置换检验
p = 0.0143），并把 KU 准确率提高 **+4.17pp**（精确置换检验 p = 0.0143），将被移除的弃权
中的 63.2% 挽回为正确答案。归因残差为 **0**；全部守卫（IE/MR/TR）在统计上不变。已声明的
混杂（`4640c86`）经方向、能力特异性与运行成功三条论证限定为零。
