## 5. 为何 Overall 反而下降：KU/MR 是可证明的对照

下降完全落在两个**在代码层面无法触及**的维度上：

| 边界 | 证据 |
|---|---|
| MR 提示词 | `buildAggregationQaPrompt`，不调用 `conInstruction()` |
| MR 解析器 | `parseAggregationAnswer`，与本变更的 `parseQaAnswer` 是不同的函数 |
| KU 提示词 | `buildKnowledgeUpdatePrompt`，CoN 措辞内联且**未被修改** |
| KU 答案形态 | **72 道题中 0 道包含项目符号枚举**，最长 48 字符——剥离器与 200 字符熔断器均不会触发 |
| 答案长度分布 | KU 最大 48、MR 最大 28，两个版本之间**完全相同**（零截断） |
| 运行日志 | 无 429 / 超时 / 重试；全部 16 个 job step 成功 |

`conInstruction()` 仅有 4 个调用点（`buildQaPrompt`、`buildPreferencePrompt`、
`buildTemporalQaPrompt`、`buildTemporalEventLookupPrompt`），全部仅服务于 IE 与 TR。

**佐证**：第三次运行中 MR 掉到 60.33（比同一实验臂的另两次运行低 5.8pp）；其 8 处损失中
有 5 处是计数题上的算术偏差（`3→2`、`2→4`、`4→5`），另有 3 处变成了弃权——典型的 LLM
服务波动，而非逻辑错误。同一次运行的 IE 实际上是三次运行中最高的（91.33%），排除了全局性退化。

## 6. 漂移校正后的效应估计

以 KU + MR（n = 193，可证明不受影响）作为内部对照，测得同日漂移为 **−3.28pp**
（−6.33 题）。将同一漂移应用于受处理的 IE + TR（n = 277）：

```
observed change      : +2.00 questions
expected drift alone : -9.09 questions
corrected effect     : +11.09 questions  (+4.00 pp on those 277)
scaled to 500        : +2.22 pp overall-equivalent
```

**估计真实效应 ≈ +2.22pp**，方向上与问题级配对净胜 +8.3/+5.3 一致。

> **注意事项**：该校正假设漂移在各能力上均匀作用。KU/MR 是当前可获得的最佳对照（该变更无法触及它们），但它们并非随机分组。**这仍是估计，不是结论。**

## 8. 建议的下一步：用同一时刻的 A/B 来定论

三个数据集分别在 01:38Z / 03:22Z / 06:17Z 采集，最大间隔 4.6 小时。弃权单调下降
（17.67 → 17.00 → 15.47）且与采集时间窗口高度相关，因此**时间漂移是真实的混杂变量**，
仅靠错时数据无法定论。

**提案**：使用 `gh workflow run --ref <sha>` 同时派发 `7a349da` 与 `8d87341`，各 3 次
运行（共 6 次运行，同时启动），把两个提交置于同一时刻，彻底消除时间漂移。

- **判据**：若 con-fix 的 Overall 显著高于 p-json（Welch p < 0.05）→ 保留该修复并推进
  到 MR 项目
- **若仍不显著** → 该修复对 Overall 是中性的（尽管 0% 泄漏率与更低的方差仍成立为收益），
  故保留它并转向价值更高的方向
- **成本**：6 次并发运行，约 1 小时外加相应的 API 配额

无论结果如何，**P0 修复本身都应保留**：它把 7.5% 的格式崩坏（含 33KB 的失控生成）降到
了零，这是独立于 Overall 统计噪声之外的一项确定的工程收益。
