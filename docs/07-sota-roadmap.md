## 0. 结论先行

1. **阅读器不是约束。** 同档阅读器（GPT-5-mini）已有系统达 94.87%；更小的阅读器
   （Gemini 3 Flash）达 **96.4%** 并登顶。在固定阅读器下架构差异（37.0pp）是阅读器
   差异（7.8pp）的 **4.7 倍**。v1.0 的「85.5–88% 天花板」是**增量外推的错误**。
2. **瓶颈是喂给阅读器的数据结构。** 高分系统的共同配方高度一致：多查询分解 + 专用抽取
   通道 + 结构化记忆单元 + 时序链解析 + 一致性重排 +（部分）多路答案聚合。
3. **cortex 现在缺的是这个配方的后半段**：有查询扩展但深度极浅（每查询 top-3），
   **完全没有重排**，**没有专用抽取通道**，双时态与关联图在 core 里但未接线。
4. **保底目标 86%，可达目标 90–95%。** 复刻对象首选 **Exabase M-1**（公开论文、统一
   提示词、主动披露噪声底），而非 Supermemory ASMR（未进生产、多路择优对基准有利）。
5. **当前状态仍不可作为起点**：发布的 83.55% 测于 `a52628f`，落后 55 个提交，测量仪器
   此后被改写 8,326 行。**第一步仍是重测。**

## 1. 前置契约

### 1.1 必须新建的组合层 `cortex-memory`

审计 §6 已证明：`cortex-core` 是已验证的算法库，但没有任何包把它组合成可运行系统。

| 层次 | 包 | 职责 | 状态 |
|---|---|---|---|
| 契约 + 纯算法 | `cortex-core` | `decideWrite`、`decideRetrieval`、`resolveContradiction`、`consolidate`、`MemoryGraph`、`sinkhorn`、FSRS、双时态 | ✅ 存在 ❌ 无人调用 |
| **组合层** | **`cortex-memory`（新建）** | 组合成满足 core 契约的 `MemorySystem` | ❌ **缺失** |
| 后端 | `cortex-node` | `SqliteStorage`、`PgStorage` | ✅ 存在（仅存储） |
| 提供方 | `cortex-llm` | LLM / embedding 适配器 | ✅ 存在 |
| 仪器 | `cortex-eval` | 测量任何满足 `MemorySystem` 的实现 | ✅ 存在 |

依赖方向无环，`cortex-eval` 保持仪器身份：

```
cortex-core  ←  cortex-memory  →  cortex-node
                     ↑                （注入 Storage）
                     └── cortex-llm   （注入 LLM / Embedding）
                              ↑
                        cortex-eval     （依赖 cortex-memory 并测量它）
```

**顺序不可颠倒**：先让认知层被测量，再谈优化它。在未接线的基础上叠加能力，会重复本次
审计记录的错误。

## 3. 各举措的实施与验收判据

### B1 — 交叉编码器重排

| 项 | 内容 |
|---|---|
| 落点 | `cortex-core` 新增抽象（若纯函数）或 `cortex-llm`（若远程调用） |
| 契约 | `Reranker { rerank(query: string, candidates: string[]): Promise<number[]> }` |
| 理由 | provider-agnostic：本地 `bge-reranker-v2-m3` 与远程 Cohere 均可插拔 |
| 验收 | MR 与 TR 分项在配对 A/B 下同向提升；one-sided p < 0.05 |
| **反证条件** | 若 MR 提升但 TR 下降超过 MR 增益，判定**无净收益**并回滚 |

**集成风险（来自 B2 的历史）**：`rrf-retrieval-fusion-verdict.md` 记录 v1 被拒的根因是
**同一字段被两处读取**——RRF 改了排序，而单会话路径把 `hits[0].score` 读作弃权置信度。
**重排同样会改排序，因此必须审计 `hits[0].score` 的所有读取点。** 这是 B1 最主要的失败模式。

#### B1 实施记录（2026-09-20）

已按上表契约落地，实现细节与**读码后修正的认知**如下：

| 层 | 落点 | 内容 |
|---|---|---|
| 纯算法 | `cortex-core/src/retrieval/rerank.ts` | `rerankHits` / `fuseRerank`：排序、平局稳定、去重、受保护前缀、全部降级路径。零 I/O。**100% 四维度覆盖** |
| 远程适配 | `cortex-llm/src/rerank/rerank.ts` | `OpenAICompatibleReranker`：`/rerank` 约定（Cohere / Jina / Voyage / 自建 bge 代理）。**100% 四维度覆盖** |
| 本地适配 | 同上 | `CrossEncoderReranker`：transformers.js 序列分类，**离线兜底**（无 provider、无 key、无网络） |
| 工厂 | `cortex-eval/src/rerank-factory.ts` | `createRerankerFromEnv`：默认**关闭**；开启但缺 key 时**抛错**而非静默降级 |
| 接线 | `natural-language-memory.ts` | `applyRerank()` 共享助手，`retrieveTurns` 与 `retrieveSessionsForQuestion` **两条路径均接线** |

**读码后必须修正的三点**（v1.0 计划中的描述不准确）：

1. **管线不是「单通道浅检索」。** `retrieve()` 已融合 4 条召回通道：question 质心、
   LLM 扩展短语、确定性词汇变体、turn-level 召回，且由 RRF 融合。B2 的原始表述有误。

2. **真正的窄口是「候选池宽度」而非「通道数」。** `retrieveTopKByQueries` 在
   **内部**就 `slice(0, topK)`，因此重排在默认配置下**只能对 top-K 做排列组合，
   无法把余弦排名第 20 的答案捞回来**。这条限制已固化为测试
   （`cannot promote beyond the pool when the pool is left at topK`），
   并通过 `rerankCandidatePool` 选项解除。

3. **弃权信号已经修好了。** `maxHitScore()` 已取代 `hits[0].score` 作为弃权置信度
   （见源码注释），因此重排对弃权是**顺序无关**的。v1.0 计划把 RRF 回归列为
   「B1 最主要的失败模式」属于过度预警——该风险在 RRF 集成时已被一并修复。
   `rerankProtectedHead` 仍保留，用于需要固定首条证据的其他读取方。

**测试覆盖**：新增 61 个测试（core 23 / llm 28 / eval 10），合计 **1048 个测试全绿**。
`A4` 覆盖率门禁已同时落地，四条维度（statements / branches / functions / lines）
在**全部四个包**均设为 95% 硬门禁，并已验证违反时进程退出码为 1。

#### B1 的 A/B 阻塞已收窄到单一 secret（2026-09-20 实测）

原记录为「需 rerank provider 凭据」，但**未区分三种在 CI 里长得一样的失败**：适配器缺陷、
网络不通、缺 credential。三者只有第一种是代码问题，而混为一谈会让代码缺陷被当作
「只是缺 key」长期搁置。已分开实测：

| 检查项 | 方法 | 结果 |
|---|---|---|
| provider 连通性 | 直连 provider 根路径 | Cohere **403**、Voyage **404**——均可达（`api.jina.ai` TLS 被截断，不可用） |
| 适配器传输/报文 | 以**无效 key** 调真实 `/rerank` | Cohere `403 Forbidden`、Voyage `400 Bad Request`——传输、路径、请求体、鉴权头**全部正确**，错误被正确上抛 |
| 工厂状态机 | 直接调 `createRerankerFromEnv` | 未设/`off` → `undefined`；`on` 无 key → **抛错**；`on` + key → `RerankScoreFn` |

**结论**：B1 的代码路径**已具备在 CI 中运行的条件**，唯一缺的是 `RERANK_API_KEY`
org secret。workflow 的 5 个透传变量已就位，**加 secret 后无需改任何代码即可派发 A/B**。

**可执行性**：这是本项**唯一**剩余的前置件，且是**运维动作而非工程动作**。

### B2 — 候选池宽度（测量仪器已落地并已实测）

| 项 | 内容 |
|---|---|
| **修正现状** | 管线已有 4 条召回通道（见上），**并非**「单通道、每查询仅 3 条」。真正的窄口是 `retrieveTopKByQueries` 内部的 `slice(0, topK)` 截断，即**候选池宽度** |
| **实测结论** | **不加宽池。** run `35498421148`（`LIMIT=60`，43 道可答题）：`ceiling` 恒为 **93.02%**，`gain` 从 **65.12%**（k=1）衰减到 **2.33%**（k=20）。按预注册读法属第 1 行——瓶颈在排序，不在广度 |
| **实测的三点含义** | ① 40/43 的答案回合已在池内，剩 3 道（6.98%）任何重排都够不到，是诚实的地板；② gain 只在窗口远窄于答案排名时为大，到工作宽度已被宽度本身吸收；③ **cortex 在可用宽度上没有广度问题**，「加召回通道」必须针对剩下的 6.98% 论证自己 |
| 目标 | 原「取 topK 的 3–10 倍」**已被实测否定**；`rerankCandidatePool` 保留为 B1 A/B 的可调输入，默认 = topK |
| 依据 | ASMR 三个搜索 Agent；M-1 查询重写 + 多路并行；两者都**先取宽池再收窄**——但本管线的 ceiling 显示该处方在此不适用 |
| 验收 | 原「MR +≥1.5pp」**已作废**：加宽池在实测形态下不产生召回 |
| 反证条件 | 若 `LIMIT=0` 全量重测显示 ceiling 显著低于 93.02%，则本结论失效，需重新评估 |
| 前置 | 已完成 |

> **注意历史**：查询扩展已被改写过至少两次并被证伪（见 `natural-language-memory.ts`
> 内注释引用的 `f39e7f9`）。**第三次尝试必须换机制，而不是改提示词措辞。**
> 实测的 ceiling 93.02% 进一步说明：该方向的总奖品只有 6.98%，不值得作为架构级投入。

> **口径警示**：60 题分层抽样，非全量 500。曲线**形态**稳健，**具体 ceiling 值不稳健**
> （换样本以约 2.3pp 步进移动），对外引用前须以 `LIMIT=0` 重读。A2 全量重测已派发
> （run `35510619912`，`LIMIT=0` + `DIAGNOSTICS_LIMIT=0`，使曲线覆盖全 500 题）。

> **反证条件的当前状态**：本项的「反证条件」是「若 `LIMIT=0` 显示 ceiling 显著低于
> 93.02% 则结论失效」。该重测**已在途**，结果回填前本结论的效力限定在 `LIMIT=60` 的
> 形态上。**不要把 93.02% 当作全量值对外引用。**

## 4. 预注册纪律（不可协商）

每一项 B 级及以上举措在**派发之前**必须登记：

1. 它必须超越的**点估计**；
2. 算作成功的**效应量**；
3. **停止规则**（何时判定无效并回滚）。

**为什么不是形式主义**：本次审计发现文档仍在推荐一条已实测失败并回滚的路线。没有事先
登记的判据，失败结果就会被事后合理化。

配套要求：

- **同刻 A/B**：4-vs-4 交错（`same-instant-ab-report.md`），避免时间漂移（~1.7–2.1pp）；
- **配对统计**：优先精确 McNemar（同问题集），而非 Welch t；
- **最小 / 中位 / 最大**：报告尾部，不只均值；
- **Wilson 区间**：比例型指标必须给区间；
- **run id 归档**：写入 `05/run-ids/`。

## 5. 消融设计

| 消融臂 | 控制变量 | 观测 | 通过条件 |
|---|---|---|---|
| `+rerank` vs `−rerank` | 同刻、同题集、同阅读器 | MR/TR/overall 分项 Δ | 目标维度 +≥1.5pp，其他不回退 |
| `+multichannel` vs `−multichannel` | 同上 | MR Δ + IE 弃权率 | MR +≥1.5pp 且 IE 弃权不超噪声底 |
| `+specialised-extract` vs `−` | 同上 | 各维度召回 | 逐维度分别判定 |
| `+temporal-chain` vs `−` | 同上 | TR Δ | TR +≥1.0pp 且 overall 不回退 |
| **`cortex-memory` vs `natural-language-memory`** | 同上 | overall Δ | 认知组合层**必须**不劣于参考管线 |
| **阅读器矩阵**（C1） | 同管线、同题集 | 各阅读器 overall | 归因验证，无通过/失败门槛 |

> **两个关键消融**：
> 1. `cortex-memory` vs 参考管线决定认知层的真实价值，也决定预算投向认知层还是检索层。
>    **在该结果出来之前，不应再向认知层追加新能力。**
> 2. 阅读器矩阵决定「瓶颈在管线」是否在 cortex 自己的管线上成立。**若换强阅读器分数
>    几乎不动，则该判断被确证；若分数显著上升，则 §08 的推论需要按 cortex 的实测修正。**

## 7. 风险与诚实边界

1. **83.55% 仍是历史锚点。** 在 A2 完成前，本计划所有增益预期都相对于一个**未重测的
   数字**。这是最大的单一不确定性。
2. **存在性证明 ≠ 预测。** Exabase M-1 的 96.4% 证明「小阅读器 + 好管线可达 96.4%」，
   不证明 cortex 能到。它界定机会上限，不承诺结果。
3. **增量不可线性叠加。** v1.0 的核心错误。B1–B5 的预期增益**不能相加**；每个臂必须
   独立消融，且存在互相干扰的先例（图召回 −7.09pp）。
4. **ASMR 的基准口径有偏差**：多路择优（任一路答对即对）在真实部署中无对应裁判，
   且需 8–12 倍推理成本。**复刻 M-1，不复制 ASMR 的择优策略。**
5. **B3 是架构级改动**，成本 ×通道数；先在单维度验证。
6. **认知层可能被证伪。** N2 结果可能是「不优于参考管线」。若如此，`cortex-memory` 仍是
   必要的（让产品路径存在），但后续预算应全部转向检索侧。
7. **基础模型快速换代**。DeepSeek V4 Pro 已于 2026-09-14 路由至 V4.1 Flash；阅读器选择
   必须经 `cortex-llm` 抽象，不硬编码。

## 9. 缺陷登记：报告与守卫子系统（四个连续缺陷）

这四个缺陷是**同一子系统在同一轮内连锁产生的**，且**没有一个能靠读码发现**。登记在此，
因为它们的共同成因比任何单个缺陷都更值得记住。

| # | 缺陷 | 发现方式 | 修复 | 教训 |
|---|---|---|---|---|
| 1 | 守卫的**爆炸半径**：前置条件检查放在它所保护的工作之后，触发时丢弃全部已完成报告 | 靠**运行**发现（run `35498421148` 在 11 分钟失败） | `fe0daa7` | 代码**单独看是正确的**，缺陷在它与其他部分的位置关系里 |
| 2 | 覆盖度是**侧信道**：`coverage` 与 `report` 并列返回，渲染器拿不到，1/7 cohort 渲染成普通结果 | 靠**验证修复**发现（run `35502712132` 的产物） | `0e2c30e` | 修复 #1 时把 permissive 变成默认，把**响亮失败**换成了**安静的错误数字** |
| 3 | 报告**无法从 JSON 重读**：`NaN`/`±Infinity` 被序列化成 `null`，重渲染时抛 `TypeError` | 靠**重渲染真实归档产物**发现 | `c17cf88` | 归档件是唯一的耐久记录；**无法重读的报告无法被辩护** |
| 4 | **侧信道的第二个实例**：`retryFires` 同样并列返回，重渲染时该臂的零结果失去唯一证据 | 靠**审计已声明的缺口**发现 | 本轮 | **如实声明缺口是有价值的**——这个缺口是真的 |

### 9.1 共同成因

四个缺陷都不是「代码写错了」，而是**边界处的假设**：

1. **位置边界**：守卫与它保护的工作的先后顺序；
2. **返回值边界**：什么信息「属于」一个结果，什么信息「关于」一个结果；
3. **表示边界**：内存中的值与持久化后的值是不是同一个值；
4. **类别边界**：「修掉这个实例」与「消除这个模式」是两件事。

### 9.2 对后续工作的约束

- **#2 的教训已升格为纪律**：任何「降级但不失败」的路径，必须同时**产出可见的警示**，
  否则它比失败更糟。已固化为 `AblationReport.cohortCoverage` + 报告顶部 banner。
- **#3 的教训是测试方法学的**：只测内存对象的测试套件**看不见序列化缺陷**，无论它对渲染
  函数的覆盖多完整。凡「写盘 → 读回」的产物，必须有跨该边界的测试。
- **#4 的教训是纪律的升级**：修两个实例不会让模式非法，因此改为断言**结构不变量** ——
  「渲染器输出的每个小节都必须仅凭报告对象得到」，以 JSON 往返后渲染来检查。
- **#2 的未审计缺口已闭环（本轮）**：9 个返回点全部审计，7 个干净，第 8 个（retry）
  确有同类缺陷并已修复。**缺口声明是真的。**
- **#4 的副作用**：审计过程中读出的 **1.50% 触发率**（3/200，control 为 0）说明该臂
  结论**欠功率**。见 §9.3。
- **#3 的未审计缺口**：其他 `benchmark-*.json` 写入方**未检查**是否存在
  「内存为 `NaN`/`Infinity`、读回后为 `null`」的字段。**仍为已知缺口。**

### 9.3 因本轮发现而需要重新表述的条目

| 条目 | 原表述 | 修正后 |
|---|---|---|
| abstention-retry 臂的结论 | 「retry 对准确率无提升」（读作已证伪） | 「200 题中仅触发 3 次，Δ accuracy 被 1.5 pp 上界框住，**欠功率**，不是证伪」 |
| 该臂的改进方向 | 优化 retry 逻辑 | **瓶颈在「产生裸弃权的总体」，不在 retry 本身** |
| 该臂结果的可辩护性 | 依赖「功能已接线」的断言 | 依赖 `controlFires == 0` 的**实测**（此前是假设，现已验证） |

> **纪律**：一个零结果只有在**计数器可见**时才可判决。这正是该小节必须留在报告里的原因，
> 也是为什么把它修成「渲染器无法产出」是一个真实缺陷，而不是排版问题。
