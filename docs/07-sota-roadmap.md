## 0. 结论先行

1. **阅读器不是约束。** 同档阅读器（GPT-5-mini）已有系统达 94.87%；更小的阅读器
   （Gemini 3 Flash）达 **96.4%** 并登顶。在固定阅读器下架构差异（37.0pp）是阅读器
   差异（7.8pp）的 **4.7 倍**。v1.0 的「85.5–88% 天花板」是**增量外推的错误**。
2. **瓶颈是喂给阅读器的数据结构。** 高分系统的共同配方高度一致：多查询分解 + 专用抽取
   通道 + 结构化记忆单元 + 时序链解析 + 一致性重排 +（部分）多路答案聚合。
3. **cortex 现在缺的是这个配方的后半段**：有查询扩展但深度极浅（每查询 top-3），
   **完全没有重排**，**没有专用抽取通道**，双时态与关联图在 core 里但未接线。
4. **保底目标 86%，可达目标 90–95%。** 复刻对象首选 **Exabase M-1**（公开论文、统一
   提示词、主动披露噪声底），而非 Supermemory ASMR（未进生产、多路择优对基准有利）。
5. **当前状态仍不可作为起点**：发布的 83.55% 测于 `a52628f`，落后 55 个提交，测量仪器
   此后被改写 8,326 行。**第一步仍是重测。**

## 1. 前置契约

### 1.1 必须新建的组合层 `cortex-memory`

审计 §6 已证明：`cortex-core` 是已验证的算法库，但没有任何包把它组合成可运行系统。

| 层次 | 包 | 职责 | 状态 |
|---|---|---|---|
| 契约 + 纯算法 | `cortex-core` | `decideWrite`、`decideRetrieval`、`resolveContradiction`、`consolidate`、`MemoryGraph`、`sinkhorn`、FSRS、双时态 | ✅ 存在 ❌ 无人调用 |
| **组合层** | **`cortex-memory`（新建）** | 组合成满足 core 契约的 `MemorySystem` | ❌ **缺失** |
| 后端 | `cortex-node` | `SqliteStorage`、`PgStorage` | ✅ 存在（仅存储） |
| 提供方 | `cortex-llm` | LLM / embedding 适配器 | ✅ 存在 |
| 仪器 | `cortex-eval` | 测量任何满足 `MemorySystem` 的实现 | ✅ 存在 |

依赖方向无环，`cortex-eval` 保持仪器身份：

```
cortex-core  ←  cortex-memory  →  cortex-node
                     ↑                （注入 Storage）
                     └── cortex-llm   （注入 LLM / Embedding）
                              ↑
                        cortex-eval     （依赖 cortex-memory 并测量它）
```

**顺序不可颠倒**：先让认知层被测量，再谈优化它。在未接线的基础上叠加能力，会重复本次
审计记录的错误。

## 3. 各举措的实施与验收判据

### B1 — 交叉编码器重排

| 项 | 内容 |
|---|---|
| 落点 | `cortex-core` 新增抽象（若纯函数）或 `cortex-llm`（若远程调用） |
| 契约 | `Reranker { rerank(query: string, candidates: string[]): Promise<number[]> }` |
| 理由 | provider-agnostic：本地 `bge-reranker-v2-m3` 与远程 Cohere 均可插拔 |
| 验收 | MR 与 TR 分项在配对 A/B 下同向提升；one-sided p < 0.05 |
| **反证条件** | 若 MR 提升但 TR 下降超过 MR 增益，判定**无净收益**并回滚 |

**集成风险（来自 B2 的历史）**：`rrf-retrieval-fusion-verdict.md` 记录 v1 被拒的根因是
**同一字段被两处读取**——RRF 改了排序，而单会话路径把 `hits[0].score` 读作弃权置信度。
**重排同样会改排序，因此必须审计 `hits[0].score` 的所有读取点。** 这是 B1 最主要的失败模式。

#### B1 实施记录（2026-09-20）

已按上表契约落地，实现细节与**读码后修正的认知**如下：

| 层 | 落点 | 内容 |
|---|---|---|
| 纯算法 | `cortex-core/src/retrieval/rerank.ts` | `rerankHits` / `fuseRerank`：排序、平局稳定、去重、受保护前缀、全部降级路径。零 I/O。**100% 四维度覆盖** |
| 远程适配 | `cortex-llm/src/rerank/rerank.ts` | `OpenAICompatibleReranker`：`/rerank` 约定（Cohere / Jina / Voyage / 自建 bge 代理）。**100% 四维度覆盖** |
| 本地适配 | 同上 | `CrossEncoderReranker`：transformers.js 序列分类，**离线兜底**（无 provider、无 key、无网络） |
| 工厂 | `cortex-eval/src/rerank-factory.ts` | `createRerankerFromEnv`：默认**关闭**；开启但缺 key 时**抛错**而非静默降级 |
| 接线 | `natural-language-memory.ts` | `applyRerank()` 共享助手，`retrieveTurns` 与 `retrieveSessionsForQuestion` **两条路径均接线** |

**读码后必须修正的三点**（v1.0 计划中的描述不准确）：

1. **管线不是「单通道浅检索」。** `retrieve()` 已融合 4 条召回通道：question 质心、
   LLM 扩展短语、确定性词汇变体、turn-level 召回，且由 RRF 融合。B2 的原始表述有误。

2. **真正的窄口是「候选池宽度」而非「通道数」。** `retrieveTopKByQueries` 在
   **内部**就 `slice(0, topK)`，因此重排在默认配置下**只能对 top-K 做排列组合，
   无法把余弦排名第 20 的答案捞回来**。这条限制已固化为测试
   （`cannot promote beyond the pool when the pool is left at topK`），
   并通过 `rerankCandidatePool` 选项解除。

3. **弃权信号已经修好了。** `maxHitScore()` 已取代 `hits[0].score` 作为弃权置信度
   （见源码注释），因此重排对弃权是**顺序无关**的。v1.0 计划把 RRF 回归列为
   「B1 最主要的失败模式」属于过度预警——该风险在 RRF 集成时已被一并修复。
   `rerankProtectedHead` 仍保留，用于需要固定首条证据的其他读取方。

**测试覆盖**：新增 61 个测试（core 23 / llm 28 / eval 10），合计 **1048 个测试全绿**。
`A4` 覆盖率门禁已同时落地，四条维度（statements / branches / functions / lines）
在**全部四个包**均设为 95% 硬门禁，并已验证违反时进程退出码为 1。

#### B1 判决：负结论——**两种配置下都测不到效应，重排不默认开启**（2026-09-22）

B1 的预期是 **+1.5–3.0pp**（上表第 81 行）。这个预期**已被实测否定**。按预注册顺序
读取两臂（同一套 150 题、`temperature=0`、托管端点）：

| 项 | 无保护臂 `35624110842` | 对照臂 `35693431980`（钉住前 N 个 hit → 关闭弃权混淆通道） |
|---|---|---|
| baseline → feature | 86.00% → 87.33% | 87.33% → 86.00% |
| **Δ** | **+1.33 pp** | **−1.33 pp** |
| McNemar p | 0.7539 | 0.7539 |
| 不一致对 | 4 : 6 | 6 : 4 |
| `abstentionShift` | +2.00 pp（**Δ 被混淆**） | +0.67 pp（可归因） |
| `fallbacks` | `null`（计数器缺陷，已修） | `{fallbackCount: 0, bucketCount: 300}` |
| MR / TR 配对（预注册验收项） | MR **0 vs 0** → 直接失败 | MR 19 → 18（**−1**）→ 同样失败 |

**两条独立理由，各自足以给出负结论**：

1. **Δ 落在 ±1.33 pp，两臂完全镜像，p 均 0.7539。** 两个对称配置读出符号相反、
   幅度相同的效应，说明该量级就是噪声；「重排无效」不是某一配置的伪影。
2. **预注册的验收标准（MR 与 TR 同向 ≥+1.5pp）直接失败** —— 两臂的 MR 分别是
   **0 与 −1**，都不满足「同向移动」，而 TR 在两臂都恰好 **+2**（17→19、16→18）。
   **只有 TR 动、MR 不动（或倒退），正是预注册要排除的形态。** 这一条与显著性无关。

**分能力明细（两臂，供复核）**：

| 能力 | 题数 | 无保护臂 | 对照臂 |
|---|---|---|---|
| MR | 22 | 18 → 18（**0**） | 19 → 18（**−1**） |
| TR | 21 | 17 → 19（**+2**） | 16 → 18（**+2**） |
| KU | 21 | 15 → 16（+1） | 15 → 15（0） |
| IE | 64 | 58 → 57（−1） | 60 → 57（−3） |
| ABS | 22 | 21 → 21（0） | 21 → 21（0） |

> **TR 的 +2 在两臂中稳定复现，而它恰好是 `hits[0].score` 弃权读取点所在的能力。**
> 无保护臂把这一通道放大成 `abstentionShift` +2.00 pp，对照臂钉住后仍余 +0.67 pp。
> 因此这个 TR「动量」至少部分来自弃权阈值移动，**不是排序质量的证据** ——
> 这与 `AUDIT-B1-HITS0-READ-SITES.md` 的事前定位一致。

**欠功率边界**：n=150，MR=22 / TR=21 题，需 6:0 才达 p<0.05。因此正确表述是
**「未测到效应」而非「已证伪效应」**，但它足以否决「默认开启」。

**因此 B1 路线的处置（对下游规划的影响）**：

- **B2（加宽候选池）失去前提。** B2 的价值论证是「重排的收益上限由候选池宽度决定」，
  而重排本身在此管线上读不出效应——先加宽池子再期待重排生效是**没有依据的次序**。
  B2 降级为「仅在 B1 出现正效应后才有意义」。
- **`rerankCandidatePool` 保留为可调输入，默认仍等于 topK。** 不因负结论删除实现——
  §B1 的本地 ONNX 形态（`CrossEncoderReranker`）与远程形态从未被真正测量过（沙箱不可达），
  这条负结论**只覆盖托管端点配置**。
- **B1 不再阻塞 B3/A6。** 预算应从「让重排生效」转向 §B1 之后被它挡住的条目
  （第 12/13 项：A6 受控阅读器矩阵、B3 专用抽取通道）。

> **这条负结论现在是可证伪的，这是它唯一值得信任的地方。** 首跑时回退计数器读出 `null`，
> 意味着「重排从未运行」与「重排运行了但无效果」给出同一个数字；对照臂读出 `{0, 300}`
> 之后，后者才是被支持的读法。**一个不可证伪的负结论不比没有结论更有价值。**

#### B1 的 A/B 阻塞已收窄到单一 secret（2026-09-20 实测）

原记录为「需 rerank provider 凭据」，但**未区分三种在 CI 里长得一样的失败**：适配器缺陷、
网络不通、缺 credential。三者只有第一种是代码问题，而混为一谈会让代码缺陷被当作
「只是缺 key」长期搁置。已分开实测：

| 检查项 | 方法 | 结果 |
|---|---|---|
| provider 连通性 | 直连 provider 根路径 | Cohere **403**、Voyage **404**——均可达（`api.jina.ai` TLS 被截断，不可用） |
| 适配器传输/报文 | 以**无效 key** 调真实 `/rerank` | Cohere `403 Forbidden`、Voyage `400 Bad Request`——传输、路径、请求体、鉴权头**全部正确**，错误被正确上抛 |
| 工厂状态机 | 直接调 `createRerankerFromEnv` | 未设/`off` → `undefined`；`on` 无 key → **抛错**；`on` + key → `RerankScoreFn` |

**结论（已更正）**：上一版这里写的是「唯一缺的是 `RERANK_API_KEY` org secret；
workflow 的 5 个透传变量已就位，加 secret 后无需改任何代码即可派发 A/B」。
**这两句都不成立**，且第二句是纯粹的文档-代码不一致——派发前实测 `benchmark.yml`，
`CORTEX_RERANK` / `RERANK_*` 出现次数为 **0**，即 5 个透传变量**一个都不存在**。
加 secret 也进不了 bench 进程。已按代码实测更正为三个独立阻塞：

| # | 阻塞 | 实测证据 | 性质 |
|---|---|---|---|
| 1 | 缺 `RERANK_API_KEY` | org secret 不存在 | 运维 |
| 2 | workflow **零**透传 | `grep -c RERANK .github/workflows/benchmark.yml` = **0** | **工程** |
| 3 | **无任何 A/B arm 拿到 reranker** | `runner.ts` 的 8 个消融函数签名均无 reranker 选项 | **工程** |

第 3 项是最容易被漏掉的一项：即便 1、2 都解决，也没有任何一条路径能产出预注册验收
所需的「MR 与 TR 分项配对 A/B」——**不存在一个构造了「开 rerank」系统的 arm**。

三项均已闭环，且**不再依赖任何新 secret**：

| 修复 | 落点 |
|---|---|
| 新增 `runRerankAblation`（同一 run 内构造 baseline/feature 双臂，复用 McNemar + Wilson） | `cortex-eval/src/runner.ts` |
| 新增 `LLMReranker`（listwise 打分，复用现有 `DEEPSEEK_API_KEY`，**不需要** `RERANK_API_KEY`） | `cortex-llm/src/rerank/llm-reranker.ts` |
| 新增 `CORTEX_RERANK_PROVIDER=local`（离线 cross-encoder，**零凭据**） | `cortex-eval/src/rerank-factory.ts` |
| workflow 补齐 4 个 input 与对应 `env:` 透传 | `.github/workflows/benchmark.yml` |
| `RERANK_PROTECTED_HEAD` 接入 bench（此前不可达） | `bench/run.ts` |

**关于第 1 项的一个技术更正**：rerank **不是** LLM、也**不是** embedding。cross-encoder
把 `question</s></s>passage` 拼成单序列联合打分，输出相关性标量；bi-encoder（embedding）
两侧独立编码，无法表达交互；LLM 输出 token 序列。DeepSeek **未发布**任何名为 Reranker 的
精排模型，也**不提供**独立 `/rerank` 接口（已由其 endpoint 清单与检索双重确认）——所以它的
secret 不能直接喂给现有 `/rerank` 客户端。但把它接成 **LLM caller** 即可复用：rerank 的
本质是一个打分函数，不是一套协议。这正是 `LLMReranker` 的由来。

**可执行性**：本项已**无任何剩余前置件**。A/B 现在有三条互不依赖的触发方式——离线
（`local`，零凭据）、复用凭据（`llm`）、或原 `/rerank` 客户端（待其 key 到位）。三者结论
不可互相替代，建议交叉验证。

## 7. 风险与诚实边界

1. **83.55% 仍是历史锚点。** 在 A2 完成前，本计划所有增益预期都相对于一个**未重测的
   数字**。这是最大的单一不确定性。
2. **存在性证明 ≠ 预测。** Exabase M-1 的 96.4% 证明「小阅读器 + 好管线可达 96.4%」，
   不证明 cortex 能到。它界定机会上限，不承诺结果。
3. **增量不可线性叠加。** v1.0 的核心错误。B1–B5 的预期增益**不能相加**；每个臂必须
   独立消融，且存在互相干扰的先例（图召回 −7.09pp）。
4. **ASMR 的基准口径有偏差**：多路择优（任一路答对即对）在真实部署中无对应裁判，
   且需 8–12 倍推理成本。**复刻 M-1，不复制 ASMR 的择优策略。**
5. **B3 是架构级改动**，成本 ×通道数；先在单维度验证。
6. **认知层可能被证伪。** N2 结果可能是「不优于参考管线」。若如此，`cortex-memory` 仍是
   必要的（让产品路径存在），但后续预算应全部转向检索侧。
7. **基础模型快速换代**。DeepSeek V4 Pro 已于 2026-09-14 路由至 V4.1 Flash；阅读器选择
   必须经 `cortex-llm` 抽象，不硬编码。

## 9. 缺陷登记：报告、守卫与测量三个子系统（九个连续缺陷 + 一个方法假阳性）

前四个是**同一子系统在同一轮内连锁产生的**；第五、第六个不在产品里，而在**测量层**；
第七、第八个是**数学核心里的真实 BUG**，在追查测量层的过程中被挖出来；
**第九个是测量仪器的分母静默缩小**，靠**核对产物之间的一致性**发现。
九个**没有一个能靠读码发现**。登记在此，因为它们的共同成因比任何单个缺陷都更值得记住。

| # | 缺陷 | 发现方式 | 修复 | 教训 |
|---|---|---|---|---|
| 1 | 守卫的**爆炸半径**：前置条件检查放在它所保护的工作之后，触发时丢弃全部已完成报告 | 靠**运行**发现（run `35498421148` 在 11 分钟失败） | `fe0daa7` | 代码**单独看是正确的**，缺陷在它与其他部分的位置关系里 |
| 2 | 覆盖度是**侧信道**：`coverage` 与 `report` 并列返回，渲染器拿不到，1/7 cohort 渲染成普通结果 | 靠**验证修复**发现（run `35502712132` 的产物） | `0e2c30e` | 修复 #1 时把 permissive 变成默认，把**响亮失败**换成了**安静的错误数字** |
| 3 | 报告**无法从 JSON 重读**：`NaN`/`±Infinity` 被序列化成 `null`，重渲染时抛 `TypeError` | 靠**重渲染真实归档产物**发现 | `c17cf88` | 归档件是唯一的耐久记录；**无法重读的报告无法被辩护** |
| 4 | **侧信道的第二个实例**：`retryFires` 同样并列返回，重渲染时该臂的零结果失去唯一证据 | 靠**审计已声明的缺口**发现 | 上一轮 | **如实声明缺口是有价值的**——这个缺口是真的 |
| 5 | **覆盖率门禁读的是噪声**：同一代码 12 次运行得 5 个不同结果，跨度 0.76pp | 靠**第三次看到同一个异常时不再解释它**发现 | 本轮 | **「重新运行一次就好了」是危险信号**——需要重跑才能正常的数字不是证据 |
| 6 | **`sinkhorn` 收敛检测器失效**：`uPrev` 是 `u` 的别名且 `u` 被原地修改，残差恒为 0 | 靠**补覆盖率缺口时顺手验证**发现 | 本轮 | 一个**恒真**的收敛判据，表现为静默的「已收敛」 |
| 7 | **`logGamma` 对所有负非整数返回 NaN**：反射公式漏掉 `\|sin\|`，`Math.log` 收到负数 | 靠**追「守卫既然可达，是什么把它们带到的」**发现 | 本轮 | 真实 BUG 可以在**追一个测量问题**的路上被撞出来 |
| 8 | **`binomialCdf` 在小 `p` 下返回无效值**：`regularizedIncompleteBeta` 在收敛域外求值连分数 | 靠**为守卫写性质测试时断言单调性**发现 | 本轮 | 返回值**看似合理、不是 NaN**，且误差在函数**最确定**处最大 |
| 9 | **召回曲线的分母静默缩小**：曲线对 **428** 题算，报告对 **500** 题算，两个产物都没说分母不同 | 靠**核对产物之间的能力项计数**发现 | 本轮 | 排除**规则**正确，缺陷在排除**沉默**；产物**内部自洽、对外误导** |

> **#6 的严重性是潜伏而非激活**：`docs/AUDIT-CODE-VS-DOCS.md` 已记录 `sinkhorn`
> 导出但从未被调用，所以产品侧没有消费过错误答案。它会在 optimal-transport distillation
> 路径接线的**那一刻**转为激活——并且以一个**静默的**「已收敛」出现。

> **#7 / #8 的严重性不同，必须分开写。** #7 对统计量潜伏（内部调用只传正数）、
> 对**公开 API 是坏的**；#8 是**激活的**——`binomialCdf` 是真实统计输出，
> 而单调性是调用方有权假定的唯一性质。两个都**不产生 NaN**（#8）或
> **只在公开 API 上产生 NaN**（#7），所以都没有触发任何既有断言。

> **#8 的修复自身带一个陷阱，值得单列**：递归到互补参数对时，若边界比较用**非严格**的
> `>=`，程序会在不动点 `a == b, x == 0.5` 上**无限递归**——而 `studentTCdf(t, 1)` 在
> `t = ±1` 恰好命中它。抓到它的是**密集网格的性质测试**，不是任何点检查。
> 这是「性质测试 > 点检查」在本仓库最干净的一次实证。

### 9.0 一次被公开更正的根因结论（比上面六个都重要）

在查 #5 的过程中，我先给出了一个根因结论并写进仓库、附了验收表：
「六个 `c8 ignore` 守卫不可达（复算得 29.9 个数量级裕度），因此注解正确，
问题在 v8 施加注解的方式」。**该结论是错的。**

| 环节 | 内容 |
|---|---|
| 我用的方法 | 往守卫体里**插计数器**，统计命中 |
| 实际发生了什么 | 插入语句改变了 v8 的基本块结构，**计数器被归因到另一行** |
| 观测到的结果 | 在「算术证明从未被进入」的守卫体上报告了 **20000 次命中** |
| 换成的方法 | **抛错哨兵**——把守卫体换成 `throw`，跑真实套件。不可达则全绿，可达则当场失败并指名自己 |
| 修正后的结论 | **五个守卫全部可达**，各被 6 个现有测试触发。注解陈述的理由是**假的** |

> **一个用来测量「归因错位」的仪器，自己发生了归因错位，就会确认你原本相信的任何事情。**
>
> **纪律（本轮最贵的一条）**：**当测量不稳定时，第一件事是检查「你用来解释它的工具」
> 是否稳定。** 推论：任何「我测过」的结论，必须同时交代**用什么测的**；
> 而「用什么测的」本身也可能是个错误答案。
>
> 这条纪律之所以比上面六个缺陷都重要：那六个各只对本缺陷有效，
> 而**这个方法错误适用于所有测量**。

### 9.0.1 后续：同一实验在修复 #7 / #8 之后给出了**相反**的答案

这一段必须紧跟 §9.0，否则读者会以为「五个守卫全部可达」是本仓库的当前事实。

修正 #5 的过程中，为闭环那条「注解理由是假的」而动手写守卫测试，**结果挖出了 #7 和 #8**。
把这两个真实 BUG 修掉之后，用**同一套抛错哨兵**、在**同一形态的测试套件**上重测：

| 时点 | 代码状态 | 哨兵实验的写法 | 注解文字 | 失败测试 | 结论 |
|---|---|---|---|---|---|
| §9.0 当时 | 含 #7 / #8 | 守卫体与注解**一起**被替换 | **被删除** | 1（注解钉桩测试） | **不可采信** |
| §9.0 当时 | 含 #7 / #8 | 守卫体被替换、注解保留 | 保留 | 未重测 | —— |
| 修 #7 / #8 之后 | 已修 | 守卫体被替换、注解**逐字节保留** | 保留 | **0** | **不可达** |

**只有最后一行在方法上是端到端干净的**，注解的真假只能建立在它上面。
第一行之所以不可采信，见 §9.0.2——它失败的那个测试断言的是注解**文字**是否存在，
与守卫是否可达无关。

### 9.0.2 支撑上一节翻转的证据本身带着一个假阳性

把某个守卫**连同它的 `c8 ignore` 注解一起**替换为 `throw` 时，恰好有一个测试失败：
`coverage-annotations.test.ts` 里的「注解集合被钉住」。那个测试断言注解**文字**仍然存在，
所以**删掉注解它就会失败，与被测的可达性毫无关系**。
照字面读，「一个守卫 ⇒ 一个失败测试」看起来像可达性证据；实际上它只是「注释被改了」的证据。

**修正后的实验保持全部六行注解逐字节不变，只替换被守卫的语句体**：

| 被替换为 `throw` 的守卫体 | 注解是否保留 | 失败测试数 |
|---|---|---|
| `welchTTest` 的 df 守卫 | 6/6 保留 | **0** —— 127/127 全通过 |
| `betaContinuedFraction` 的 `d` 初值 | 6/6 保留 | **0** —— 127/127 全通过 |
| 循环内两个 `d` 守卫 | 6/6 保留 | **0** —— 127/127 全通过 |
| 循环内两个 `c` 守卫 | 6/6 保留 | **0** —— 127/127 全通过 |

**被执行到的路径上放一个 `throw`，测试套件不可能通过。**
四次运行全绿，因此这是**不依赖计数器归因**的可达性证明。

> **纪律（本轮第三条最贵的）**：**哨兵实验有两个扰动旋钮，两个都必须按住。**
> 语句体必须变（那是探针），而**其他任何东西都不能变**。
> 这里注解注释就是一个没被承认的第二个旋钮，而它恰好被接到一个「一拧就红」的测试上。
>
> **推论**：一个「探针」如果同时改动了**不止一处**，它测的就不是你以为的那一处。
> 做扰动实验前先列出**所有**被改动的字节，然后确认只有一个是故意的。

两次测量**都正确**，只是对象不同。**注解文字一个字都没改，也没有任何机制去重新评估它。**

> **纪律（本轮第二条最贵的）**：**方法写出来之后，还要在代码变更之后再跑一次。**
> 一条关于「代码不可达」的注解，是**关于某个修订版**的断言，不是耐久事实。
> 后续修复可以让一条假注解变真，也可以让一条真注解变假，**全程没有任何信号**。
>
> **推论**：注解、覆盖率注释、文档里的「实测结论」都带**版本有效期**。
> 只写结论不写它测的是哪个版本，等于写了一句会过期的话而不标注保质期。

### 9.1 共同成因（前四个）

四个缺陷都不是「代码写错了」，而是**边界处的假设**：

1. **位置边界**：守卫与它保护的工作的先后顺序；
2. **返回值边界**：什么信息「属于」一个结果，什么信息「关于」一个结果；
3. **表示边界**：内存中的值与持久化后的值是不是同一个值；
4. **类别边界**：「修掉这个实例」与「消除这个模式」是两件事。

### 9.2 对后续工作的约束

- **#2 的教训已升格为纪律**：任何「降级但不失败」的路径，必须同时**产出可见的警示**，
  否则它比失败更糟。已固化为 `AblationReport.cohortCoverage` + 报告顶部 banner。
- **#3 的教训是测试方法学的**：只测内存对象的测试套件**看不见序列化缺陷**，无论它对渲染
  函数的覆盖多完整。凡「写盘 → 读回」的产物，必须有跨该边界的测试。
- **#4 的教训是纪律的升级**：修两个实例不会让模式非法，因此改为断言**结构不变量** ——
  「渲染器输出的每个小节都必须仅凭报告对象得到」，以 JSON 往返后渲染来检查。
- **#2 的未审计缺口已闭环（本轮）**：9 个返回点全部审计，7 个干净，第 8 个（retry）
  确有同类缺陷并已修复。**缺口声明是真的。**
- **#4 的副作用**：审计过程中读出的 **1.50% 触发率**（3/200，control 为 0）说明该臂
  结论**欠功率**。见 §9.3。
- **#3 的未审计缺口已闭环（本轮）**：24 份归档产物逐叶审计完毕，41 个
  `decision.answer: null` 全部由**共现关系**解释（41/41 非 null ↔ `abstained: false`，
  41/41 null ↔ `abstained: true`，零矛盾），23 个 `ablation.*` null 属渲染器已处理的代换，
  **0 个未解释值**。见 `09-progress-and-delivery-report.md` §3 与 `AUDIT-PERSISTED-NULLS.md`。
- **#5 的约束**：覆盖率读数在 `cortex-core` 上有 **0.76pp** 的实测波动，
  **引用该包覆盖率时必须注明它是波动区间内的一个采样，而不是常量**。
  阈值仍为 95，**未放宽**——放宽阈值等于对指标用 `|| true`。
- **#6 的约束**：凡「迭代直到满足某判据」的循环，其**判据本身必须有一个「注定不满足」的
  测试**（如 `tol = 0`）来证明它不是恒真。`sinkhorn` 的回归测试即按此写。
- **#7 / #8 的约束（测试方法学，本轮新增）**：这两个缺陷存活下来的原因**是同一个** ——
  **测试的生成器从不进入被测分支**。#7 是一个**以分支命名却从不进入该分支**的测试
  （`z < 0.5` 的名字下断言了 `z = 0.3` 和 `0.7`，都在直接路径上）；#8 是一个
  **性质测试内部硬编码了参数**的测试（`fc.property(n, k, ...)` 里用了外层作用域的
  `p = 0.5`，而 `0.5` 恰是缺陷不可能发生的那个值）。
  **约束**：凡新增覆盖某个分支的测试，必须问「**它要失败必须出现什么输入？生成器会产生它吗？**」
  纯常量表可以留作回归锚点，但**不能作为该分支唯一的覆盖证据**。
  配套动作：**把修复回退，确认新测试变红** —— 否则新测试只是分母。
- **#9 的约束（口径纪律，本轮新增）**：任何**被排除了一部分样本**的测量，必须在产物里
  **同时记下分母与被排除的清单及其成因**，否则它的百分比会被读成整个样本的百分比。
  #9 的具体形态是：召回曲线对 **428** 题算、主报告对 **500** 题算，
  两个文件的每个数字都正确、**没有任何东西抛异常或失败**，
  错误只在**读者被邀请去做的那次比较**里。
  这与 #2（侧信道）、#3（序列化代换）、§9.0.2（性质测试的假阳性）**同属一类**：
  **测量静默收窄了自己的范围**。
  **约束**：凡新增一个会 `continue` / `skip` / `exclude` 的测量循环，
  必须同时输出**被跳过者的身份与原因**；只输出计数不足以让读者复核分母。

## 10. A2 收口后的优先级重排（本轮补充）

run `35523328949` 的 N=500 发布级结果（详见 `09-progress-and-delivery-report.md` §2.5）
给出了两条**互相独立**的事实，合起来决定下一步该做什么：

| 事实 | 读数 | 含义 |
|---|---|---|
| 召回广度（ceiling） | **96.26%** | 证据**几乎总在池子里**；广度只差 3.74 pp |
| 首位命中率（k=1 recall） | **33.18%** | 三分之二的题**把证据排错了位置** |
| k=20 recall | **89.72%** | 排序做对时，绝大多数题是可解的 |
| k=50 gain | **0.00%** | **继续加宽池子已无可回收的收益** |

**结论：瓶颈已经从「找得到吗」转移到「排得对吗」。**

> **因此 B1（交叉编码器重排）的判决价值高于 B3（专用抽取通道），也高于任何加宽池子的改动。**
> 原计划里 B3 排在 B1 之后是有理由的，而这份数据把它变成了**可量化**的理由：
> 一个只在排序上工作的机制，面对的是 63.08 pp 的可回收损失；
> 一个只在广度上工作的机制，面对的是 3.74 pp 的天花板。

> **§10 的排序前提已被 B1 实测否定（2026-09-22 更新，必须与上面这段一起读）。**
> 「排序是瓶颈」这个**诊断**没有被推翻——k=1 recall 33.18% 对 ceiling 96.26% 依然成立，
> **63.08 pp 的可回收损失依然在那儿**。被推翻的是**推论**：由「排序是瓶颈」推出
> 「重排能回收它」。两臂实测 Δ 分别是 **+1.33 / −1.33 pp，p 均 0.7539**（见 §B1 判决），
> 即**把重排接到这条管线上读不出效应**。因此：
>
> | 原排序 | 修正后 |
> |---|---|
> | B1 判决价值最高 | **B1 已判决（负结论），不再占用预算** |
> | B2（加宽池子）是 B1 的输入池消融 | **B2 失去前提**：先加宽池子再期待重排生效是没有依据的次序；降级为「仅当 B1 出现正效应后才有意义」 |
> | B3 次于 B1 | **B3 与 A6 解除 B1 的阻塞，成为下一个可执行项（第 12/13 项）** |
> | 排序缺口由重排填补 | **排序缺口的填补机制仍未知**：63.08 pp 的损失是真的，但重排（至少托管端点形态）不是它的解。需要的是**另一类**排序机制，或者对「首位命中率」这个指标本身的归因复核 |
>
> **这正是「诊断正确 ≠ 处方正确」的一次实例。** 上一版把 63.08 pp 读成「重排的机会」，
> 而 63.08 pp 只说明**损失存在**，不说明**哪个机制能回收它**。**可回收损失的大小是一个
> 上界，不是一个预测。**

同时必须挂上两条**尚未解决**的项：

- **conjunction 臂 −1.67%（cohort 7/7 完整，p=0.375）**：完整 cohort 排除了「比较不同人群」
  这一解释，因此这是一次真实负增量。**不显著只说明 180 题分辨不出它，不说明它不存在。**
  **本轮未推进**（B1 判决占用优先级；见第 9b 项）。
- **retry 臂 Δ=0.00%（触发 16/500，control 0）**：仍有内容可读，但仍不足以判决。

  → **不默认开启**。负结论，且**可证伪**（对照臂 `fallbacks = {0, 300}`）。见 §B1 判决。
