## 1. 为什么这一轮只剩这一条

`MR` 是全线最弱的能力（84.30% 对 MemCog 92.48%，差 8.18 点）。围绕它的六个方向已经各自按判据关闭：

| 方向 | 读数 | 出处 |
| --- | --- | --- |
| 措辞（七个 `ask` 值：enumerated / sweep / aggregation / silent / operands / candidates / derive） | 没有一个把 `MR` 推过 88 | §13.34–§13.205 |
| 房间（宽度） | 24K 76.9 → 36K 79.3 → 48.5K 83.5；55,000 重分配**没买到任何东西** | `PROMPT-ROOM-IS-LOAD-BEARING.md` §10、§14.34 |
| 密度（分层分辨率） | `MR` +6.7% 轮次、字符 −0.1%，且账单不动 | `RETRACTIONS.md` §1 |
| 账单价（房间表） | −25.4% 账单卖 −1.85 点，第二段比第一段贵 1.5 倍 | `RETRACTIONS.md` §2 |
| 算术（聚合步骤） | 22 道错题里 **22 道**答案等于 Step 1 行数——错的是集合不是相加 | `AUDIT-MR-ENUMERATION.md` §1 |
| 检索（证据） | 20 道失败题的金标轮次**全部**在交付窗口内 | `MEASURE-MR-CEILING.md` §1 |

剩下的是**读者**。而读者轴上我们只测过两件事：`thinking` 开关（+4.35 点总体、`MR` +4.13、`TR` +12.4；`M1`），
以及 `v4-pro` 的 **non-thinking**（−5.55 点，且失败模式是指令跟随退化：过度作答、该弃权时不弃权）。
后者是一份被自己写明的负结果：v4-pro 的价值在它自己的推理模式里，而我们从未在那个模式下派发过它。

> **H**：`MR` 的剩余差距是读者能力，不是证据、不是措辞、不是房间。因此在**同一批题、同一份提示词字节**下，
> 把读者换成以推理为优化目标的模型并让它运行在自己的模式里，`MR` 会上升。

## 2. 单一变量，以及为什么这一次它真的是单一的

这次派发改变**一个**字段：`reader.model`（`deepseek-chat` → `deepseek-v4-pro`）。提示词由一个不含读者身份的
装配器生成，所以 121 道 `MR` 题的 `promptDigest` 必须与控制臂逐字节相同——这不是承诺，是产物里的
`promptIdentity` 块必须报告 `identical: 121, differ: 0`，否则这次派发作废（§5 第 3 行）。

`thinking` 保持登记的 `multi-session+temporal`：`MR` 的题走 `multi-session`，本就在启用范围内，所以它不是
第二个变量。

**判官会跟着读者走，这是已知的混杂，也是本轮的诚实边界。** `CORTEX_JUDGE_MODEL` 目前只接在
`judge-audit.yml` 里，A/B 臂没有把判官钉住的入口（这是一个真实缺陷，下一轮修）。因此本轮的读数按
「判官 = v4-pro」取得，并在结论处用 `regrade-cortex-memory.yml` 以 `deepseek-chat` 复判一次作为对照：
两次判官的结论一致才进入 §5 的采纳分支。

## 3. 总体与对照

- **总体**：LongMemEval-S 的 121 道 `MR` 题（`capability=MR`），4 轮重复，`limit=0`。
- **对照**：`44017278305` 的同 121 道题（登记房间 48,460 / 24,000，同一读者代际 `deepseek-chat`，
  同一判官代际，4 轮多数票 101/121 = 83.47%）。
