# 预登记：会话边界时钟（第 131 轮）

> 本文件在**任何派发之前**写下机制、成本、判据与后果。它登记的是一个**默认关闭**的能力：本轮不花钱，
> 也不产生任何准确率读数。可发布信号不因它改变。

---

## 1. 先审计再动手：三个候选，两个被自己的测量否掉

`S16`（run `44017278305`，500 题 × 4 轮 = 2,000 格，1,825 正确 = **91.25%**）的逐题产物是本轮全部
判断的唯一来源。按能力分解，错误的质量分布是不均匀的：

| 能力 | 题数 | 每轮正确 | 正确率 | 每轮错误 |
| --- | ---: | ---: | ---: | ---: |
| `ABS` | 30 | 30.00 | **100.00%** | 0.00 |
| `TR` | 127 | 120.25 | 94.69% | 6.75 |
| `KU` | 72 | 66.50 | 92.36% | 5.50 |
| `IE` | 150 | 138.25 | 92.17% | 11.75 |
| `MR` | 121 | 101.25 | **83.68%** | **19.75** |

`MR` 占全部 43.75 个错误里的 **45%**，且是唯一一条同时在三处排第一的能力（准确率最低、房间最敏感、
对 MemCog 92.48% 差 −8.80）。所以这一轮只问一个问题：**`MR` 的 19.75 个错误是什么形状？**

121 道 `MR` 里 57 道至少错一轮（16 道四轮全错、11 道部分错），每题平均交付 **201.1 个轮次**、
45,000 字符上下。把 16 道全错题逐条读完，得到三个能被测量检验的假设——两个没有撑住：

### 1.1 候选 A「替读者把数加出来」——被否掉

产品已有确定性账本（`parseTallyLedger` / `tallyTotal`），把读者列的清单变成精确计数是一个便宜的
扩展。它要求一个前提：**清单是对的，数错了**。产物里 34 道数字型金标的错题：

| 判据 | 计数 |
| --- | ---: |
| 清单行数 == 金标，而读者最终答案 != 金标 | **1** |
| 清单行数 != 金标 | **31** |
| 读者没给出可解析答案 | 6 |

**34 道里只有 1 道是「数错了」。** 其余是成员判定错：名单本身就不对（`gpt4_2f8be40d` 把 5 场婚礼都
算进去，金标 3；`gpt4_ab202e7f` 数 7 件厨具，金标 5）。替读者做加法会把一个错误的清单精确地加成一个
错误的数。**结论：不建。**

### 1.2 候选 B「替读者做日期算术」——被否掉

登记表第 20 行说确定性日期算术是「最便宜的产品侧时间收益」。读数否决了这条说法：

| 证据 | 读数 |
| --- | --- |
| `370a8ff4`（金标 15 周）读者的两个日期之差 | **81 天**，与 2023-01-19→2023-04-10 完全一致，**算术是对的** |
| `gpt4_7abb270c`（六家博物馆排序） | 名字与金标不同 → 是检索错，不是排序错 |
| `eac54add`（四周前的里程碑） | 读者找到「3 月 1 日入职」，金标是「签下第一个客户」→ 事件定位错 |
| 把 `resolveTimeRange` 的逻辑在 500 题上镜像一遍 | 只解析出 **25** 个窗口（`TR` 15 / `MR` 8 / `IE` 2） |

**算术不是缺陷所在**：读者算得对，算的东西不对。**结论：不作为本轮机制**（它仍然是登记表里一条
真实的 ⑯ 缺口，但按「先测量后建」的规则，它不是现在该建的那条）。

### 1.3 候选 C「告诉读者每段对话发生在什么时候」——保留

16 道全错题里反复出现同一个签名：**读者把同一个日期印在所有条目上**。

| 题 | 金标 | 读者答案 | 读者印的日期 |
| --- | ---: | ---: | --- |
| `gpt4_2f8be40d` | 3 | 5 | 五场婚礼全部 `2023/10/15`（**问题日期**） |
| `d851d5ba` | $3,750 | $8,750 | 八笔捐款全部 `2023/03/20` |
| `gpt4_372c3eed` | 10 年 | 8 年 | 两个事件同一 `2021/08/20` |
| `21d02d0d` | 2 | 1 | 三月的事件印成 `2023/04/26` |

签名是可测量的，而且定义必须写死在这里，因为它决定了所有后续引用：
**「一次回复打印 ≥3 个日期，其中 ≥3 个完全相同」**

| 人群 | 命中 | 比例 |
| --- | ---: | ---: |
| 至少错一轮的 57 题 | **17** | **29.8%** |
| 四轮全对的 443 题 | **39** | **8.8%** |
| 富集倍数 | — | **3.39×** |

而日期本身**没有丢**：该产物 41,822 个交付轮次里 **0** 个缺少 `[YYYY/MM/DD …]` 前缀；`MR` 的 121 题
里 **93** 题交付了 ≥2 个不同日期（中位数 **11** 个）。所以缺陷不在数据、不在渲染的字节数，而在
**归属**：200 个轮次里，日期贴着一段读者扫过就丢的段落；等到它把候选写下来时，那个日期已经不属于任何
东西了。

## 2. 建的是什么

`packages/cortex-memory/src/turn-clock.ts`，一个纯函数：

```ts
export function annotateSessionBoundaries(prompt: string): string;
```

它把**已经组装好的提示**里每一行 `Session N` 改写成 `Session N (2023-05-21)`，块内日期跨天时写成
`Session N (2023-05-21..2023-05-27)`。三个决定，各有测试：

| 决定 | 理由 |
| --- | --- |
| 在**预算之后**、对**渲染后的文本**操作 | 第一版按「被选中的轮次」计算标签，属性测试当场抓住它：700 字符的房间选 4 个轮次、渲染 2 个半，标签却写着 `2023-05-21..2023-12-31`——一个读者从未收到的日期 |
| 只认**方括号**里的日期 | `I moved on 2023/05/21` 是内容，是事件发生的日子；把它写进边界就是在说证据没说过的话 |
| 不存在的日子不打印 | `[2023/02/30]` 是笔误，边界不能把一个不是日期的日期写进读者唯一会信的那一行 |

**默认关闭**（`sessionClock?: boolean`，`undefined` 即关）。关闭时提示与产出每一个已发布数字的那份
**逐字节相同**（`turn-clock.test.ts` 断言）。

### 2.1 成本

每条边界 `Session N (` + 日期 + `)` ≈ **22 字符**。二十段会话的窗口约 **450 字符**，占 45,000 字符提示的
**1.0%**（≈110 token）。交付的多重集不动：机制只改边界行。

### 2.2 可达性（需求 ⑯ 的五个环节）

| 环节 | 位置 | 缺失时的失败 |
| --- | --- | --- |
| 产品渲染 | `memory.ts` `#promptSessionAware` | 模块存在而没有任何提示带它 |
| 臂能请求 | `bench/run-ablation.ts` 条件展开 | **`semanticCarry` 的原样失败**：选项、变量、记录都在，臂永远不执行 |
| 臂记录 | `bench-memory-arm.ts` + `report.ts` | 执行过的运行与「字段出现之前」的运行不可分 |
| workflow 转发 | `benchmark-cortex-memory.yml` | 任何派发都是控制臂 |
| 派发器写入并声明 | `dispatch-cortex-memory-ab.py` | 残留的 `on` 给下一次控制运行贴上标签；未声明的 `on` 在钱花完之后被拒 |

五处由 `tools/__tests__/test_session_clock_wiring.py`（10 条）逐条钉住，其中两条做过变异检验：
删掉 `run-ablation.ts` 的展开 → 该条转红；删掉 `memory.ts` 的调用 → 产品路径测试转红。

## 3. 判据（读数之前写死）

**本轮不派发。** 判据写在这里是为了让下一次派发不能事后挑一个方向。

### 3.1 设计约束：两个格子必须在同一个 job 内

`§11.13` 用本仓自己的数据量出跨派发的分辨力地板是 **0.70 点**（参考侧未受处理，两天里 882 → 896 格）。
这个机制的可信效应小于该地板，所以**跨派发比较不构成判决**，无论它给出什么符号。判决只能来自同 job
双格（`flat` 与 `on` 交错），这也是下一轮的仪器工作。

### 3.2 四条判据

| # | 判据 | 阈值 | 失败的含义 |
| --- | --- | --- | --- |
| C1 | `MR` 正确题数变化 | ≥ **+3** 题（121 题中），且题级 `up − down ≥ +3` | 效应小于地板或方向相反 → 不切换 |
| C2 | 非 `MR` 路线的提示摘要 | **逐题不变**（`promptDigest` 相等） | 机制越过了它声明的 reach → 该运行作废，不是「效应」 |
| C3 | 交付多重集 | `carried` 与 `evidenceChars` 逐题相等 | 机制动了证据 → 读数不可归因 |
| C4 | 成本 | 每题提示字符 ≤ **+0.5%**、每正确题 token ≤ **+1%** | 用更多 token 买准确率 → 按成本轴重新登记，不得以准确率单独通过 |

C2/C3 是**前置条件**而非结果判据：它们在机制的设计里已经成立（只改边界行），所以它们失败只有一种
解释——实现与声明不符。

### 3.3 后果表

| C1 | C2/C3 | C4 | 动作 |
| --- | --- | --- | --- |
| 通过 | 通过 | 通过 | 下一轮把默认值切到 `on`，回填读数，更新手册与账本 |
| 通过 | 通过 | 失败 | **不切换**。记为「有效但更贵」，成本轴另立机制 |
| 失败 | 通过 | 通过 | `on` 保持可选、默认仍 `off`；写 `RETRACTIONS.md` 一行，机制不删 |
| 任一失败 | 失败 | — | 运行作废，先修实现，不解释数字 |

## 4. 什么会否证**解释**而不只是效应

机制的解释是「误归属」。它有一个可否证的推论，写在派发之前：

> **P1**：若 `MR` 出现退步，退步的题必是**交付了 ≥2 个不同日期**的题（93 / 121）。落在 28 道单日期题上
> → 解释错，风险来自别处。

> **P2**：若机制有效，增益应集中在**签名人群**（17 道塌缩题）。若增益均匀分布 → 有效但不是因为归属。

两条都不影响 C1 的判决，但它们决定下一轮是否还沿着「归属」这条线走。

## 5. 本轮不声称的东西

- **不声称 SOTA 进展。** 端到端仍是 91.25%，对 Maximem Synap 95.6% 差 −4.35；`MR` 83.68% 对
  MemCog 92.48% 差 **−8.80**。这两个数字本轮一个也没动。
- **不声称机制有效。** 它有一条 3.39× 的富集签名、一条精确的成本和零读数。默认关闭正是这个状态的
  诚实表达。
- **不声称候选 A/B 永久无用。** 它们是被**这一份产物**的量否掉的：清单对的只有 1/34、算术对的样本
  在三例里成立。换一批题、换一个读者，两条都值得重测——但那时要重新登记，不得引用本轮的否定当结论。
