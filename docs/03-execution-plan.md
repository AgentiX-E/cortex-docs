# Cortex 项目执行推进计划

> 对象：`AgentiX-E/cortex`。内部文档。
> 分工：**本文回答"按什么顺序做、做到什么算过"**；设计要求见 [02](02-technical-design.md)，
> 已完成什么见 [04](04-execution-tracking-report.md)，产品定位见 [01](01-product-whitepaper.md)。
> 纪律：**没有指标的功能不立项；没有消融的机制不算贡献；没有预注册的实验不算证据。**

---

## 0. 结论先行

1. **项目分三段**：设计（已完成）→ 实现（二十四步，§2）→ SOTA 攻关（已在进行）。三段的门禁不同，
   混在一起谈是过去多次误判的根源。
2. **实现阶段不从 SOTA 攻关的剩余项开始**，而从**有 POC 或单测可依据**的步骤开始（§2）。
   理由：SOTA 侧剩下的杠杆（换读者、`maxSessionChars`）**都不改变架构**，而架构侧各步
   每一项都有可复跑证据。
3. **验收不用"感觉更好"，用五个数**：逐能力计数（`mean (min–max)`）、配对 McNemar、Wilson
   区间、噪声底、以及"这一轮动了哪个变量"的配置行。
4. **单次运行无法支撑小于 5 道题的声称**（噪声底 MR −2 / TR −4）。这是本计划最硬的一条约束，
   它已经否掉了此前所有 1–3 道题的移动。
5. **回归即回滚**：任何使基准变差的改动，即使理由看似合理，也按实证 revert 或默认关闭
   （先例：图扩散激活 TR 77.95%→70.87%；重排两臂 Δ ±1.33 pp）。
6. **每轮迭代必须交付两样东西**：本条结论的读数，以及**剩余缺口清单 + 关闭它的下一步**、
   直到缺口为空（§12）。
7. **验收标准从散文变成可执行物**（第 33 步）：17 条判据写在
   `cortex/packages/cortex-eval/src/acceptance.ts`，当前值由 `tools/acceptance-check.mjs`
   现算，文档里引用的分数由 `tools/docs-crosscheck.mjs` 与代码比对。三个后果：
   判据有 `gate`（已达成，掉下来拦）与 `aim`（未达成，报告不拦）之分；`unrun` 是独立状态
   而不是 0；**文档写错一个数字会让 CI 变红**。

## 4. 测试方法与覆盖率

### 4.1 TDD 铁律

1. 先写失败测试 → 最小实现 → 重构。**测试必须先红**（本轮多次以"改动前 2 个变红"作为证据）。
2. 覆盖四维度（语句/分支/函数/行）**每维 ≥95%**，目标 100%。
3. **禁止 mock**：真实 `better-sqlite3`、`pg-mem`、真实 SQLite-WASM、真实小模型。
4. 属性测试覆盖纯算法：SVD 重构误差、Sinkhorn 双随机收敛、FSRS 单调性、t 分布对称性。
5. 每个新增测试必须能**指名它防的缺陷**；不能指名的测试是分母。

### 4.2 三类"假通过"，各有对策

| 假通过                           | 例证                                                                      | 对策                                                                           |
| -------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **检查不可能失败**               | `p03` 首版的 `async () => true`                                           | 每个守卫必须有一条**故障注入**测试证明它会红                                   |
| **生成器选在缺陷不可能发生的点** | `binomialCdf` 的性质测试硬编码 `p = 0.5`（13 处调用里 11 处如此）         | 生成器要覆盖缺陷的**定义域边界**；用旧代码反向验证新测试会红                   |
| **断言打错层**                   | 普查测试打在 `countCallers`，缺陷实际在 `censusPackage`                   | 首轮注入存活即视为"没测到"，而不是"实现对了"                                   |
| **结构性零**                     | `[POC-6]` 在 1,467 条 persona 语句上读出 0 次泄漏，而发布规则一次都没命中 | 报告任何"零"之前，先报**被测机制的命中次数**；命中为 0 则该列写 `NOT MEASURED` |

### 4.3 覆盖率注解的纪律

`v8 ignore` 不得用来买覆盖率。判定一个注解是否正当，唯一办法是**替换语句体为抛错哨兵**看它是否
可达；且**注解文字本身是第二个扰动旋钮**（曾把守卫连同注解一起替换，测出来的是另一个缺陷）。
清理目标：注解数降到 0，覆盖率仍 ≥95%。

#### 7.1.1 A3 的预注册协议（第 13 步写定，先于任何点击）

| 项     | 值                                              | 为什么                                                            |
| ------ | ----------------------------------------------- | ----------------------------------------------------------------- |
| 单元   | **同一张卡**，两种呈现（原句 / 模型拆出的原子） | A3 说的是「呈现方式」，不是「卡片集合」；比不同卡片会测到卡片本身 |
| 配对   | 每张卡两个判断，构成一对                        | McNemar 只在**不一致的对**上检验                                  |
| 顺序   | 偶数张先原句、奇数张先原子                      | 疲劳效应落在两臂上，而不是落在「第二个」                          |
| N      | **≥20 对**                                      | 预注册；不足则判 `underpowered`，不报告点估计的意义               |
| 判据   | 精确 McNemar `p<0.05` **且** `abs(Δ)≥10pp`      | 两者都满足才算更好；只有一个满足时判 `no-difference`              |
| 停止   | 一次会话做完，不因中途读数重跑                  | 与 §8 的纪律一致                                                  |
| 空结果 | `no-difference` 是**结果**，不是失败            | 设计说明写下的是「零假设为预期」                                  |

**判定由代码给出，不由人给出**：`scoreA3` 返回五个可能值之一（`atoms-better` / `source-better` /
`no-difference` / `underpowered` / `unpaired`）并附一句可引用的理由。算术有 17 条测试，全部对着
手算的二项分布值。

**门槛现在是一条命令**：

```
node tools/a3-review.mjs dosage --cards <cards.json>
```

它把上面那三行算数变成机械检查，并打印 `profile` 与 `promptVersion`——因为 A3 的处理是"呈现方式"，
而呈现方式随**哪个模型**和**哪版提示词**变化。第 14 步用这条命令比较了 v2 与 v3，两次都是
`GATE FAIL: 1/20`。

**怎么收这 40 次判断**（第 16 步）：终端循环不是唯一的路，也不该是默认的路。

```
node tools/a3-review-page.mjs --cards <cards.json> --out review.html
# 打开 review.html，每张卡答两次；中途关闭不丢，回到页面继续
node tools/a3-review.mjs score --decisions a3-decisions.jsonl
```

页面与 CLI 读同一份 `cards.json`、导出同一种 JSONL；`review-page.test.ts` 把导出行直接交给 `scoreA3`，
而不是逐字段比对——**一个形状在最后一步被丢掉，等于二十次判断白做**。

**开跑前的门槛（本步新增）**：先量**处理强度**——两臂的呈现是否真的不同。若同一段文字占多数，
收集点击测到的只是「模型不拆」，而不是「原子有没有用」。第 13 步实测 14/20 相同、1/20 真拆，
因此点击被有意推迟；第 15 步远端档把剂量推到 75%，第 20 步据此开跑，判 `no-difference`
（20 对、1 对不一致、−5.0pp、p=1.0000）。

### 7.4 新增三个增量：受控矛盾集与六个开关（第 29–33 步）

前三节的消融都在 LongMemEval-S 上做。新增量不行，理由是一条负结果：**真实语料的矛盾密度太低**，
Nous（arXiv 2606.22030 系）在 LoCoMo 上测出贝叶斯信念更新**几乎不优于 last-write-wins**。
一个不含冲突的语料测不出"为冲突而生的机制"。所以自建**受控矛盾集**（17 例，确定性生成，
无模型），每个家族对应一个已发表失败形态：

| 家族          | 例数 | 来源的失败形态                                               |
| ------------- | ---- | ------------------------------------------------------------ |
| `type-i`      | 3    | STALE Type I：同 slot 不同值、无显式否定                     |
| `historical`  | 2    | PACMI：历史问题必须答得出旧值                                |
| `false-stale` | 2    | 对照组：更新落在提问时刻之外，标成 stale 才是错              |
| `conflict`    | 2    | 同一时刻两个值——不是更新，是**真矛盾**，正确行为是答"不知道" |
| `type-ii`     | 2    | STALE Type II：上游变了、下游从未被提及                      |
| `cascade`     | 1    | PACMI：被失效事实是第三条的前提                              |
| `plan`        | 4    | PM-Bench：已落空/仍待定/已兑现的计划                         |
| `immutable`   | 1    | 既定事实不得被后来事实取代                                   |

三臂 + 八项消融，全部走**同一个函数** `assemble()`，只切 policy：

| 臂 / 消融                                    | 准确率                     | 差                                   |
| -------------------------------------------- | -------------------------- | ------------------------------------ |
| `flat`（无台账、无窗口、无分池、无冲突标记） | 6/17 = 35.3%（即 K0 − K1） | —                                    |
| `annotated`（同 flat，渲染照常）             | 6/17 = 35.3%               | 0.0pp                                |
| `gated`                                      | <!-- reading:K0 -->100.0%  | 比 flat 高 <!-- reading:K1 -->64.7pp |
| −`persistence`                               | <!-- reading:K2 -->58.8%   | −41.2pp                              |
| −`uniqueness`                                | <!-- reading:T1 -->88.2%   | −11.8pp                              |
| −`temporality`                               | <!-- reading:T1 -->88.2%   | −11.8pp                              |
| −`cascade`                                   | <!-- reading:T3 -->94.1%   | −5.9pp                               |
| −`fulfil`                                    | <!-- reading:T3 -->94.1%   | −5.9pp                               |
| −`immutability`                              | <!-- reading:T3 -->94.1%   | −5.9pp                               |
| −`time-anchor`                               | <!-- reading:T4 -->100.0%  | 0.0pp（预注册为零）                  |
| −`lapse`                                     | <!-- reading:T4 -->100.0%  | 0.0pp（**结构性零**，见 02 §5.5.9）  |

**读法只有一条**：这是**机制归因**，不是收益大小。基线是"按相关度取第一、并列按 id"，
矛盾是构造的，17 例的区间很宽。它证明的命题是"每个机制在它该起作用的地方起作用、
在不该动的地方不动"，而不是"能涨多少分"。任何把这个 64.7pp 引用成产品增益的写法都是错的。

**这一轮的方法论修正值得单记**：三臂之前是**三份实现**，所以差距随时可能来自代码而非能力。
现在它们是一次 `assemble` 调用加不同 policy，`flat` 与 `gated` 的差只可能来自开关。
代价是 `annotated` 与 `flat` 同分从"经验发现"降级为"构造性事实"——这个结论更弱，但它是真的。

`cortex-memory` vs 参考管线 是**决定认知层价值的关键消融**，也是预算投向的分水岭。
**在该结果出来之前，不应再向认知层追加新能力。** 预注册要求：双侧精确 McNemar `p<0.05` 且
`Δ>0`、全量 N=500、4 runs、`temperature: 0`、**零假设为预期**（"不劣于"而非"超过"），
一次 dispatch 不偷看不重跑。

## 8. 预注册纪律与停止规则

1. **写下来再跑**：假设、单变量、判据、停止规则，四项缺一不可。
2. **一次 dispatch**：不为更好的抽签重跑；三种结局各自预先定义后续动作。
3. **零假设也是预注册**：把"预期没有效应"写在派发之前，使 null 结果既不能被读成失败，
   也不能被事后调参转成正值。
4. **对照组必须逐字符成立**：否则不允许下"更好/更差"的结论。
5. **负向点估计必须复核**：`p=0.375` 不显著只说明分辨不出，不说明效应为零（conjunction 臂的
   教训：复核后判决比原读数更不利）。
6. **不再运行"结构上产不出"的实验**：`candidateSides` 的 question-only 回退只产 1 侧，而
   `discriminateContext` 需 ≥2 侧才标注 —— 该路径**结构性**产不出标注。先证明通道存在，再派发。

## 11. 风险、回滚与回归规则

1. **回归即回滚**：基准变差 → revert 或默认关闭。不接受"理论上应该更好"。
2. **一次只动一个变量**：配置行必须能说清这一轮动了什么；多变量同动视为无效实验。
3. **不做"更谨慎"式对策**：对"配置无法抵达测量"这类系统风险，对策是**双向断言闸**（dispatch
   input 与产物字段互相校验），不是让操作者更小心。
4. **门禁宁缺勿滥**：一条会在**正常运行**上报红的检查比没有检查更糟（它教会读者跳过输出）。
   被拒绝的候选检查要写进文档（例：`evidenceTurns > k`、turn 长度 > cap 都会在正常配置上触发，
   故不加入 `--audit`）。
5. **成本风险**：供应商限流契约见 02 §11；重试不得把已付费的嵌入重复付费。

每轮必须交付，缺一即视为未完成：

1. **读数**：本轮结论 + run id + 配置行 + 区间/上界；

4. **下一步**：按依赖排序，并写明**为什么是这个顺序**（通常因为它是其他项的前置）；
5. **诚实边界**：本轮**没有**证明什么。

### 13.3 一条不会再犯的错

这一轮最大的收获不是那 64.7pp，而是**发现了消融在测自己的实现**。判据很简单，可以复用：

> 一个机制读数，如果它的调用栈里没有产品代码，那它测的是夹具。

`assemble` 的引入让这条判据可以机械检查：`tools/export-census.mjs` 现在会报告

才是这两个机制第一次进入产品路径。

### 13.4 第 56 步的坐标与剩余步骤

**一句话坐标**：84.20%（421.0/500，四跑均值），距 85.0% 阈值 **0.80pp**，距可复现前沿 85.8–86.5 差
**1.60–2.30pp**，距 RAW-RAG 的 87.53 差 **3.33pp**。

**这一节在本轮被重写过一次，原因是检索侧被封死了。** 此前三条距离各自挂着一个"具名检索机制"
（预算、池宽、重排）。§13.123.1 把 500 题的 `goldOverlap` 一次性读出来，三条机制同时被否：

| 事实（500 题全量）                       | 数值                     |
| ---------------------------------------- | ------------------------ |
| gold 单元总数                            | 7,516                    |
| 已进入检索池（`pool`）                   | 7,155 — **95.2%**        |
| 已进入 prompt（`carried`）               | 6,501 — **86.5%**        |
| 83 道错题中，gold **不在** prompt 的      | **0 道**                 |
| 83 道错题的 gold 最佳名次——中位 / 均值    | **0 / 2.1**              |
| gold 最佳名次 < 10 的错题                 | **78/83 — 94.0%**        |

该统计在 `T=0`（421/500 均值）与 `T=default`（421.5/500 均值）两臂上**逐字节相同**：
三个总量都是 7516 / 7155 / 6501，错题的 gold 最佳名次中位都是 **0**。温度不改检索，
这一点因此同时是这两臂"只差一个变量"的又一条证据。

**没有一道错题是因为证据缺失。** 错题的答案证据中位排在**第 0 位**，94.2% 在前十位之内。

由此三条机制被逐条否定：

| 机制                    | 为什么动不了这个数                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **S-5 交叉编码器重排**  | 重排是对池的置换。错题的 gold 已在 0–18 位，没有一种置换能改进列表的第一个元素                                              |
| **抬池宽**              | 95.2% 的 gold 已经召回。完美池只多加 4.8% 的*单元*，而这些单元所在的题本来就有 gold 在 prompt 里                            |
| **96,000 预算**         | **这一行在 §13.139 被就地修正：结论不变，理由换了。** 原写「prompt 跑在 46,622 字符 / 48,000 预算、没有一题贴到上限」——46,622 是**均值**。同一份产物的分布是中位 46,851、最大 47,591、**468/500 题 ≥ 上限的 95%**、恰好 48,000 的 0 题：预算在几乎每道题上都绑定，绑它的是**渲染器**（`max < cap` 是适配程序的性质）。正确读法是「这根杠杆没有可花的余量」（最紧一题只剩 735 字符，不到两个 turn），不是「它不绑定」 |

**这就是本轮真正的进展**：不是拿到了分数，而是把三个"应该有用"的实验在**不花一次派发**的情况下判定
为无效，并且给出了机制而不是噪声解释。一条可复用的纪律随之写下：凡调整预算/池宽，先证明该约束**绑定**

**新的目标位置是"读"而不是"取"。** 剩下的 3.33pp 全部落在读者侧，而且有直接对照：同一模型、同一
数据集、**更小窗口**的 `reference-pipeline` 在 MR 上是 86.78%，本臂 71.9%，差 18 题。曾把差异归因到
一句指令的方向——参考臂要求 *"write ONLY the final answer"*，本臂要求**把列表写出来**——并据此派发了
`ask=silent`。**这条归因已被该实验否证**（§13.127）：同样的两步、把笔记改成不写出来，MR 从 87 掉到

| 5   | **`reviewPass: recover`（已注册，§13.128）**   | 排在 3 之后（同为读者侧）      | 人口用产品自己的谓词数出来：**16 题**（MR 10 / TR 5 / KU 1），ABS **0**（29 次弃答全为裸 token）；判据：≥5 题转为正确，ABS 不动，5 道计数题是转化主力 | 结构上只能赚不能亏（只对已判错的题开火），上限 +16 题 |
| 6   | **MR 块级差分（本轮新增，指向 §2.1.2 第 3 条）** | 3 结算                       | 参考臂 MR 106/121 与本臂逐句对齐，每句单独定价；先测它的会话上下文与 Step 2 逐题型算术 | 同一个 artifact 里已有 87.6% 的同读者证据，缺口是块不是模型 |
| 6b  | **agentic 多步检索**（MemCog 方向，92.5 MR）  | 6 与 1–5 全部读完             | MR ≥ 100 题；每题步数 2–3 且可复算                                       | 唯一有公开高分背书的架构级方向 |

**检索轴的总天花板是 5 题，而且是按能力分的（§13.126）。** 同一份 T=0 归档里 `goldRanks` 逐题可算：
83 道错题中，gold 最佳名次 **<10** 的 78 道、**≥10** 的 5 道、**没有一题存在未召回的 gold**。所以任何
**改排序**的机制——S-1 时间信号、S-5 交叉编码器、以及已退役的重排——合起来的上限是 5 题（最宽松读法），
而按"gold 已全部进 prompt"的严格读法上限是 **0**。按能力分：MR 2、TR 2、IE 1、KU 0、ABS 0。这直接改写了
两行判据：S-1 原写"TR recall@10 +3"，而 TR 的排序头寸只有 2 题；S-5 原写"整体 +2"，恰好等于天花板本身，
也就是说它可能达成预测而**不可能超过**预测。**新判据（§13.126.4）：任何检索类提案在派发前必须先报出
自己的上限**，且不得用 recall 作单位登记准确率预测。

**读者噪声地板：5.0%（§13.127.2）。** `ask=silent` 与对照在 IE/KU/TR/ABS 上的提示词**逐字节相同**（379 题），
判词却有 **19 道不同（5.0%）**、答案文本有 **191 道不同（50.4%）**——`temperature=0` 只固定了采样参数，没有
固定输出。这条改写了装配判据：**"未触及路由逐题复现"是不可满足的**，能复现的是**提示词**，不是判词。它同时
给第 2 步定了门槛：IE 只有 150 题，5% 的地板约 7 题，所以 IE 的净增益要 ≥5 题才读得出"护栏有效"。

**地板在 `recommend` 那一对被重新量了一次，而且比 5.0% 更强（§13.135）。** 500 题里 **466 道提示词逐字节相同**，
两次运行之间 **33 道判词翻转（7.08%）**、**净 +7（+1.5pp）**；按能力：MR 0 变动 / 12 翻转 / 净 −2，KU 0 / 5 / +5，
TR 0 / 10 / +2，ABS 0 / 0 / 0。而真正被处理的 34 道只买 2 卖 0，扣除未触碰桶自己的 1.50%/题之后，**真实超额
只有 +1.5 题**。三条推论改写登记规则：

1. **地板不再是一个常数，而是每一对运行自带的实现值**——它就在 artifact 里，在那 466 道没被碰过的题上，
   不需要向上一对借。`tools/ledger.mjs --across` 现在自动算并打印，超额 ≤ 0 时打印 `ATTRIBUTION FAILS`。
2. **全册低于约 2 个百分点的差异，单次运行读不出来。** 121 题的 MR 尺度上净值离散度约 √12 ≈ 3.5 题（≈2.9pp），
   所以 `derive` 的 MR +5 判据约 **1.4σ**——它保留，但追加"必须给出相对 KU+ABS 的正超额"。
3. **判据的算术上限必须在被处理的人口上算。** `recommend` 的判据 1 要求 28，而处理人口的上限是 27：
   33 道段落 gold 里只有 9 道走 `flat`、其中 3 道错。**上限低于门槛的判据是愿望，不是预测。**

**`selfConsistency` 不在上表，这是有意的。** §7.2 已把它证伪：k=3 时 75% 的题出现分歧，净 **+1 题**，
且误差是偏差而不是方差。它唯一可能翻案的场景是第 1 或第 2 步给出正向前提之后——即"读者的判断确实
是不稳的那一层"——在那之前重测它是重复上一轮已经付过钱的实验。

**第 1、2 步的读数不只看 Δ，还要过一遍逐题台账（第 54 步新增，第 56 步修正了它的口径）。** `tools/ledger.mjs`
把两份报告的 `discordantQuestions` 按题目 id 对齐，输出"并集 / 求和 / 重复计数 / 冲突题"四个数。**但那份
记录写的是"同一次运行内 feature 对 `reference-pipeline`"，不是"处理对跨运行的对照"** —— 于是两条增量共用
的是参考臂这个基线，跑出来 208/448 的重叠，而它不是路由隔离的结论（`silent` 233/52、`answer-line` 215/86，
两条都在 IE/KU/TR 上赢同一个参考臂）。**被注册的那条"买入应当不相交"因此问了一个工具不计算的量**，已在
§13.131 更正。跨运行那一对给出的才是注册想问的表：`answer-line` 对 `enumerated` 买入 **14**、卖出 **81**
（IE 1/13、MR 3/51、KU 6/1、TR 4/16），而且 **14 个买入全不在护栏瞄准的 IE 上**。

工具修法已登记（§13.131.3）：`--across arm=<report> --control=<report>` 给出跨运行对；同运行与跨运行混在
一张组合里按名拒绝；每个增量打印自己的对照身份。在那之前**两份文档都不作可加性声明**——两条增量对同一个
对照都是负的，没有东西可加。

**一条新的噪声地板，免费得来——而且它不是一条，是三条。** 第 54 步在归档上第一次运行台账时，两份
500 题报告的对照臂**同名**（`reference-pipeline`）、题集逐题相同，但正确数 218 对 217。台账报出
**4 道冲突题**，而冲突的定义（一份报告里"基线对、臂错"、另一份里"基线错、臂对"）在**两份基线完全
相同**时是不可能的，所以这 4 题是两份基线的分歧的**证明**；再用 218−217=+1 反推，另一个方向至少
还有 3 题，合计 **≥7/500 = 1.4%**，且这是下界（两臂都错的题把基线的判词藏在两个 null 后面）。这条路
量的是**逐题身份**。

同两批产物的 `baselineAggregate` 里还躺着**计数**地板，此前没人读过：温度未设那一臂的对照在四次重复
里是 219.0 / 221.8 / 224.0（极差 **5**），T=0 那一臂是 225.0 / 225.8 / 227.0（极差 **2**），而处理臂
分别是 415/421.5/431（极差 16）与 417/421/424（极差 7）。三件事：①温度把**对照**的抖动也减半了；
②**逐题地板大于任何计数地板**——对照可以换掉二十题而净差两题，所以"Δ 小于 7 题是噪声"和"对照只动
2 题"说的是不同的量，只引一个而不点明量名的是单位错误；③**对照的均值在两臂之间动了 4 题**
（221.8→225.8），处理只动半题，所以 §13.122 的"中心不动"只在**处理臂名册**上成立，不能读成"温度不
改变这一对的差"（那个差动了约 4.5 题）。T=0 下的**逐题**自一致率仍未测：四次重复只落一组
`discordantQuestions`（取第一跑的向量），要等一次同配置重复派发。

**三条排期硬约束（本轮修订）：** ①任何改变**证据集合**的增量（预算、池宽、重排、**分解**）在派发前必须先证明
该约束绑定，否则判为"杠杆未接上"而非"机制无效"。**这条在 §13.139 被自己用过一次，而且方向对、理由曾经错**：
`expand` 要往提示词里加证据，实测 42/42 道目标题的 `promptChars` 都在上限 95% 以上、最紧的一道只剩 735 字符
（不到两个 turn）→ 加不进 → 判"不适用"。**判断对，是因为用了"贴近上限的质量"这个统计量**；按 §13.118 原来的
"最大值低于上限"读，会得出"预算不绑定、加得进"的相反结论，然后在一次两小时的派发里学到同一件事。
**判定约束绑定的量是"有多少题贴在上限附近"，不是"最大是多少"**（468/500 ≥ 95%）。
②1、2、3、3c 都动**读者读什么/怎么写**，必须串行；它们
的不变量是"未触及路由逐字符复现对照窗口"，这条现在由 `evidence-ask-reach.test.ts` 的
`declared reach == measured reach` 自动守住，不再依赖人工比对。

1. **`13.163` 的五元组**：dataset｜variant｜答题模型｜裁判｜harness。上表只有 dataset 共享（500 题 LongMemEval），其余四项与除
   参考臂外的每一行都不同。**它是一张目标清单，不是排名。**
2. **等级在括号里**：A 可复现、B 单变量可解释、C 厂商自报且复现条件不足。
3. **同 harness 的那一行最硬**：MR 的 71.9%（96k）/ 73.55%（48k）与参考臂 82.6%（96k）/ 85.1–86.0%（48k）出**同一份 artifact、
   同一个 reader、同一个 judge**。这不是「我们落后竞品 10 点」，是「我们的记忆臂在多会话上比不带记忆的同一条管线差 10.7–12.4 点」。
4. **96k 那一列不是趋势，是一次交易**：TR +12 道、IE +1 道，KU −8 道、MR −2 道，净 +3 道，代价是 1.62 倍 prompt token。按
   `§9.127.2`，它在缓存修好之前不作为发货配置。

### 14.3 结论：cortex 是否 SOTA

**不是。** 三抽把总体钉在 **83.40%–85.60%**：低于 Raw-RAG 的 87.5%（B）与 agentmemory V4 的 96.2%（C），与 memoricai 的 85.8%（A）
最多持平、最差落后 2.4 点。按能力项，多会话（71.9%–73.55%）与时序（74.8%–84.3%）明确落后公开最强，前者**还落后自己同一 harness
的无记忆臂 10.7–12.4 点**——这一条比任何跨 harness 比较都严重，因为它的四个变量完全相同。

**要 SOTA 必须先做三件事**，顺序由「改动能被谁的读数验证」决定：

1. **把 MR 从 73.55% 抬到参考臂之上（≥ 103/121，同轮配对）**。这是唯一不需要外部对齐就能验证、且落后最多的一条。下一抽
   （`41159983913`）先把仪器修对：turn id 已改为推导（`§9.127.4`），因为此前每一轮 prompt 都带随机 UUID，四轮从来不是同一份请求。
2. **与竞品同 harness 对跑**：把 Raw-RAG（87.5%，B）与 MemCog（92.5%，C）的管线搬进 Runner，用我们的 reader 与 judge 跑
   **双方数据集**，「我们比它低 N 点」才成为可复现的差而不是两个自报数的差。
3. **在 2 成立之后**才谈超越。

### 14.4 噪声底与「重复」，以及本轮推翻的一个前提

`41039779987` 与 `41090564131` 是**同一负载的两次派发**，第 1 轮分别读出 85.60% 与 83.40%（−2.20 点、11 道题），而三次派发的
证据在 artifact 能记的维度上相同（500/500 相同 turn 序列、相同 `evidenceChars`、相同 `promptChars`），MR 第 1 轮两次都是 89/121。
由此确立两条规则：

- **任何小于 2.2 点的头条增量，在第二次同负载派发复核之前都只是一次抽样。** `+2.60`／`+0.80` 这一对就是这样：第二抽读出 `+0.00`。
- **准确率判据必须同轮配对**：拿一次运行比一份归档运行，量到的是两次抽样的差，不是治疗的效应。

**而本轮把这条带子的成因找到了，至少一部分。** `41144910162` 的证人说：四轮 prompt 各 94,674 字节，只共享 **14** 字节；
把 UUID 剥掉后四份文本逐字节相同。原因是 `createMemory` 把 turn id 默认成 `crypto.randomUUID()`，**每次准入都重新抽一次**，
而 sourced 渲染把 id 写进了 prompt。于是：

- 四轮从来不是同一份请求 ⇒ 前缀缓存在 14 字节之后再无可用 ⇒ 8.70% 的命中份额是这个缺陷，不是 provider；
- `promptVariants == 4` 是同一件事的计数版本；
- 准入不幂等：同一 turn 两次准入产生两个身份。

修复是把 id 改成「算」出来的（四条雪崩 FNV-1a 流，UUID 形状，版本位 8），并把 `prompt-determinism.test.ts` 从 3 条扩到 5 条
（sourced 渲染的 flat 与 multi-session 路由，四轮必须一份 prompt）。`41159983913` 就是**先登记后执行**的那一抽：它测六条预测，
包括缓存份额 ≥60%、计费成本 ≤ 上一抽的 0.7 倍、MR 四轮极差 ≤2 道。若最后一条成立，`runs: 4` 从此不再是方差仪器，
而是一次确定性检查——那会把「噪声底」这件事变成「读者方差」的单独问题。
