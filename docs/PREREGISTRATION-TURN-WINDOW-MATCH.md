# 预登记：`turnWindow: 'match'` 在注册臂上的第一次 500 题读数（第 133 轮）

> 本文件写在**派发之前**。它登记的是本仓已经实现、已经单元测试、并且**已经在 200 题筛选臂上
> 跑过三格**的机制；缺的是它在**当前注册配置（500 题 × 4 重复）**上的一次读数。
> 派发成本按上一轮实测登记为 **≈14.26 CNY / ≈120 分钟**。

## 1. 为什么是它

三件事在同一轮里指向同一处：

1. **证据侧的切点与错误同向。** 用 `44317789307` 的渲染后提示（`ablation.featurePromptTexts`）逐题核对
   金标轮次：`MR` **恒错 13 题**的金标轮次有 **57 / 230 = 24.8%** 被截在恰好 400 字符处（平均 4.38 条/题，
   **13/13 题都有**），而 **全对 95 题**只有 **144 / 1,382 = 10.4%**（1.52 条/题）。
   无帽的 `IE` 是 **0 / 1,709**，`KU` 是 1 / 1,688。
2. **读第二遍这一族已经关闭。** `tally` −9.5、`spec` −7.8、`audit` −6.10、`selfConsistency` `MR` 86.2
   （判据 89）、`item-ids` −2。剩下的只能是**第一次读**的改进。
3. **窗口这一格的四轮同向信号是所有记录里最强的。** `S10` 三格（`04` §104）：
   纯窗口 **+7.25**（+7, +9, +5, +8，**四轮全正**）、纯标记 **−4.75**（−1, −4, −6, −8，**四轮全负**）、
   捆绑 **+2.50**，且 −4.75 + 7.25 = +2.50 精确可加。

第 3 条的三个数字来自 **200 题筛选臂、基线 86.75%**，与今天注册臂的 500 题、91.15% 不是同一代配置。
本文件要买的就是这一格在注册臂上的读数。

## 2. 机制的一句话形状

`turnWindow: 'match'` 把 `maxTurnChars` 花在**问题与轮次词面重合最密的位置周围**，而不是从轮次开头花：
锚前留 `LEAD_SHARE = 0.25` 的预算（英文里操作数常在谓语之前），两端切点吸附到词边界，并用 `…` 标记。
数据行 `[date] role:` 先被剥离再进窗口（`TR` 的答案是日期，切掉日历行比它修的问题更糟）。

命令面：`cortex_memory_max_turn_chars = 400::match`（窗口强制 `ellipsis`，语法见 `readTurnCap`）。

### 2.1 reach

`relevanceUnits` 与 `turnWindow` 都落在 `buildSessionPrompt` 上，因此这次派发**同时触及
`multi-session`（`MR`）与 `temporal`（`TR`）**，两条都是受帽路由。
`IE` / `KU` / `ABS` 不经过它，所以它们是**内部对照**。

## 3. 判据（读数之前写死）

比较对象是 **`44017278305`（`S16`，当前注册配置，500×4）**，同一语料
（`datasetFingerprint` `sha256:d6f21ea9…`）。这是**跨派发**配对，因此在总体准确率上的分辨力受
`§11.13` 的 0.70 点地板约束；判据因此写在**能力级**并配题级符号检验。

| # | 判据 | 阈值 | 失败的含义 |
| --- | --- | --- | --- |
| **B1** | 机制确实执行 | 两侧 `promptVariants == 1` 的题里，`MR` + `TR` 的 `promptDigest` **全部变化** | 机制没跑 → 运行作废 |
| **B2** | reach 越界 | 稳定子集上 `IE`/`KU`/`ABS` **逐题不变** | 越界 → 运行作废，先修实现 |
| **B3** | **机制的直接效应** | `MR` 金标轮次的「被切率」从 **13.4%** 降到 **< 5%** | 切点没移动 → 窗口没生效，不许读准确率 |
| **B4** | `MR` 准确率 | 均值 **≥ 105.25**（+4 题）且题级 `up − down ≥ +4` | 效应在地板下或方向相反 → 不切换 |
| **B5** | `TR` 不劣 | 均值 ≥ **118.25**（−2 题以内） | 窗口在日期型问题上伤到日历行 → 不切换 |
| **B6** | 成本 | token/题 ≤ **7,822**（基线 × 1.05） | 用 5% 以上的 token 买准确率 → 按成本轴重新登记 |

**B3 是本文件与 `S10` 的区别所在。** `S10` 判的是准确率；本文件要求先证明**切点真的移到了操作数上**
（被切率是机制的直接输出），再读准确率。一个把切点移了却没有提高准确率的读数，意义与
「切点没移、准确率也没动」完全不同，而后者是 `S10` 的读数无法区分的。

## 4. 三个可否证的预测（写在派发之前）

> **P1**：若效应真实，收益应**集中在 13 道恒错题**上（它们 13/13 都有被切的金标轮次），而不是均匀分布在
> 108 道其余题上。若均匀分布，有效但不是因为「切点回到操作数」——解释要改写，而机制保留与否要重判。

> **P2**：若 B3 通过而 B4 失败，则**「证据可读性」这条线的上限低于被切率所暗示的**：24.8% 的金标轮次
> 被切，而把它们全部恢复也不足以让 13 道题答对，说明读者对「轮次被切」本身不敏感。
> 这会把下一步推到**轮次粒度**（一条长轮次是否该被拆成多条），而不是窗口。

> **P3**：`TR` 的方向应与 `MR` 同号。两条路由用同一个渲染器、同一个问题，若 `TR` 反向，则窗口在
> 「答案是日期」的问题上有系统性副作用（例如把日期句挤出窗口），这本身是一个可修的实现缺陷。

## 5. 本轮不声称的东西

- **不声称窗口有效。** 它在 200 题筛选臂上 +7.25（四轮同向），在本配置上**零读数**。
- **不声称 `S10` 的 −4.75（标记）与 +7.25（窗口）可加。** 那三个点是三点，交互项未测；
  本文件只跑 C 格，不跑被语法禁止的第四格。
- **不声称能把 `MR` 拉到 MemCog 的 92.48%。** 105.25 是 +4 题，对 `MR` 是 +3.3 点，仍差 4.9 点。
