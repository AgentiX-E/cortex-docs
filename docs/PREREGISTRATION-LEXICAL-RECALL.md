# 预登记：词法零召回的离线修复（`I17`）

> 状态：**已登记，未执行**。本文件在派发之前写死判据、候选与拒绝条件，理由与本项目其他预登记文件一致——一个先看到数字再决定判据的实验，测的是实验者的偏好。
>
> 前置：`docs/ANALYSIS-LEXICAL-ZERO-RECALL.md`（读数来源与三条判据）、`cortex` 的 `S14` 证据（`cortex-docs/evidence/longmemeval/lexical-index.json`）。

## 1. 问题

`S14` 证明：词法索引在 500 题里 **21 题一条金轮都没送到**（其中 3 题是 `ABS`，且因「没送到」而答对），向量臂 **0 题**。零召回桶的正确率 19.0%，非零召回 82.9% 起。

所以问题不是「词法检索好不好」，而是：**在登记房间（各路由 24,000 / 48,460 / 48,000 字符）下，能不能把零召回题数从 18 降下来，而不把 `1–33%` 桶撑大、也不碰 `ABS`。**

## 2. 为什么这一轮不需要模型

金轮是**文本**，不是标签：`questions[].goldOverlap.goldTurns` 里逐条存着。检索是否命中金轮，只取决于倒排、打分、融合与房间——这四件全是确定性代码。因此整个第一段是 **0 CNY、0 派发、0 判官** 的离线读数。

确认性派发（500×4，≈14.26 CNY）只在**离线读数改善且三条判据同时成立**之后做一次，用途是回答「召回改善有没有变成正确率」。

## 3. 仪器（必须先自证）

新增 `packages/cortex-memory/bench/lexical-recall.ts` + `.github/workflows/lexical-recall.yml`（**仅 `workflow_dispatch`，不进任何自动触发**）。

| 项 | 定义 |
| --- | --- |
| 语料 | LongMemEval-S 的 500 个 haystack，与 `benchmark-cortex-memory.yml` 用同一下载步骤与同一 fingerprint |
| 金轮 | 取自 `S14` artifact 的 `goldTurns` 文本，逐题按**全文相等**匹配（不做相似度近似） |
| 度量 | 每题的 `delivered / total` 与桶分布，与 `tools/gold-recall-census.py` 同一分桶规则 |
| 交付口径 | 与产品同一路径：`SearchIndex` → 融合 → 房间裁剪 → 逐轮渲染；**不调用 reader、不调用 judge、不调用 embedder** |
| 输出 | 一个 JSON：逐题 `delivered/total`、桶表、零召回题号及能力，附配置指纹 |

### 3.1 校准闸门（不过就整轮作废）

在**登记配置**下，仪器必须复现 **零召回 21 题**（`IE 17 / ABS 3 / TR 1`），且逐题 `total` 与 artifact 的 `goldDelivered.length` 完全相同。

- 复现不出来 ⇒ 仪器与产品路径不是同一条，后面所有候选的比较都无意义；
- 允许的偏差只有一种：**`goldOverlap` 的金轮文本在 haystack 里出现多次**导致匹配歧义，此时报告歧义题数并要求人工裁定，**不得**用「近似匹配」把差异抹平。

这一段是整轮最重要的部分。本项目已经付过三次「数字是真的，但挂在了没有产生它的配置名下」的钱（§26.4、§27.2），校准闸门是第四次之前的那道门。

## 9. 执行记录：仪器已实现（第 127 轮），校准待派发

本节在派发**之前**写下仪器的形态，因为 §3 只说了「必须先自证」，没说自证的做法可以怎么变。做了三处**收窄**，每处都让判据更硬而不是更软。

### 9.1 仪器不是新写的检索器，是产品加常量

§3 把仪器描述成 `SearchIndex → 融合 → 房间裁剪 → 逐轮渲染`。那样实现等于把产品的组装逻辑写第二遍，而第二遍测到的第一件东西是两遍之间的漂移。改为：**产品原样跑**，读者与判官换成常量（`CORTEX_ARM_OFFLINE=1`）。

| 组件 | 仪器里的形态 |
| --- | --- |
| 检索 / 融合 / 房间 / 截断 / 渲染 | 出厂代码（`CortexMemory`） |
| 读者 | `"offline instrument"` |
| 判官 | `incorrect` |
| 嵌入 | 不构造（`indexEmbedding: none`） |

交付口径因此与 §3 的「不调用 reader、不调用 judge、不调用 embedder」一致，而「与产品同一路径」从**承诺**变成**同一份代码**。

### 9.2 校准闸门的判据从「零召回 21 题」加严到逐题三元组

§3.1 要求复现零召回 21 题且逐题 `total` 相同。实际实现比对的是**每题三个字段**：

| 字段 | 不一致意味着 |
| --- | --- |
| `total` | 两次读的是同一 id 下的不同实例（数据集问题，不是打分问题） |
| `carried` | 交付集不同 —— 后面每个候选都是拿另一个基线在比 |
| `deliveredDigest` | 计数相同而文本不同：另一段语料、另一张房间、或渲染动了 |

加入 `deliveredDigest` 的理由是 §3.1 那句话的反面：只比 `carried` 时，一个「恰好也送到同样多金轮」的不同交付会通过。基准摘要由 `--write-reference` 从 `S14` artifact（run `43829744532`）折出，桶分布 21 / 129 / 114 / 236 与 `ANALYSIS-LEXICAL-ZERO-RECALL.md` §2.1 逐格相同——这是摘要口径的自证。

### 9.3 三条新断言，位置与 §3.1 同类

| 断言 | 位置 | 抓的形状 |
| --- | --- | --- |
| `assertOfflineInstrumentConfiguration` | 读语料之前 | 排名不在产品侧，或为动不了的通道付钱 |
| `assertOfflineInstrumentReached` | 写 artifact 之后 | 常量回复触发二次检索（`indexes != 题数×轮数`） |
| `lexical-recall-calibrate.py` | 读 artifact 时 | 仪器不是那条路径（逐题三元组） |

产品侧另有三条性质测试：证据与回复无关（两种回复 → `lastRetrievedContext()` 逐字节相同）、回复解析成答案（不触发 `reviewBareDecline`）、每问一次索引。

### 9.4 成本不变，但单位变了

§7 的离线段仍是 0 CNY；确认性派发仍是 1 × 14.26 CNY。变的是**候选之间**的比较：从「一次派发试一个」变成「一次离线跑完、再挑一个进确认性派发」。§6 的否证条款因此更容易被执行——六个候选全不过判据 1 的结论，现在一次运行就能拿到，而不是六次。

## 10. 候选登记（第 128 轮）：IDF，与房间下限

§4 的六个候选，在第 128 轮之前一直是一个清单；`ANALYSIS-LEXICAL-ZERO-RECALL.md` §7 把它收缩成一个，因为零召回的 21 题被拆成了三个群体，而**19 题的形状只对得上词项特异性**：金轮有分（中位差 0.212 ＝ 一个词的平坦覆盖份额），只是被常见词挤掉。

### 10.1 候选一：`lexicalWeighting: 'idf'`

| 项 | 值 |
| --- | --- |
| 公式 | `ln(1 + (N − df + 0.5) / (df + 0.5))`（Robertson/Sparck-Jones，Lucene 用的那一支） |
| 语料 | 索引自己持有的轮次（`#turns`）与倒排（`#postings`），**不引入任何新调用** |
| 新增成本 | 0（`embedCalls` / `terms` 不变；纯词法部署仍然不碰 provider） |
| 默认 | `flat`，即所有归档读数的口径 |
| 拒绝 | 未知取值抛错而不是回落 `flat`（回落会让「跑了但没变」被当成「机制无效」） |

**先被否掉的写法**：`ln(1 + N / (1 + df))`。它在 N=10 的小语料上把稀有词与常见词只分出 2.4 倍，不足以压过三个命中词；同一夹具上 Lucene 形式分出 13 倍。这条写进 `SearchIndexOptions.lexicalWeighting` 的注释里，因为「为什么不是那个更简单的式子」是下一个人会问的第一个问题。

### 10.2 候选二（产品修复，不是调参）：房间下限

> **三次落笔，第三次才是读数。** 第一版归因（一条超长轮吃掉了整个房间）当时没有候选支撑；第二版把它撤回，理由是「承载它的候选运行 `44231317722` 改了 0/500 次交付」——**这一撤是错的**；第三版发现那条日志只说明**仪器看不见这条分支的输出**（`carried` 数金轮条数、`deliveredDigest` 哈希轮次文本，两者都是整轮形状，裁剪交付在两项上都不变，于是「裁了一段」与「什么都没交付」逐字节相同）。补上 `deliveredChars`（= `promptChars`）之后，同一个闸门运行 `44239553110` 直接读出 **`b86304ba` 交付 0 → 23,503 字符**，也就是房间在扣掉 497 字符指令与问题之后的全部余量。归档对该题的供给是 `evidenceTurns 456` / `evidenceChars 477,543`——房间的二十倍——所以最大可装前缀确实是空的。**这条修法现在是实测的，不是不变式。**

`b86304ba` 交付了 **0 条**证据。当时的解释是「456 条候选、`flat` 路由、24,000 字符房间，而排在第一的助手轮比整个房间还长」，前缀规则于是返回空前缀，读者拿到的提示词说「没有证据」。

修法沿用字符裁剪路径已有的规则：**整轮装不下时，房间买下排名第一的那一轮并裁剪它**。`carried` 仍只计整轮（因此为空），`evidenceChars` 报告真正交付的字符数——这两个字段本来就是分开的，读者能分辨「交付了一段」与「交付了零」。

**这条不变式留下来，但依据换成了它自己的局部性质**：装不下一整轮的房间仍然可以买下最好那一轮的一部分，「太长读不了」不等于「没有证据」。它不再声称修好了 `b86304ba`。

| --- | --- | --- | --- |
| 1 | 零召回 **21 → 更小** | `21 → 11`，走掉 10、**进来 0** | **通过** |
| 2 | `1–33%` 桶不得暴涨 | `129 → 119`；`34–66%` 114 → 123、`67–100%` 236 → 247 | **通过**（该桶缩小，其余三桶全部变大） |

### 10.4 一个必须写下来的风险

IDF 让「稀有词」变贵，而稀有词也可能是噪声（拼写错误、一次性的专有名词）。19 题组里最弱的一题差距只有 0.060，这类题可能因为一个偶然的稀有词而**反向**移动。判据 2 是这条风险的唯一保险，因此它的阈值是「不得暴涨」而不是「不得变化」。

**这条风险在第 128 轮部分兑现了**：17 题倒退，其中两题是 `_abs`（`gpt4_372c3eed_abs` 5 → 3、`gpt4_c27434e8_abs` 13 → 10），最重的一题 `0862e8bf` 从 12 掉到 5。判据 2 之所以仍然通过，是因为它只问「`1–33%` 桶有没有暴涨」，而倒退集中在 `67–100%` 与 `34–66%` 这两个高位桶里——**判据 2 不是为这种倒测量身写的，这是它这一轮暴露出的边界**。要不要在下一轮加一条「`_abs` 子集不得倒退」的判据，须在派发前登记，不能事后按读数补。

### 10.5 仪器侧的两处改动

1. `--candidate <label>`：候选是**预期会不同**的报告，闸门因此换成「差值读数 + 配置逐字段 diff」，并且**永不打印** `IS the path` 那句相等判定。
2. reference 记录整份 `memoryArmConfig`（去掉 census 字段），于是每次候选都会自己打印它动了哪几个字段——一个同时动了两件事的候选，在它自己的日志里就能看见。

两处都按登记的形态工作了：`room-floor` 那一行打出的是 `unchanged -- this candidate's difference is in code, not in a setting`，`idf` 那一行只名出一个字段 `lexicalWeighting: "flat" -> "idf"`。三次离线代入（embedding / judge / reader）在两次运行里都会列出来，它们不是 arm 字段，是仪器自己的替身。

### 10.6 第二个候选的三次读法，与它的实测读数

同一个候选、同一份语料，读出过三种结论，而只有第三种有仪器支撑：

| 落笔 | 结论 | 依据 | 判定 |
| --- | --- | --- | --- |
| 第一次 | 一条超长轮吃掉房间，裁剪修好它 | 逐题重算（0 CNY） | 机制合理但**当时无候选** |
| 第二次 | 分支从不触发，`b86304ba` 原因不明 | `44231317722` 打印 `0` 题交付文本变动 | **错**：仪器量的是整轮账本 |
| 第三次 | 分支触发，交付 `0 → 23,503` 字符 | `44239553110`（补了 `deliveredChars` 后） | **实测** |

运行 `44239553110` 是**不带候选**的闸门运行，所以它按设计**失败**了：基准记录的是已派发运行的交付，不能为了迎合新代码而改写，于是这条变动以 `expectedMoved` 声明进基准（写明是哪一节造成的），声明会被双向检查——若裁剪哪天不再触发，闸门会以 `still_moved` 失败。

两处必须写下来的边界：①`carried` 与 `zero-recall` 对这次修复**永久看不见**（两者都数金轮整轮，裁剪交付 0 条），该运行的零召回仍是 `21 → 21`；②23,503 字符进入提示词**不等于**读者用了它，准确率仍要靠 500×4 确认性派发（≈14.26 CNY，仍被余额阻塞）。

## 11. 派发前的两条登记（第 129 轮）：`ABS` 子集判据，与候选的自陈轴

这一节是在**付费派发之前**写的，顺序本身就是纪律的一部分：判据必须在读数之前登记，否则就是按读数补判据。

### 11.1 为什么要一条子集判据：+190 的总账下面，`ABS` 涨了 29

`idf` 候选（run `44231332168`）的两个总账数字是 `4,299 → 4,489` 与零召回 `21 → 11`。本轮把 `capability` 拆开印出来，同一份产物立刻给出第四个数：

```

```

`ABS` 是 30 道**本应拒答**的题，基准已经答对 **29.25/30**。对其余四类能力，「多交付一条金轮」是目标；对 `ABS` 不是——让读者看到更多证据，正是让它在应该拒答时开口的原因。**同一个「+190」在两类能力上符号相反**，而总量报表把它们加在了一起。

值得同时记下的是：子集总量涨 29，但逐题看有两题在跌（`gpt4_372c3eed_abs` 5→3、`gpt4_c27434e8_abs` 13→10）。子集账本与逐题账本得出相反印象，这正是两者都要打印的理由。

### 11.2 判据（登记，未读）

在 500×4 确认性派发里，`ABS` 的 30 道题按**配对**方式与基准逐题比较：

| 项 | 定义 |
| --- | --- |
| `d_worse` | 基准答对、`idf` 答错的 `ABS` 题数 |
| `d_better` | 基准答错、`idf` 答对的 `ABS` 题数 |
| **判据 4** | **`d_worse ≤ d_better`**；否则 `idf` 被否决，**无论总体提升多大** |
| 附带报告 | 精确二项检验的 p（`d_worse` 侧单尾），以及 `ABS` 的均值是否仍 ≥ 29.25/30 |

选配对计数而不是「不得下降超过 N 题」，是为了不引入一个需要论证的 N：判据本身没有可调参数，它的功效由 30 道题决定，而它的方向与 §10.4 登记的风险（稀有词可能是噪声）完全一致——错的词恰恰出现在这类题上。

### 11.3 明确**不**是判据的东西

`ABS` 的金轮命中数**不是**判据。它这一轮涨了 29，而涨的理由可能是错的理由：该子集要的是拒答，金轮越多，越可能诱导作答。把它当判据会让「更容易开口」被判成改进。这条写在这里，是因为下一轮读到 `ABS 128->157` 的人一定会先冒出「涨了 29，稳了」的念头。

### 11.4 候选必须自陈它要动哪条轴

仪器侧新增 `--expects-change`（`cortex` `§13.381`）：候选在派发时声明它预期移动的轴（`turns` / `chars` / 两者 / `none` / `any`），工具双向比对——**动了没声明的轴判失败，声明了没动的轴也判失败**。`idf` 第一次按 `--expects-change turns` 读直接失败：

```
predicts         : turns
observed         : turns,chars
```

这不是缺陷而是机制事实：重新定价词项会重排轮次，交付长度因此在 **235/500** 题上变化（其中 1 题是裁剪：轮次账本不动、长度动）。`idf` 的正确声明是 `turns,chars`。**从此任何候选的日志第一屏就带着它自己的预期**，读数字之前先知道它想动什么。

### 11.6 判据 3/4 怎么算（第 130 轮，派发途中补齐，读数仍未到达）

判据 3/4 登记时说的是「配对」「逐题」，而一次派发给每个题**四次**重复。四次重复怎么塌成一个
「这题答对了吗」，是一个**必须在读数之前**定下的规则：事后从三种塌法里挑一种，等于挑了一个方向。

塌法只有一条，写在代码里而不是写在这一节里：**一道题在四轮里答对的次数**就是它的读数，
`up` 是次数上升的题，`down` 是次数下降的题，次数相同（哪怕对错的轮次换了）的题**两个表都不进**。
这条语义在 `cortex` 的 `arm-verdict.ts` 里既有注释也有测试（`counts a reshuffle as neither a
conversion nor a regression at question level`），本轮只是把判据挂上去，不是新定义。

于是：

| 判据 | 等价形式 | 谁来判 |
| --- | --- | --- |
| 4 | `d_worse ≤ d_better` ⇔ `up − down ≥ 0` | `node tools/arm-verdict.mjs --control <flat> --arm <idf> --capability ABS --bar net=0` |
| 3 | `ABS` 均值 ≥ 29.25/30 | 同一条命令打印的 `passes / cells` 行（`117/120` 起） |

`--bar net=` 是本轮新加的子句，理由是**判据必须是工具判的**：旧的 `--bar` 只有两条子句
（`conversions` 下限、`falsifierLoss` 上限），都不表达「净损失不为正」，而要读者去比两个打印出来的
整数，就是把一次判定留在人手里——本仓库为此吃过两次亏（`S1` 连读三轮 83.45%、一条门槛把 62 题
写成 65 题）。子句在 `arm-verdict.ts` 里有四条新测试，其中一条专门钉住「格点变好、题数变坏」的
情形：`cells` 的符号与 `questions` 的符号可以相反，判据登记在题上，就必须读数在题上。

**空子句不读作满足**：没给 `net` 时结果是 `null` 而不是 `true`，两子句的旧判词因此逐字不变
（`MEASURE-CONFLICT-SURFACING.md` §5 记的那一行仍是原来那一行）。

### 11.7 判据 3/4 的组合与该做什么（派发前写死）

§11.2 只写了判据 4 失败时「`idf` 被否决，无论总体提升多大」，**没有写判据 3 失败时做什么**。
一条没有事先写死后果的判据，等于把决定留给读到数字的那个人。补在这里：

| 判据 3（`ABS` 均值 ≥ 29.25） | 判据 4（`up ≥ down`） | 动作 |
| --- | --- | --- |
| 通过 | 通过 | `idf` 被**接受为候选默认**：另起一轮做默认值切换（`flat → idf`）、回填 `S14`/`C1`、更新手册与宣告表 |
| 通过 | 失败 | **否决**。判据 4 是守门判据：它在 `ABS` 上读到净损失，而 `ABS` 是唯一一类「证据越多越糟」的题 |
| 失败 | 通过 | **不切换**。记为「总体 +、`ABS` 有代价」，`idf` 留在候选位；下一轮若要救它，必须另立一条**只作用于非 `ABS` 路线**的机制并重新登记，不得把这次读数改写为通过 |
| 失败 | 失败 | **否决**，写 `RETRACTIONS.md`，`flat` 保持默认 |

三种「不切换」的形态**不同**，写清楚是因为下一轮读到同一组数字的人会想把它们合并成一句
「`idf` 没通过」——而「净损失」与「均值略降」是两件不同的事，前者说方向错了，后者说代价真实但有限。

### 11.8 配对里的「基准」是哪一份产物（派发途中定，仍先于读数）

配对比较只有在两端的**代码与配置**都是同一件事时才成立，而 `idf` 是跨派发的比较，所以「基准」必须按
规则指定，不能按哪一份好看指定：

> **基准 = 当前注册臂的产物**，即产出 91.25% / 7,448 token 那一行的那次运行 `44017278305`（`S16`，
> `relevanceSignal=self-index`、`indexEmbedding=injected`、`lexicalWeighting` 字段尚不存在＝`flat`）。
> 产物已取回并在本地核对：500 题 / 4 轮，`featureCorrectByRun` 每轮 `[456, 454, 458, 457]`，
> 均值 **456.25 = 91.25%**，`ABS` **120/120 格 = 30.00/30**。

这一段里有一个必须记下来的更正：`§11.1` 写的「基准已经答对 **29.25/30**」来自**另一份产物**，而按上面
这条规则选出的基准在 `ABS` 上是**满分**。两个数字都属于基准臂，差别在轮次与配置，而不是在能力。
后果有两条，都写在这里以免下一轮重新推理：

1. **判据 3 比它读起来更严**：`30/30` 没有余量，任何一格掉下来都算移动；判据 3 的失败因此不等于
   「显著变差」，而等于「在满分处出现了一次移动」——所以 §11.7 里它对应的动作是**不切换**，而不是
   「否决」（否决留给判据 4）。
2. **判据 4 的分母很小**：30 道题的天花板意味着 `up` 几乎没有空间（基准已经全对），`down` 每加一题
   都必须由另一题的不可能来平衡——在满分子集上 `d_better` 恒为 0，判据 4 于是退化为
   **「`ABS` 不得有任何净损失」**。这不是笔误，是天花板子集的正确读法，也解释了为什么这个判据
   必须与总体提升分开记：总体 +190 可以同时与「`ABS` 净损失 ≥1」成立。

可信」的东西。两份离线产物（基准 `44239553110` 的参考账本、候选 `44231332168`）逐题对齐后：

| --- | ---: | ---: | ---: |
| 交付的金轮总数 | 128 | **157** | **+29** |
| 交付字符总数 | 665,269 | 662,289 | −0.45% |
| 金轮**变多**的题 | — | — | **16** |
| 金轮**变少**的题 | — | — | 3 |
| 金轮不变的题 | — | — | 11 |

两个数字决定了这一节的预测：

1. **字符几乎不动，内容动了。** 交付长度只差 0.45%，所以 `ABS` 上的风险不来自「房间装得更多」，

2. **`+29` 集中在 16 道题上**（最大三例 `eeda8a6d_abs` 12→16、`80ec1f4f_abs` 7→10、

| --- | --- | --- |

给检索类候选定价」这条省钱路线就有了一次反证；若相交，这条路线第一次拿到外部效度，而它正是本项目
把 14.26 CNY 的派发压到每轮最多一次的依据。

### 11.10 判据 3 的门槛是 30.00，不是 29.25（同一个门槛的两处写法，读数前统一）

登记里判据 3 出现了两个数字，必须现在统一，因为它们的差别恰好决定一次失败是否算失败：

| 出处 | 写法 |
| --- | --- |
| `§11.5` 判据表 | 「`ABS` **30/30 不动**」 |
| `§11.2` 附带报告 | 「`ABS` 的均值是否仍 **≥ 29.25**/30」 |

`29.25` 不是门槛，它是**对基准的描述**，而且描述的是更早的那份产物（`§11.8`）。注册臂在 `ABS`
上的实测是 **120/120**，所以「不动」的正确读法是 **30.00**。若按 `29.25` 判，则掉两格（29.50）仍算
「通过」——一条在满分处允许两格退步的判据，比它自己那句话（「不动」）更松，而更松的判据与更严的
判据一样，都不能在读数之后才定下来。**因此：判据 3 = `ABS` 均值 30.00，零容差。**

这带来一个必须一起写下的推论，它把 §11.7 的四行表压缩成两行：

> 在**天花板子集**上（基准全对），`d_better ≡ 0`、`up ≡ 0`，于是
> 判据 4 ⇔ `down = 0` ⇔ 每一格都保住 ⇔ 判据 3。**两条判据在 `ABS` 上是同一个检验。**

所以 §11.7 的第 2、3 行（一过一败）在 `ABS` 上**不可达**，不是因为纪律，而是因为算术：一侧已经在
天花板，另一侧只能持平或下降。这条写在这里是为了避免下一轮把「两条判据都过」误读成「两条独立证据
都支持 `idf`」——它是一个证据说了两次。要两条独立证据，需要换一个非天花板子集（`MR` 或 `KU`），
那是另一次登记。

### 11.11 一个削弱 P1 机制的先验，记在读数之前

`§11.9` 的 P1 建立在「`ABS` 上金轮从 128 涨到 157，所以更可能开口」之上。取注册臂自己的产物
（`44017278305`）逐题对齐后，这个机制**弱得比写 P1 时以为的更明显**：

| 量（`ABS` 30 题） | 离线 `flat` | 离线 `idf` | 注册臂（向量通道开，`flat`） |
| --- | ---: | ---: | ---: |
| 交付字符 | 665,269 | 662,289 | **666,899**（+0.25%） |
| 交付金轮 | 128 | 157 | **239** |

注册臂在 `ABS` 上交付的金轮是离线仪器的 **1.87 倍**，而它**仍然 30/30 全拒**。也就是说
「金轮越多越爱开口」在这条流水线上**不是单调的**：239 条没有让它开口，那么 157 条更不该。P1 因此
**保留**（预测不因不利证据而撤，那正是预测的意义），但它现在是一条**预期会被否证的预测**——
若 `ABS` 守住 30/30，得到的结论不是「`idf` 无害」，而是「金轮计数不支配弃权，`§11.1` 的担心
在这条流水线上被否证」。

两条一起记的理由：`§11.1` 把 `ABS 128->157` 当作**风险信号**，而注册臂自己的数字说明同一类信号在
更大的量级上并没有兑现。**风险信号不等于风险**——这条区分写在这里，因为下一轮若 `ABS` 退步，
最容易被引用的是 `+29`，而最应该先看的是这 239。

**一句话：88 条更多金轮、280 条重新定价的交付，换来 0.15 个点的准确率下降。** 四条能力里一条涨
（`IE +2`）、三条跌、`ABS` 不动，净变化落在一个噪声带内（`p = 0.83`）。

### 11.13 交叉派发的分辨力：这一轮自己量出来的地板是 0.7 个点

这次派发的**参考管线一侧完全没有被处理**（`lexicalWeighting` 只接进 `self-index`，
`bench-memory-arm.ts:3120`），而它从 **882 格** 变成 **896 格**：

| 侧 | `S16`（11-17 06:23Z） | `44259394957`（11-18 09:36Z） | 差 |
| --- | ---: | ---: | ---: |
| 参考管线（无处理） | 882 = 88.20% | 896 = 89.60% | **+14 格 = +0.70 点** |
| 产品臂 | 1,825 = 91.25% | 1,822 = 91.10% | −3 格 = −0.15 点 |

也就是说：**同一个不变的臂，隔 27 小时，自己动了 0.70 个点**。而这次要测的效应是 0.15 个点。
若把参考管线的漂移当作环境的漂移、用差中差估计处理效应，得到
`(−3) − (+14) = −17 格 = −0.85 点`（假设两条流水线同向漂移，这个假设本身无法在本次数据里检验）。

两种读法方向一致（−0.15 或 −0.85），但**精度都不足以支持「`idf` 有用」**，而这正是结论：
**跨派发配对的分辨力地板（0.7 点量级）高于这次要测的效应，设计上就测不出来。**
`§14.94.3` 早就写过「时间漂移 1.7–2.1 点，大于这个臂能找的大多数效应」，这一轮把它从文献值变成了
本仓自己的实测值。要测这一档效应，两个格子必须在**同一个 job 里**跑（同一 job 的配对能抵掉漂移）——
这是下一轮的设计约束，不是这一轮的补救。

### 11.14 判据 3/4 通过，而它们通过的含义比字面小得多

| 判据 | 读数 | 状态 |
| --- | --- | --- |
| 3（`ABS` 均值 30.00，零容差） | 120/120 | ✅ |
| 4（`up ≥ down`，`--bar net=0`） | `net up 0 - down 0 = 0 met=true` → **ACCEPTED** | ✅ |
| P1（`ABS` 不会停在 30.00） | 停在 30.00 | ❌ **被否证** |
| P2（退步必落在金轮变多的 16 题） | 无退步，空真 | ⚪ 未被检验 |
| P3（判据 3 与 4 同向） | 同向（两者都过） | ✅ |

P1 被否证这件事本身有信息：`§11.11` 已经量到注册臂在 `ABS` 上交付 239 条金轮仍全拒，现在 `idf`
在**同一批题上再交付更多**也没有让它开口。**「金轮数量不支配弃权」这条从先验升为实测。**

判据 3/4 通过，但**它们能通过是因为它们测的是一个满分子集**：`d_better ≡ 0`，所以「无净损失」由
任何未变的臂自动满足。**判据通过说明「没有伤害」，不说明「有价值」。** `§11.7` 第 1 行写着
「通过 → 接受为候选默认」，这一行**不执行**，理由写在下一节，并且承认它是 `§11.7` 写法的缺陷。

### 11.15 决定：`flat` 保持默认，`idf` 被拒绝作为默认值

`§11.7` 第 1 行把两条判据写成**准入条件**，而它们实际是**否决条件**。一次否决没有触发，不等于
被否决的事情成立。这一轮把两种东西分开：

| 命题 | 谁登记 | 读数 | 结论 |
| --- | --- | --- | --- |
| 「`idf` 不伤害 `ABS`」 | §11.2 判据 3/4 | 通过 | 成立 |
| 「`idf` 提高准确率」 | 这次派发本身要回答的问题 | **−0.15 点**（`p = 0.83`），差中差 −0.85 | **不成立** |

第二条不需要新判据：它就是这条臂存在的理由。**否决通过 + 主张不成立 → 不切换**，`flat` 保持默认，
`idf` 保留为可选项（产品侧 `lexicalWeighting: 'idf'` 仍然可用、仍然有测试）。

`§11.7` 的缺陷记在这里，因为它会重犯：**一张只有否决的表，被读成了准入表。** 正确的写法是
「判据 3/4 是 veto；veto 全过之后，切换与否由总体读数按它自己的判据决定，而那条判据在派发前就该
写在同一张表里」。这一轮的补救是**不切换**——不是补一条事后判据，而是拒绝把一个「没被否决」当成
「被支持」。

## 12. 派发通路（第 129 轮）：候选此前无法从臂上表达出来

这一节记的是**一个被当成前提而没被检查的事实**：要读 §11 的 `ABS` 判据，臂必须能在 `idf` 下运行，而它此前不能。

### 12.1 五段链路里缺了后两段

| 链路 | 本轮之前的状态 |
| --- | --- |
| `SearchIndex` 按语料给词项定价（`§13.379`） | 有 |
| `CortexMemory` 拒绝它不管理的取值（`§13.382` 起在装配期就拒绝） | 有 |
| `bench-memory-arm.ts` 读 `CORTEX_MEMORY_LEXICAL_WEIGHTING`（`flat`/`idf`） | 有（`§13.379` 加的） |
| workflow 转发该变量 | **没有** |
| 派发器写入变量并声明 departure | **没有** |

后果是：操作者设了仓库变量，拿到的是注册臂，而 artifact 会**诚实地**写 `lexicalWeighting: "flat"`。也就是说，`idf` 的 `+190` 是**一个准确率派发从未能到达的配置**上的读数。

这正好是要求⑯ 在更高一层的形态：此前的形态是「产品做不到评估证明过的事」，这次是「**臂无法被派发成评估测量过的那个配置**」，而且两端都看不见——臂的测试过（它解析这个变量），产品的测试过（选项可用），缺口落在中间那两个用不同语言写的文件里。

### 12.2 三条改动，以及限定它的约束

`workflow_dispatch` 上限 25 个输入，该工作流已占 24，`test_dispatch_inputs.py` 禁止贴到上限——所以像 `supersededRendering` / `indexEmbedding` 一样走**仓库变量**：

| 链路 | 改动 | 它防的失败 |
| --- | --- | --- |
| workflow | `vars.CORTEX_MEMORY_LEXICAL_WEIGHTING \|\| 'flat'` | 臂读、workflow 不设 = 旋钮接不到任何东西 |
| 派发器 | `lexical_weighting_switch`，严格收 `flat`/`idf`，缺省 `flat` | 拼错回落到 `flat` = 用注册臂的数字冒充候选 |
| 派发器 | 每次派发都 `write_variable(...)`，且在 POST **之前** | 上一轮遗留的 `idf` 会把下一次控制跑成处理组 |
| 派发器 | 仅当 `!= flat` 时声明 `lexicalWeighting` | 未声明会被闸门在花完钱之后拒绝；无条件声明则报告一次没发生的 departure |
| `readout-arm-run.py` | `REGISTERED_CONDITIONS['lexicalWeighting'] = ('lexicalWeighting', 'flat')` | 声明落到一个没有座位的名字上 = 两小时跑完才被拒（`S14` 的失败，方向相反） |

`tools/__tests__/test_lexical_weighting_wiring.py` 七条测试钉住全部五段，外加两套词表互校（臂的 `LEXICAL_WEIGHTINGS` 与派发器的元组，以及两边默认值）。其中「workflow 转发」一条做过**变异检查**：删掉那行 → 测试失败；恢复 → 通过。删掉一行就能让测试变红，是这条测试唯一的有效证明。

第六个条件也让判定器的表头从 **26 个字段变成 27 个**，而 `test_registration_diff.py` 里那条「表长大了，计数也要跟着长」的断言当场变红——它存在的理由就是这个：注册对比的总体不是一个数，是「21 个输入 + 条件表的长度」，两边必须一起改。

### 12.3 顺手做的 0 CNY 探针，以及它为什么不可用

为了回答「provider 余额回来了吗」，最省的做法看似派一次 1 题。**不可用**，原因是本项目自己的规则：run `44251051571`（`limit=1`、`ablation_runs=1`）在 **9 秒、0 CNY** 被 `registration-preflight.py` 拒绝：

```
asked 8 field(s), 22 registered, 17 departed, 16 not declared
a dispatch that names a budget map and nothing else is not the registered arm.
```

两个读数：①**没有便宜的 provider 探针**——一次运行要么是注册臂，要么不是读数，所以余额问题只能由那次要花 14.26 CNY 的运行来回答；②**闸门在花钱之前就开火**，这正是它存在的理由——同样一句拒绝若晚两小时出现，留下来的会是一个在十六个字段上偏离、无法归因的 artifact。
