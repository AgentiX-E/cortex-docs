# 预登记：词法零召回的离线修复（`I17`）

> 状态：**已登记，未执行**。本文件在派发之前写死判据、候选与拒绝条件，理由与本项目其他预登记文件一致——一个先看到数字再决定判据的实验，测的是实验者的偏好。
>
> 前置：`docs/ANALYSIS-LEXICAL-ZERO-RECALL.md`（读数来源与三条判据）、`cortex` 的 `S14` 证据（`cortex-docs/evidence/longmemeval/lexical-index.json`）。

## 1. 问题

`S14` 证明：词法索引在 500 题里 **21 题一条金轮都没送到**（其中 3 题是 `ABS`，且因「没送到」而答对），向量臂 **0 题**。零召回桶的正确率 19.0%，非零召回 82.9% 起。

所以问题不是「词法检索好不好」，而是：**在登记房间（各路由 24,000 / 48,460 / 48,000 字符）下，能不能把零召回题数从 18 降下来，而不把 `1–33%` 桶撑大、也不碰 `ABS`。**

## 2. 为什么这一轮不需要模型

金轮是**文本**，不是标签：`questions[].goldOverlap.goldTurns` 里逐条存着。检索是否命中金轮，只取决于倒排、打分、融合与房间——这四件全是确定性代码。因此整个第一段是 **0 CNY、0 派发、0 判官** 的离线读数。

确认性派发（500×4，≈14.26 CNY）只在**离线读数改善且三条判据同时成立**之后做一次，用途是回答「召回改善有没有变成正确率」。

## 3. 仪器（必须先自证）

新增 `packages/cortex-memory/bench/lexical-recall.ts` + `.github/workflows/lexical-recall.yml`（**仅 `workflow_dispatch`，不进任何自动触发**）。

| 项 | 定义 |
| --- | --- |
| 语料 | LongMemEval-S 的 500 个 haystack，与 `benchmark-cortex-memory.yml` 用同一下载步骤与同一 fingerprint |
| 金轮 | 取自 `S14` artifact 的 `goldTurns` 文本，逐题按**全文相等**匹配（不做相似度近似） |
| 度量 | 每题的 `delivered / total` 与桶分布，与 `tools/gold-recall-census.py` 同一分桶规则 |
| 交付口径 | 与产品同一路径：`SearchIndex` → 融合 → 房间裁剪 → 逐轮渲染；**不调用 reader、不调用 judge、不调用 embedder** |
| 输出 | 一个 JSON：逐题 `delivered/total`、桶表、零召回题号及能力，附配置指纹 |

### 3.1 校准闸门（不过就整轮作废）

在**登记配置**下，仪器必须复现 **零召回 21 题**（`IE 17 / ABS 3 / TR 1`），且逐题 `total` 与 artifact 的 `goldDelivered.length` 完全相同。

- 复现不出来 ⇒ 仪器与产品路径不是同一条，后面所有候选的比较都无意义；
- 允许的偏差只有一种：**`goldOverlap` 的金轮文本在 haystack 里出现多次**导致匹配歧义，此时报告歧义题数并要求人工裁定，**不得**用「近似匹配」把差异抹平。

这一段是整轮最重要的部分。本项目已经付过三次「数字是真的，但挂在了没有产生它的配置名下」的钱（§26.4、§27.2），校准闸门是第四次之前的那道门。

## 4. 候选（每个一次一个变量）

| # | 候选 | 变量 | 先验 |
| --- | --- | --- | --- |
| 1 | BM25 长度正规化 | `k1 ∈ {1.2, 1.5}`, `b ∈ {0.3, 0.5, 0.75}` | 轮次长度差异极大（见 `evidenceChars` 50 万 vs 交付 2.4 万），`b=0.75` 可能压掉长金轮 |
| 2 | 词干化 | 关 / 开 | 用户语言口语化，词形变化多 |
| 3 | 停用词 | 关 / 开 | 问题短，停用词占权重会稀释 |
| 4 | 字段权重 | 查询命中的轮次里，`user` 轮 ×1.0 / ×1.5 | 金轮多为用户自述 |
| 5 | 近似短语 | 关 / 3-gram 窗口 | 与候选 1 相互作用的唯一一项 |
| 6 | 候选宽度 | `relevance_top_k` 256 → 512 | 只影响召回上界，不改打分 |

**不做**：语义扩写（需要模型）、向量混合（就是 `S14` 否掉的那条）、改房间（房间是登记值）。

## 5. 判据（三条同时成立才算改进）

| # | 判据 | 现在的值 | 通过条件 |
| --- | --- | --- | --- |
| 1 | 可修零召回题数（`IE`+`TR`，排除 `ABS`） | **18** | **≤ 14**（按 1–33% 桶 82.9% 折算 ≥ +2.0 点） |
| 2 | `1–33%` 桶题数 | 129 | **≤ 145**（把金轮换成噪声的改动会推高它） |
| 3 | `ABS` 零召回题数 | 3 | **= 3**（不变；若某候选让 `ABS` 拿到了证据，直接拒绝，不论判据 1 多好） |

判据 1 的 14 这个数字是算出来的，不是拍的：零召回桶现有 21 题、4 题答对；若把 4 道可修题拉进 1–33% 桶，18 → 14 对应 `(18−14) × (0.829 − 0.19) ≈ +2.6` 点。写进登记是因为它必须可以在事后被检查「当初是不是这么算的」。

## 6. 否证与停止

- 全部候选都不满足判据 1 ⇒ **结论是「词法打分不是这条损失的杠杆」**，写进 `RETRACTIONS` 并把 `I17` 的下一步指向 `I8`（候选集裁决），而不是继续调 `k1`。
- 任一候选满足三条 ⇒ 做一次确认性派发（500×4，14.26 CNY），判据是配对 Δ 题 ≥ −5 且零召回题数同向下降；**离线改善但派发不改善**，则以派发为准并把该候选记为无效。
- 一次只跑一个候选进确认性派发；不做多候选网格的「挑最好」——那是在 500 题上做选择，选择本身就是过拟合。

## 9. 执行记录：仪器已实现（第 127 轮），校准待派发

本节在派发**之前**写下仪器的形态，因为 §3 只说了「必须先自证」，没说自证的做法可以怎么变。做了三处**收窄**，每处都让判据更硬而不是更软。

### 9.1 仪器不是新写的检索器，是产品加常量

§3 把仪器描述成 `SearchIndex → 融合 → 房间裁剪 → 逐轮渲染`。那样实现等于把产品的组装逻辑写第二遍，而第二遍测到的第一件东西是两遍之间的漂移。改为：**产品原样跑**，读者与判官换成常量（`CORTEX_ARM_OFFLINE=1`）。

| 组件 | 仪器里的形态 |
| --- | --- |
| 检索 / 融合 / 房间 / 截断 / 渲染 | 出厂代码（`CortexMemory`） |
| 读者 | `"offline instrument"` |
| 判官 | `incorrect` |
| 嵌入 | 不构造（`indexEmbedding: none`） |

交付口径因此与 §3 的「不调用 reader、不调用 judge、不调用 embedder」一致，而「与产品同一路径」从**承诺**变成**同一份代码**。

### 9.2 校准闸门的判据从「零召回 21 题」加严到逐题三元组

§3.1 要求复现零召回 21 题且逐题 `total` 相同。实际实现比对的是**每题三个字段**：

| 字段 | 不一致意味着 |
| --- | --- |
| `total` | 两次读的是同一 id 下的不同实例（数据集问题，不是打分问题） |
| `carried` | 交付集不同 —— 后面每个候选都是拿另一个基线在比 |
| `deliveredDigest` | 计数相同而文本不同：另一段语料、另一张房间、或渲染动了 |

加入 `deliveredDigest` 的理由是 §3.1 那句话的反面：只比 `carried` 时，一个「恰好也送到同样多金轮」的不同交付会通过。基准摘要由 `--write-reference` 从 `S14` artifact（run `43829744532`）折出，桶分布 21 / 129 / 114 / 236 与 `ANALYSIS-LEXICAL-ZERO-RECALL.md` §2.1 逐格相同——这是摘要口径的自证。

### 9.3 三条新断言，位置与 §3.1 同类

| 断言 | 位置 | 抓的形状 |
| --- | --- | --- |
| `assertOfflineInstrumentConfiguration` | 读语料之前 | 排名不在产品侧，或为动不了的通道付钱 |
| `assertOfflineInstrumentReached` | 写 artifact 之后 | 常量回复触发二次检索（`indexes != 题数×轮数`） |
| `lexical-recall-calibrate.py` | 读 artifact 时 | 仪器不是那条路径（逐题三元组） |

产品侧另有三条性质测试：证据与回复无关（两种回复 → `lastRetrievedContext()` 逐字节相同）、回复解析成答案（不触发 `reviewBareDecline`）、每问一次索引。

### 9.4 成本不变，但单位变了

§7 的离线段仍是 0 CNY；确认性派发仍是 1 × 14.26 CNY。变的是**候选之间**的比较：从「一次派发试一个」变成「一次离线跑完、再挑一个进确认性派发」。§6 的否证条款因此更容易被执行——六个候选全不过判据 1 的结论，现在一次运行就能拿到，而不是六次。
