# 竞品分析：谁在同一个赛道上，以及哪些数字可以放在一起

> 本文的每一个数字都能在 `AgentiX-E/cortex` 的 `tools/competitor-ledger.json` 里找到同名条目，
> 由 `node tools/competitor-ledger.mjs` 生成表格、`--check` 校验、`--gap` 判定我们能否与之排名。
> **台账是数据，本文是读法。** 两者冲突时以台账为准，并且这条冲突本身是一条缺陷。

## 0. 一句话结论

LongMemEval-S 上公开可查的数字从 **51.8 到 94.4**，跨度 42.6 点，而这个跨度里**大部分不是系统差异**：
同一个 Zep 被三份来源读成 90.2 / 79.8 / 71.2，同一个 Mem0 自报 94.4、同 harness 读成 56.0。
所以我们**不宣称任何跨来源排名**，只做三件事：登记可比条件、在自己 harness 内比较、把可复现的对手
拉进自己的 harness 跑。

## 1. 可比性是一个五元组，不是一个数据集

两个数字可以放在一起排序，当且仅当它们在下列五项上全部一致：

```
dataset | variant | answer model | judge | harness
```

- 前两项说**问了什么**；
- 中间两项说**谁答、谁判**；
- 最后一项说**谁的流水线决定了什么进入答题模型**——检索、截断、什么叫"答对"都在这里。

`harness` 必须进键，而不是从中间两项推出来：两个 harness 可以有相同的答题模型和裁判，
却在检索深度、截断策略、判正规则上完全不同。**分组比真相粗**只可能把一个可比的表拆开，
不可能把两个不可比的表合并——这是唯一安全的错误方向。

`--gap 83.0` 在 23 条台账上给出的结果是**没有可比组**，并列出三个并列最近的组及各差字段。
这个"没有"就是诚实答案；换成"83.0 排第二"就是把 harness 的事实读成系统的事实。

## 2. 唯一可排序的表：OmniMemEval

这是我们找到的唯一一份"同一流水线跑所有系统"的公开结果（答题 GPT-4.1-mini，裁判 GPT-4o-mini，
由 MemOS 团队发起，公开 adapters 与运行配置）：

| 系统 | LongMemEval-S | LoCoMo | 备注 |
|---|---|---|---|
| MemOS | **89.20** | 88.83 | 发起方自己的产品，同一 harness 下两个数据集都第一 |
| EverOS | 80.40 | — | |
| Zep / Graphiti | 79.80 | 63.83 | LongMemEval 上是该系统本表的第三次读数；LoCoMo 自报 94.7，**同 harness 低 30.9 点** |
| Letta | 77.67 | 77.12 | MemGPT 一脉，两个数据集几乎一致 |
| Hindsight | 72.20 | 81.99 | 反过来：LoCoMo 比 LongMemEval 高 9.8 |
| Supermemory | 66.07 | 73.53 | 自报 84.6；LoCoMo 上排第五，LongMemEval 上排第六 |
| Viking | 61.07 | — | |
| Mem0 (cloud) | 56.00 | 77.68 | 自报 94.4；开源版第三方复现 **49.0** |
| Cognee | 51.80 | 83.48 | **两个数据集差 31.7 点，本表最大** |

**两列一起读才是这张表的用处。** Cognee 在 LongMemEval 上垫底、在 LoCoMo 上第三；Zep 在
LongMemEval 上第三、在 LoCoMo 上倒数第二。**名次会随数据集翻转**，所以任何"某系统 SOTA"
的说法都必须带数据集名——这也正是 §8 要求补第二个数据集的实证理由，而不是一句方法论口号。

**这张表的价值不在于名次，在于它证明了名次可以被测量的方式改变多少。** Mem0 从 94.4 掉到 56.0
（−38.4，开源版第三方复现 49.0，即 −45.4），Zep 自报 90.2 在这里 79.8，Supermemory 从 84.6 掉到 66.07（−18.5）。

**这张表的局限必须同时说**：它由参赛者之一发起，且它在 LongMemEval 上把 Mem0 读成 56.0，
与 Mem0 自己的 94.4 相差 38 点——两者必有一个测的不是对方在测的东西。我们的立场是：
**在这种分歧被第三方裁掉之前，任何一方都不能被当作 SOTA 的证据**，包括我们自己。

## 3. 一个系统能被读成多少种分数

`node tools/competitor-ledger.mjs --spread` 的原样输出：

```
Mem0            LongMemEval  spread 45.4  (49 .. 94.4)
Zep / Graphiti  LoCoMo      spread 30.9  (63.83 .. 94.7)
Zep / Graphiti  LongMemEval  spread 19.0  (71.2 .. 90.2)
Supermemory     LongMemEval  spread 18.5  (66.07 .. 84.6)
full context    LongMemEval  spread  2.0  (60.2 .. 62.2)
```

注意 Zep 出现两行：它在两个数据集上各有自己的跨度，而 `LongMemEval` 的 19.0 是本节表格里要读的那个数
（LoCoMo 的 30.9 对应 §2 备注里那条「同 harness 低 30.9 点」）。**同一个系统在不同数据集上跨度不同，这本身就是 §8 要求第二个数据集的理由之一。**

| 系统 | 读数（同一数据集 LongMemEval-S） | harness 数 | 跨度 |
|---|---|---|---|
| Mem0 | 94.4 / 93.4 / 56.0 / 49.0 | 4 | **45.4** |
| Zep | 90.2 / 79.8 / 71.2 | 3 | **19.0** |
| Supermemory | 84.6 / 66.07 | 2 | **18.5** |
| full context（无记忆） | 62.2 / 60.2 | 2 | 2.0 |

Mem0 一行是四个读数，因为它有**两种口径 × 两种部署**：自报（94.4 自托管配置、93.4 新版）与
复现（56.0 托管服务、49.0 开源自托管）。把这四个数平均成"Mem0 是 73.6 分"没有任何含义——
**这不是同一件事的四个测量，这是四件不同的事**。台账把它们放在同一个 `system` 下是为了算出这个
45.4，而 `deployment` 字段是为了记住它们不是一件事。

最后一行是让前几行可读的东西：**`full context` 只有 2.0 点**，而它是一个完全没有记忆机制的系统
——整份 haystack 塞进 prompt。这是**效应量的地板**：任何记忆系统的跨度都应该对着 2.0 读，而不是对着 0 读。
Mem0 的 45.4 是地板的 22 倍，Zep 的 19.0 是 9.5 倍。

工具还区分另一种跨度，本表暂时没有实例但规则要在：**同一个 harness 下的两个读数是一个版本差异，
不是 harness 效应**（`version difference, not a harness effect`），并且这类行会被排在跨 harness 的行
**之后**——因为读者会把第一行当成最大的发现，而版本差异不是本文在说的事。

## 4. 第三方对比表内部也不是同一条件

台账第一版被自己的检查拒了，而拒绝本身就是发现：

```
apex-mem-published: members disagree about answerModel (Claude 4.5 Sonnet, unknown)
supermemory-published: members disagree about answerModel (GPT-5, GPT-4o)
```

- APEX-MEM 的表：自己一行 Claude 4.5 Sonnet，三个 baseline 一行**未说明模型**；
- Supermemory 的表：自己一行 **GPT-5**，竞品一行 **GPT-4o**。

**一张第三方对比表是一组条件的集合，不是一个条件**；而把自家那一行放在更强模型上的，正是编表的人。
处置是把 harness 按答题模型命名（`supermemory-published/gpt5`、`supermemory-published/gpt4o`），
**不是放宽检查**——检查是对的。

## 5. 我们在哪

本仓当前读数（run `40989420944`，feature 侧，500 题）：

| 能力 | n | 我方 | 我方参照 | 差 | 仅参照对 / 仅我方对 | 精确 McNemar p |
|---|---|---|---|---|---|---|
| IE | 150 | 94.0% | 0.7% | +140 | 0 / 140 | < 1e-30 |
| KU | 72 | 86.1% | 0.0% | +62 | 0 / 62 | < 1e-18 |
| TR | 127 | 78.0% | 66.1% | +15 | 7 / 22 | 0.0081 |
| **MR** | **121** | **69.4%** | **86.0%** | **−20** | **26 / 6** | **0.00054** |
| ABS | 30 | 96.7% | 100.0% | −1 | 1 / 0 | 1.0 |
| **合计** | **500** | **83.00%** | **43.80%** | **+196** | 34 / 230 | 6.3e-37 |

三个必须分开说的判断：

1. **83.00% 不能与第 2 节的任何数字排序。** 答题模型是 DeepSeek，裁判是自己写的规则，
   harness 是本仓流水线。五元组五项全不同。`--gap` 因此拒绝给名次——这不是谦虚，是定义。
2. **43.80% 不是竞品，是本仓的参照流水线**，一个没有记忆臂的检索-阅读管线。把它当竞品引用会
   低估表里每一个系统。
3. **MR 上的 −20 是本轮最重要的读数。** 详见 §6。

## 6. MR：我方记忆臂显著输给自己的对照

| 题 | 金标 | 我方答案 |
|---|---|---|
| How many items of clothing do I need to pick up or return from a store? | `3` | `2` |
| How much total money have I spent on bike-related expenses since the start of the year? | `$185` | `65` |
| How many movie festivals that I attended? | `4` | `3` |
| How many times did I bake something in the past two weeks? | `4` | `3` |
| How many babies were born to friends and family members in the last few months? | `5` | `6` |
| How many properties did I view before making an offer on the townhouse? | `4` | `5` |
| How many hours of jogging and yoga did I do last week? | `0.5` | `30` |
| What time did I go to bed on the day before I had a doctor's appointment? | `2 AM` | 弃答 |

二十六道里有八道读了；七道是**枚举差一个成员**（五道少一、两道多一），一道是单位聚合错。
这不是阅读失败，也不是通常意义的检索失败——**记忆臂够到了那些会话并且读了它们**。
它是**成员判定**失败：哪些提及算作被计数事物的一个实例。

这个诊断在 `§13.96` 就写下过，当时三次提示词侧尝试都没能推动它，于是把力气转向了窗口机制。
窗口机制现在结案（ceiling = 2 道，`§13.161.8`）。而 MR 这边是 **20 道净差，且这 20 道已经
被本仓自己的组件答对过**——同样的 haystack、同样的读者、同样的裁判。

**这是本臂迄今最大的机会，且不需要发明任何新东西**：需要找的是参照做了而记忆臂没做的那件事。

## 7. 对标的三类靶子，按可复现性排序

| 靶子 | 为什么是它 | 复现成本 |
|---|---|---|
| **Mem0（开源）** | 唯一有"自报 94.4 / 第三方复现 49.0 / OmniMemEval 56.0"三读的系统，本仓 `tools/competitor-sut/mem0_driver.py` 已能驱动它自己的代码 | 已有适配器；`infer=0` 零模型调用，`infer=1` 约 27.5 万次调用 |
| **A-Mem（NeurIPS '25）** | 机制与本文完全不同（结构化笔记 + 链接 + 演化），在 APEX-MEM 表里 59.3；纯 Python，无外部服务 | 需新适配器；抽取需逐轮模型调用 |
| **MemOS** | 同一 harness 下第一（89.20）；公开 adapters 与配置，是"可审计的 SOTA"里最像样的一个 | 需读它的 adapter 契约，可能需服务端 |

**纪律**：任何一方进入本仓 harness 时，`MEM0_INFER` 之类的开关必须写进产物清单。
`infer=0` 测的是**检索**，`infer=1` 测的是**抽取 + 检索**，两者不能都叫"Mem0 的分数"。

## 8. 我们还缺的三个轴

公开对比里已经有人在报，而本仓**完全没有测量**：

| 轴 | 别人怎么报 | 我们为什么现在必须补 |
|---|---|---|
| **上下文 token / 查询** | Contextier 91.6% @ 2,807；Mem0 93.4% @ 6,787；Zep 90.2 @ 4,408 | 我方 prompt 均值 46–47k 字符，**每道题都顶到 48k 预算**。这在成本上不可持续，且掩盖了"检索选得好不好"——预算恒定用满时，选择质量不可观测 |
| **延迟** | MemScore 三轴写 `85% / 120ms / 1500tok` | 我们没有 p50/p95。零调用的机制和 68 次调用的机制在准确率上可能打平，在延迟上不会 |
| **第二个数据集** | LoCoMo 与 LongMemEval 同报；同 harness 下 Cognee 差 **31.7** 点、Hindsight 差 9.8 点、Supermemory 差 7.5 点（反方向） | 单数据集上的 +15 可能只是对该数据集的形状过拟合；§2 的两列已经证明名次会翻转 |

补这三轴不是为了好看：**第 8 节第一行直接解释第 6 节的缺陷**。MR 的枚举失败发生在
166–184 轮、46k 字符的交付里——如果检索能给出 30 轮相关证据而不是 170 轮，成员判定会容易得多。
**降 token 不是一个效率工作，它可能就是 MR 修复的路径。**

## 9. 检验方法与验收标准

| 项 | 检验方法 | 验收标准 |
|---|---|---|
| 台账完整性 | `node tools/competitor-ledger.mjs --check` | 每条有 `source`；同 harness 组内答题模型与裁判唯一；`harness` 类至少覆盖 3 个系统 |
| 可比性判定 | `--gap <score>` | 同组才给名次；无同组时列出**所有**并列最近组及差字段，且**不打印名次** |
| 我们 vs 竞品（同 harness） | `competitor-retrieval.yml` 的 `sut=` 臂，`infer` 开关入产物 | 两臂同回答模型、同裁判、同 roster；报告必须打印 `infer` 值 |
| MR 缺口诊断 | 对 26 道逐条分类（差一/单位/弃答/其他），四类计数之和 = 26 | 主导类命名一个机制；该机制的登记写在这份普查**之后** |
| MR 修复 | 重派后看 discordant 对 | ≥10 道移出"仅参照对"，"仅我方对"增长 ≤2；总分 +1.5 pt 以上；其他能力掉 ≤2 道 |
| token 轴 | 产物已带 `promptChars` 与 `evidenceTurns` | 报告必须给均值与 p95；不得只给"预算上限内" |
| 延迟轴 | 待建（本轮未做） | 未建前不得在任何对比中使用延迟一词 |

## 10. 这份文档本身的可证伪点

- 若任何一个竞品的**自报**数字被第三方以同 harness 复现到 ±2 点内，§2 的"分歧未裁"结论就要改；
- 若 `--gap` 在某次真实对比里给出了名次（即五元组真的全同），§1 的"没有可比组"就是本轮的
  结论而非永久结论；
- 若 MR 的 26 道普查发现"差一"不是主导类，§6 的机制方向作废，且这必须写在下一轮文档里。

——以上三条不是免责声明，是**下一次修订的触发条件**。
