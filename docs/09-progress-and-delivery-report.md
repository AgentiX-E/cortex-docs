## 1. B1：交叉编码器重排

### 1.1 为什么做

全仓检索 `rerank` 得到**零个实现**。cortex 用双编码器检索并按 RRF 融合，但从未用一个
能同时看到问题和候选的模型重新打分。双编码器在编码期两者互不可见，因此**无论多少余弦
运算都无法恢复交互信号**——这正是交叉编码器存在的理由。已发表且 LongMemEval ≥95% 的
记忆系统都在检索末段跑一次联合重打分；Exabase M-1 的第三阶段就是「一致性重排」。

### 1.2 落地位置

| 层 | 位置 | 四维度覆盖 |
|---|---|---|
| 纯排序 | `cortex-core/src/retrieval/rerank.ts` | 100 / 100 / 100 / 100 |
| 远程适配 | `cortex-llm/src/rerank/rerank.ts` | 100 / 100 / 100 / 100 |
| 本地适配 | 同上（transformers.js 离线兜底） | 同上 |
| 工厂 | `cortex-eval/src/rerank-factory.ts` | 100 / 100 / 100 / 100 |
| 接线 | `natural-language-memory.ts` 两条检索路径 | 100 / 100 / 100 / 100 |

### 1.3 读码后修正的三条计划前提

这是本轮最有价值的部分：**计划里有三条判断在读码后站不住**。

**修正一：管线不是「单通道浅检索」。** `retrieveSessionsForQuestion` 已用 RRF 融合
**4 条通道**：question 质心 / LLM 扩展短语 / 确定性词汇变体 / turn-level 召回。
原 B2 表述为「加多通道并行检索」，会重复造一个已存在的轮子。

**修正二：真正的窄口是候选池宽度。** `retrieveTopKByQueries` 在**内部**就执行
`slice(0, topK)`，因此默认配置下重排**只能对 top-K 做排列组合，无法把余弦排名第 20 的
答案捞回来**。这条限制已由 `rerankCandidatePool` 解除（先取宽池、重排、再收窄回 topK，
所以答案提示词的宽度不变），并且**固化为测试**——故意断言这个限制，使得日后有人再次收窄
池宽时，原因可见而非靠推断。

**修正三：弃权风险已经修好。** 计划把 RRF v1 回归（IE 95.0% → 87.5%）列为 B1 的
「最主要失败模式」。但读码确认 `maxHitScore()` 早已取代 `hits[0].score` 作为弃权置信度，
且其注释明确写了「弃权信号必须与融合顺序无关」。因此重排对弃权**天然安全**，
原计划的预警属于**过度**。`rerankProtectedHead` 仍保留，供需要固定首条证据的调用方使用。

### 1.4 本轮发现的 BUG

**接线只接了一条路径。** 首次实现只把重排接进 `retrieveSessionsForQuestion`（多会话路径），
而 `answer()`——大多数 LongMemEval 题目走的路径——经 `retrieveTurns`，**完全没有重排**。

后果是：这个阶段「已实现、能被一个调用方触达、却在评测路径上静默缺席」。
面向多会话路径写的测试**会通过**，而 benchmark 分数**不会动**。这正是
`06-code-docs-consistency-audit.md` 记录的缺陷类别，在同一个仓库里再次出现。

**修复不是再抄一份调用**：抽出共享的 `applyRerank()` 服务两条路径，使「某条路径忘了重排」
在**结构上不可表达**。另外 `retrieveTurns` 在 admission **之前**重排而非之后——
admission 窗口是有界的，事后重排只能打乱它已经选中的回合，而救不回它本该提升的证据。

### 1.5 明确不声称的部分

- **无精度声明**：尚未带重排跑过 LongMemEval。07 文档里的 +1.5–3.0pp 是**假设**。
- **不改默认**：重排保持关闭，直到其预注册 A/B 为绿。本仓库的历史是一串「因缺少受控对比
  而被回滚的检索改动」，再添一个未测量的默认值就是重蹈覆辙。
- **池宽默认等于 topK**：这是**诚实但最弱**的设置，写在选项文档里，而不是藏在一个
  无测量支撑的调优值后面。

## 2. B2：召回曲线测量仪器

### 2.1 为什么需要新仪器

原有的检索诊断只报 `recall@1` 与 `recall@5`。这一对**无法回答决策问题**，因为同一个
症状下有两种截然不同的成因，而在单一截断点上二者不可区分：

| 成因 | 实际发生了什么 | 对症的举措 |
|---|---|---|
| **广度不足** | 证据回合从未被检索到 | 加宽候选池 |
| **排序不佳** | 证据一直在池里，只是排得太靠后 | 重排（B1） |

两者的表现都是「recall@5 不是 100%」。**凭它就选举措，是猜。**

### 2.2 仪器测什么

在每个截断点 `k`，仅统计**可答题**：

| 字段 | 含义 |
|---|---|
| `recall` | 双编码器自身排序已召回的占比 |
| `ceiling` | 答案落在宽度为 `poolWidth` 的池内的占比 = 完美重排的上界 |
| `gain` | `ceiling - recall`，即**不新增任何检索**、仅靠重排能解锁的召回 |

两条性质使它成为正确的仪器：

- **`gain` 隔离出重排的净空间**：它对固定池计算，因此**无法靠多检索来改善**，只能靠排序。
  这正是判定 B1 存废的数字。
- **`ceiling` 饱和即停止加宽的信号**：越过 `gain` 归零的 `k`，每多一个候选都是只有成本、
  没有召回。

### 2.3 实际输出（合成分布演示）

40 个答案在 rank 1、25 个在 rank 3、20 个在 rank 8、10 个在 rank 16、5 个在 rank 41，
池宽 50：

```
k      recall   ceiling  gain
1      40.0%    100.0%   60.0%
3      65.0%    100.0%   35.0%
5      65.0%    100.0%   35.0%     <- 3→5 加宽毫无收益
10     85.0%    100.0%   15.0%     <- 5→10 加宽买到 20pp
20     95.0%    100.0%    5.0%
50    100.0%    100.0%    0.0%
```

「3→5 平坦、5→10 陡峭」这种区分，正是 `recall@1`/`recall@5` 表达不出来的。

### 2.4 设计的三个关键决定

**上界属于池，不属于截断点。** `ceiling` 按构造对所有 `k` 恒定——它回答「若完美重排这个池，
最多能到多少」。若它随 `k` 变化，`gain` 就失去意义，因为重排模型**不能自己挑截断点**。

**`gain` 在 0 处截断。** 当 `poolWidth` 设得比某个截断点更窄时，实际 recall 可能超过池上界。
负的 `gain` 会被读成「重排有害」，而真相是「池太窄，说不出任何结论」。截断是为了不让
数字断言一个该配置无法支撑的结论。

**空答案集算未命中，不算命中。** 弃权题没有 `has_answer` 回合。把「没有答案可找」
当成「在 rank 0 找到」，会把每道弃权题都算成完美检索并抬高整条曲线。弃权题已从曲线中
整体排除。

### 2.5 预注册读法（测量前固定）

| 观察 | 结论 | 行动 |
|---|---|---|
| `gain` 大、`ceiling` 已平坦 | 瓶颈在排序，不在广度 | 执行 B1 的 A/B；**不要**加宽池 |
| `ceiling` 在最宽截断点仍在上升 | 存在真实召回空间 | 加宽 `rerankCandidatePool` 并重测 |
| `gain ≈ 0` 且 `ceiling` 处处平坦 | 广度与排序都不是瓶颈 | 停止，约束在别处（上下文 admission 或阅读器） |

**反证条件**：若加宽池抬高了 `ceiling` 却没抬高 `gain`，则池不是约束，加宽必须回滚。
若 `gain` 处处很大、而 B1 的 A/B 显示精度不动，则检索排序无法传导到答案，
**两个方向同时关闭**。

## 3. A4：覆盖率从约定变成硬门禁

**四个包中有三个根本没有 vitest config**，所以「≥95% 每维度」一直是可以被静默违反的约定：
`vitest run --coverage` 会打印一个低数字然后**仍然退出 0**。

现已为四个包都加上 `thresholds`，四条维度（statements / branches / functions / lines）
均为 95，并**实测验证**：临时把 statements 抬到 99.5 后，进程**退出码为 1**。

之所以四条维度都设门禁，是因为它们**独立失效**：语句覆盖高而分支覆盖低（三元、
`??`、短路 `&&`、switch 的 default 臂未被走到）恰恰是记忆系统会藏缺陷的地方——
一条未被走到的回退路径。
