# 阅读器判断再研究：阅读器是不是真正的约束？

> 研究日期：2026-09-20
> 触发：对 `07-sota-roadmap.md` v1.0 中「SOTA 需要换阅读器」结论的复核请求
> 结论：**该结论被证伪。阅读器不是约束瓶颈。** 本文给出证据与修正后的判断。

---

## 0. 结论先行

`07-sota-roadmap.md` v1.0 写了三句话，其中两句是错的：

| v1.0 的断言 | 判定 | 证据 |
|---|---|---|
| DeepSeek 阅读器下天花板 85.5–88% | ❌ **错误** | 同档阅读器（GPT-5-mini）已有系统达 **94.87%**；更小的阅读器（Gemini 3 Flash）达 **96.4%** |
| 91–96% 的 SOTA 必须更换阅读器 | ❌ **错误** | **Exabase M-1 用 Gemini 3 Flash（比 Gemini 3 Pro 小 4–6 倍）达 96.4%**，登顶排行榜 |
| 阅读器换代值 +6–9pp | ✅ **正确** | Hindsight 20B → Gemini 3 Pro：+7.8pp（架构固定） |

**修正后的判断**：在固定阅读器下，架构差异的解释力**是阅读器差异的 4.7 倍**
（37.0pp vs 7.8pp）。真正的约束不是阅读器能读多好，而是**我们喂给它什么结构的数据**。

这也意味着 `SOTA-BASELINE.md` 里那句话——"83.55% is a strong result at the DeepSeek
ceiling"——**不成立**。DeepSeek 的 LongBench v2 得分（58.3）**高于 GPT-4o（51.4）**，
即在该档位上 DeepSeek 不是更弱的阅读器。82–86% 不是阅读器天花板，是**管线天花板**。

复现：`python3 reader_attribution.py`（纯算术，无网络，结果确定）。

---

## 1. 决定性证据：同架构换阅读器

Hindsight 是唯一公开了跨阅读器结果的系统，因此提供了干净的变量隔离——
**记忆层固定，只换阅读器**：

| 阅读器 | LongMemEval-S |
|---|---|
| 20B 开源模型 | 83.6% |
| Gemini 3 Pro | **91.4%** |
| 增量 | **+7.8pp** |

**这是阅读器的净贡献**：7.8pp。

## 2. 决定性证据：同阅读器换架构

反过来，固定 GPT-4o 阅读器，架构差异有多大：

| 系统 | GPT-4o 下的 LongMemEval-S |
|---|---|
| EmergenceMem | 86.00% |
| Supermemory（单遍） | 85.86% |
| AgentOS | 85.60% |
| Mastra OM (base) | 84.23% |
| Oracle（论文参照） | 82.40% |
| **cortex** | **83.55%**（DeepSeek） |
| Zep / Graphiti | 71.20% |
| Mem0 | 49.00% |
| **极差** | **37.00pp** |

**37.0pp vs 7.8pp：架构的解释力是阅读器的 4.7 倍。**

> Zep 与 EmergenceMem 用同一个 GPT-4o，差 14.8pp。这个差值不可能是阅读器的。

---

## 3. 决定性证据：小阅读器已经登顶

| 系统 | 阅读器 | 成绩 | 相对阅读器档次 |
|---|---|---|---|
| **Exabase M-1** | **Gemini 3 Flash** | **96.4%** | 比 Pro **小 4–6 倍** |
| OMEGA | frontier | 95.4% | — |
| Mastra OM (high) | **GPT-5-mini** | **94.87%** | 中档 |
| Mastra OM | gemini-3-flash | 89.20% | 小档 |
| QRhead+ReAttn | **Llama-3.1-8B**（Recall@5） | **85.8** | 8B 开源 |

**Exabase M-1 是本次研究最重要的单一数据点。** 它明确以「隔离检索质量与模型能力」为
实验设计目标：

> "A bigger model can compensate for weaker retrieval... We deliberately chose a smaller
> model to isolate retrieval quality from model capability and solve for real, production use."

并且它**不使用任何按问题类型定制的提示词**——500 题统一用同一条通用提示词，还主动
去掉了 Mem0 评测脚本里的分类模板与启发式。**在自设更严格条件下拿到 96.4%。**

---

## 4. 对「DeepSeek 阅读器弱」这一前提的直接否证

LongBench v2 衡量**无记忆层**的裸长上下文阅读能力，是阅读器能力的诚实代理：

| 模型 | LongBench v2 |
|---|---|
| Gemini 2.5 Pro | 63.3% |
| **DeepSeek-R1** | **58.3%** |
| 人类 | 53.7% |
| **GPT-4o** | **51.4%** |

**DeepSeek-R1（58.3）高于 GPT-4o（51.4），距前沿仅 5.0pp。**

因此「cortex 用 DeepSeek 拿到 83.55%，而 Emergence 用 GPT-4o 拿到 86.0%，说明 cortex
架构弱」这个推论**方向反了**：cortex 用的阅读器在该档位上更强，却拿了更低的分。按
阅读器解释，cortex 应该高于 86；实际 83.55。**差值是负的，说明差距出在管线。**

---

## 5. 为什么 v1.0 会算错

v1.0 的 85.5–88% 是**把前沿系统之间的消融增量相加**得到的：重排 +1–2、RRF +0.5–1.5、
图激活 +1–2、时序检索 +1–2，从 83.55 起加总得 85.5–88。

**错在哪**：它假设「增量可以线性叠加」，且**只在当时那批系统里取增量**。但增量叠加在
真实系统上是非线性的（`p3b-graph-verdict.md` 已经证明：同一检索栈上的两个扩展会**互相
干扰**，图召回把一个本该 +1~2pp 的方向做成了 −7.09pp）。更关键的是，它**没有去问
"是否有系统在同一阅读器档位上做到了 95%+"**——而那才是唯一能界定上限的证据。

**方法论教训**：界定天花板要靠**存在性证明**（有人做到过），不是靠**增量外推**（把
小效果加起来）。

## 6. 竞争对手的共同配方：赢在数据结构，不在阅读器

把 §2–§3 里高分系统的做法横向对齐，出现一个高度一致的配方。这**不是阅读器能力**，是
**给阅读器的数据的结构**：

| 手段 | Exabase M-1 | Supermemory ASMR | Mastra OM | cortex 现状 |
|---|---|---|---|---|
| **多查询分解 + 并行检索** | ✅ 查询重写并分解为多个并行通道 | ✅ **3 个搜索 Agent**（直接事实 / 语境线索 / 时间线） | ✅ observ. | ⚠️ 有 `queryExpansion`，top-K/查询仅 **3** |
| **专用抽取器（按维度分工）** | ✅ 重要性 / 时序链 / 一致性 | ✅ **3 个 Observer Agent** × 6 维度 | ✅ | ❌ 单一通用抽取 |
| **结构化记忆单元（本体 + 时间戳 + 语义锚点 + 置信度）** | ✅ | ✅ | ✅ | ⚠️ 双时态在 core，**未接线** |
| **时序链解析** | ✅ temporal chain resolution | ✅ 时间线重建 Agent | ✅ | ⚠️ 部分 |
| **一致性重排** | ✅ cross-memory coherence | ✅ 聚合裁决 | ✅ | ❌ **完全没有重排** |
| **多路答案 + 聚合/投票** | — | ✅ 8 专家 prompt 并行（98.6%）/ 12 Agent 投票（97.2%） | — | ❌ 单路答题 |
| **完整上下文注入（非截断 JSON）** | — | — | — | ⚠️ 有 session char 上限 |

### 6.1 三条可复用的判据

1. **"专业化分工胜过通用模型"**——ASMR 的核心发现。专用抽取器（如细节提取专家）显著
   优于单一全能提示词。cortex 现在是**单一通用抽取**。
2. **"Agent 检索优于向量搜索"**——主动推理检索绕开语义相似度陷阱，解决时序变化导致的
   信息失效。cortex 现在**完全依赖向量 + 词法混合**。
3. **"并行处理是效率核心"**——把负载分发到多个专用通道，同时提升速度与颗粒度。

### 6.2 一个必须诚实记录的边界

Supermemory 的 ASMR **目前未用于其核心生产系统**（"ASMR目前还没有用在Supermemory的
核心生产环境中"），且其回答阶段使用了「8 条专家 prompt 并行，任一路答对即算对」的
**多路择优**策略——这在真实部署中意味着 8 倍推理成本，且**在基准口径下有乐观偏差**
（真实场景没有"任选一条正确"的裁判）。引用时应标注这一点。

相比之下 **Exabase M-1 的口径更硬**：单条通用提示词、无按题类型定制、明确讨论并披露
了基准噪声底。**M-1 是更可信的复刻对象。**

## 7. 修正后的目标区间

| 目标档 | 依据 | 判定 |
|---|---|---|
| 83.55% → **86%** | 同阅读器档位已有 GPT-4o 系统达 85.6–86.0% | **保底，必须达到** |
| → **90%** | Exabase M-1 top-10 即 90.8%（**只喂 top-10**） | 可达 |
| → **94–95%** | 同档阅读器（GPT-5-mini）达 94.87% | 需要补齐配方 |
| → **96%+** | Exabase M-1 top-50 达 96.4%（Gemini 3 Flash） | 上限参照 |

**修正**：不再有「DeepSeek 阅读器下 85.5–88% 天花板」这个说法。
**DeepSeek V4 Pro / V4.1 Flash 的 1M 上下文与本档阅读能力，不构成约束。**

> **关于 V4 Pro / V4.1 Flash 的判断**：用户的直觉方向正确——这两个型号的长上下文能力
> 不弱于 GPT-4o。但需要标注两点事实：(1) **DeepSeek V4 Pro 已于 2026-09-14 起路由至
> V4.1 Flash**（V4.1 Pro 未发布）；(2) V4.1 Flash 是 552B MoE（prefill 激活 8B / decode
> 16B），1M 上下文，CSA2 把 KV cache 压到 ~890 bytes/token。**它们是可用的强阅读器，
> 不是瓶颈。** 但公开来源里没有 V4.1 Flash 的 LongBench v2 分数，因此本节的判据建立在
> **架构归因**（§1–§2、§6）而非阅读器归因上——这反而更稳健。

## 9. 局限

1. **多数分数是厂商自报**，口径不统一。本文所有对比都已标注来源，且**结论只依赖两个
   最硬的证据**：Hindsight 跨阅读器（同一团队同一架构）与 Exabase M-1（公开论文、明确
   方法论、主动披露噪声底）。
2. **Exabase M-1 只跑了 LongMemEval**，未跨基准验证——它自己列为局限。因此不能推论
   「其配方在 BEAM 上也成立」。
3. **ASMR 未进生产**，且多路择优对基准有利。
4. **存在性证明 ≠ 预测**。M-1 的 96.4% 证明「小阅读器 + 好管线可以到 96.4%」，不证明
   cortex 能到。它界定机会上限，不承诺结果。
