### 2.2 P1 —— 在评分路径上无法度量，但扩展词确实被记录了

> P1：扩展变为分解形式 —— 出现一条包含 `chili` 且不同于番茄短语的短语。

**对较早一次解读的更正，记录在案是因为错误的方向很重要：**
*评分*运行的决策追踪确实携带 `expansionQueries` —— 例如
`gpt4_7f6b06db` 记录了 `["first trip","second trip","third trip"]`。而
**消融实验臂**完全没有携带任何追踪：`benchmark-conjunction-ablation-report.json`
只保存 `featureCorrect`（每道题一个布尔值）加上聚合值，别无其他。

因此 P1 原则上可回答，但**无法从 R4 产物回答**，因为变动扩展的那个实验臂
正是那个什么也不记录的实验臂。所以“分解没有修复目标”这一结论依托于 P2
（可观测，且它失败了），而非依托于 P1。缺失的追踪被记录在 §5 中，作为任何重试的先决条件。

一个有用的副作用：阅读失败 TR 题上的扩展词，能看出好的扩展与坏的扩展长什么样，
并且它重新界定了 TR 瓶颈（§3.3）。

### 3.2 这些损失是 LLM 评分噪声，而非代码

承重测试：`top1Score` 由确定性检索栈计算，因此若它在两次运行之间完全相同，
则检索到的上下文完全相同。

| 量 | 计数 |
|---|---|
| 两次运行中都有的题 | 171 |
| **`top1Score` 相同** | **132** |
| `top1Score` 不同 | 39 |
| **在 `top1Score` 相同的情况下判决翻转** | **4** |
| 在 39 道分数不同的题中判决翻转 | **0** |

**全部四次翻转都发生在检索信号逐位相同的题上。** 没有一次翻转与分数变化
相关。检查这四道：

| id | 旧答案 | 新答案 | `top1Score` |
|---|---|---|---|
| `6aeb4375` | `"...report the value from the latest turn: four.\n\nfour"` | `"Let me work through this chronologically."` | 0.7033（相同） |
| `b6019101` | `"5"` | `"12"` | 0.6349（相同） |
| `e493bb7c` | `"bedroom"` | `"bed"` | 0（相同） |
| `32260d93` | 相同文本 | **逐字节相同的文本** | 0.5557（相同） |

`32260d93` 是决定性的：两个答案是同一个字符串，而判决不同。
这是 LLM 评判器或答案路径在 `temperature=0` 下不可复现，而非检索或确定性引擎的改动。
`6aeb4375` 以另一种形态显示了同一件事 —— 新答案泄漏了一段思维链前言
（`"Let me work through this chronologically."`），而旧答案没有，且检索完全相同。

**因此这 4 项损失不可归因于 P32/P33。** 它们是在没有这两项修复时也会出现的噪声。

## 5. 本次运行暴露出的工具缺口

**R4 消融实验臂不产生任何决策追踪**，而评分运行会。
`benchmark-conjunction-ablation-report.json` 中具体缺失的是：

1. **没有每臂每题 `expansionQueries`。** P1 在*从 R4 产物*的角度无法回答；
   P4 的机制（在 `and`/`or`/`vs` 上打碎）是被推断的而非被展示的。
2. **没有每题的基线正确性。** 该产物只保存 `featureCorrect`，
   因此那 3 道翻转的 IE 题**仅凭该产物无法被点名** ——
   识别它们需要离线重建范围内顺序。这是一个可复现性缺陷：该产物所包含的内容
   不足以审计其自身的不一致对。

在 R4 被重试或任何扩展改动被做出之前，该实验臂必须产出每臂每题的追踪，
携带扩展查询与两个判决。建造那个东西才是先决条件，而非重试。

注意评分路径已经具备正确的形态 —— `expansionQueries` 和
`retrieved` 上下文都在 `benchmark-single-session-diagnostics.json` 中。
缺口在于**消融**路径从未被赋予与评分路径相同的接线。
