# 检索融合与重排 —— 深度审计（P0）

**日期：** 2026-09-06
**目标：** 弥合与前沿（Hindsight / AgentOS / HydraDB /
AutoMem）之间的融合缺口，该缺口被 SOTA 格局报告认定为 cortex 最高杠杆的
缺失要素。

---

## 1. cortex 今天做什么（测量，而非假设）

cortex 在**四处**融合检索信号，且没有一处是倒数排名融合（RRF）：

| 位置 | 函数 | 当前融合 | 问题 |
| --- | --- | --- | --- |
| 会话多查询 | `retrieveByQueries` | 每个会话保留**最大**分数 | 丢弃了“被多个查询命中”的信号 |
| 回合多查询 | `retrieveTopKByQueries` | 每个回合保留**最大**分数 | 同上 |
| 回合召回 | `retrieveSessionsByTurns` | 每个会话保留**最大**回合 cosine | 单通道；最大归约已被证明在多证据下表现不佳（DCG 负面结果） |
| **MR 入口点** | `retrieveSessionsForQuestion` | 基础 + 扩展按**最大**合并；回合召回被**追加** | 跨通道分数不可比，因此最强的回合召回会话被强制排到尾部 |
| 单会话混合 | `retrieveTopKByQueriesHybrid` | **词汇优先级联**：关键词回合占据前 `MAX_LEXICAL_HITS` 个槽位，语义填充其余 | 不是排名融合；词汇“分数”（匹配数）与语义 cosine 处于不同单位 |

代码本身记录了核心缺陷（`retrieveSessionsByTurns`，约第 481 行）：

> “返回的分数是回合 cosine，与质心
> cosine 不可比……因此调用方必须按排名合并……
> 而非按原始数值排序。”

然而 MR 入口点并**不**按排名合并 —— 它追加，因此一个作为真实证据的回合召回
会话（在其通道中排名 1）会被排到每一个质心会话之后，包括干扰项。

## 2. 前沿做什么

RRF 把 N 个独立的排名列表融合为一个：

```
RRF(d) = Σ_{channel c} 1 / (k + rank_c(d)),  k = 60 (standard)
```

每个通道用其*排名*投票，而非其原始分数，因此分数尺度不同的通道
（质心 cosine 对回合 cosine 对词汇匹配数）变得可比。Hindsight 运行四个通道
（vector/BM25/graph/temporal）并对它们做 RRF 融合；AutoMem/AgentOS/HydraDB
都在重排之前对 BM25 + 稠密做 RRF 融合。

## 3. 根因 —— 一句话

**cortex 的检索通道没有任何一处是按排名融合的；它们要么被最大归约
（这丢掉了多通道一致性），要么被追加（这降级了最强证据所依赖的
回合召回通道）。**

这是一个纯函数、零依赖、可 TDD 的修复 —— 最干净的那类 P0。

## 4. 交叉编码器重排 —— 在此代码库中的可行性

cortex 是一个 TypeScript monorepo，**没有本地模型运行时**（嵌入与
LLM 都是远程 API）。因此交叉编码器有三个选项：

| 选项 | 成本 | 风险 | 判决 |
| --- | --- | --- | --- |
| 本地 ONNX 交叉编码器 | 模型下载 + 运行时 | 高（新依赖、构建体积） | ❌ 不是本次迭代 |
| LLM 作为重排器（DeepSeek 为每个候选打分） | 每查询 +1 次 LLM 调用 × top-k | 中（成本 + 延迟，但 Hindsight 交付的正是这个） | ⏸ 推迟，RRF 落地后评估 |
| 嵌入对重排（`[q, d]` 拼接 → 嵌入 → 打分） | 每候选 +1 次嵌入 | 低但信号弱（Zhipu 是双编码器，不是交叉编码器） | ⏸ 不是真正的交叉编码器 |

**决定：** 本次迭代只实现 **RRF 融合**（纯、低风险、高信号）。
交叉编码器重排是后续的 P1 —— 它是一个更大的改动，带有真实的依赖/成本决策，
且它应骑在 RRF 之上，而非替代它。

## 5. P0 计划（本次迭代）

1. 添加 `reciprocalRankFusion<T>(rankedLists: T[][], k = 60): T[]` —— 一个纯
   函数，接收每通道的*排名*列表（最优优先）并按 RRF 分数降序返回条目，
   按同一性去重。
2. 把 **MR 入口点**（`retrieveSessionsForQuestion`）改为按排名对
   三个通道（质心基础、扩展查询、回合召回）做 RRF 融合，
   而非最大合并 + 追加。
3. 把**单会话混合**（`retrieveTopKByQueriesHybrid`）改为对
   词汇与语义排名列表做 RRF 融合，而非词汇优先
   级联。

## 6. 测试计划（TDD，红 → 绿）

- `reciprocalRankFusion`：空列表、单列表、去重、
  排名加权（对选定的 k，一个在一个通道中排名 1 的文档胜过在两个
  通道中排名 2 的文档）、确定性，各自的单元测试。
- MR 入口点：一个在回合召回通道中排名 1 的会话绝不能被
  降到仅质心的干扰项之下；多通道一致性必须把一个
  会话升到单通道同类之上。
- 混合：词汇与语义投票融合；一个既有稀有关键词又有
  高 cosine 的回合，排名高于只有一个的回合。
- **变异测试**：删除 RRF 加权（回退到 max）必须使一个
  有判别力的测试失败。
- 阴性对照：计数题仍路由到枚举（未变）。
