## 2. 我关于“评估差距”的假设被证伪

我曾假设相当大一部分“错误”答案实际上是语义正确、但被评估器判为错误的（格式/逐字不匹配）。逐题 `correct` 标志表明这是 **false** — LLM 评判器工作正常：

| 预测值 | 金标 | 评判器判决 |
| --- | --- | --- |
| `The Nightingale` | `'The Nightingale' by Kristin Hannah` | **正确** |
| `Episcopal Church` | `the Episcopal Church` | **正确** |
| `JetBlue` | `American Airlines` | **错误**（真实错误） |

早先的“格式不匹配”信号是我自己粗糙的精确/首位数字分类器的产物，它无法复现评判器的语义等价性。**没有实质性的评估缺陷**需要修复。

## 4. 最大的可修复目标：TR 时长算术是确定性的

TR 时长错误在各次运行间完全一致地复现，因此它们来自确定性时间引擎，而非 LLM 采样：

| 题目 | 预测值 | 金标 | 备注 |
| --- | --- | --- | --- |
| days passed since car feedback | `37` | `38 days`（含首尾 39） | off-by-one |
| days ago attended baking class | `25` | `21 days`（含首尾 22） | off-by-4 |
| weeks since flu recovery | `12` | `15` | 金标不可达（先前分析） |

其中两个（`37` vs `38`、`25` vs `21`）是 `computeTemporalAnswer` 中的确定性日期算术错误 — 一个经典的含首尾/不含首尾天数计数或错误锚点日期缺陷。流感那道题（`12` vs `15`）是已知的金标不可达，而非引擎缺陷。
