## 1. 根因：MR 的瓶颈不是检索，而是算术

对三次 `8d87341` 运行的 121 道 MR 题（363 个答案）做逐题归因：

| 指标 | 值 |
|---|---|
| 平均证据会话召回 | **94.7%**（87.6% 的题达到 100% 召回） |
| "全部证据都已召回"的错误答案 | **73.7%** |
| "完全没有召回任何证据"的错误答案 | **2.6%** |

**检索基本已解决；剩下的就是聚合层的算术与枚举。** 证据就摆在模型眼前，它还是算错了：

```
gt=3      predicted=2       missed one item
gt=4      predicted=6       double-counted twice
gt=$5,850 predicted=$5,250  sum short by 600
gt=$720   predicted=$700    sum short by 20
```

把既有数值金标准又有数值预测的 257 个答案按问题类型拆分：

| 类型 | n | 准确率 | 错误数 | 算术错误（自身的枚举与自身的答案矛盾） | 枚举错误 | 无法解析 |
|---|---|---|---|---|---|---|
| COUNT（`how many items/times/people`） | 141 | 75.9% | 34 | **25（73.5%）** | 6（17.6%） | 3（8.8%） |
| SUM（`how much money` / `how many hours/days`） | 116 | 87.1% | 15 | **10（66.7%）** | 3（20.0%） | 2（13.3%） |

**模型自己列出的项与它自己给出的答案不符** —— 占全部计数错误的 70%。这不是知识问题，是
算术问题，而算术本不该交给 LLM。

---

## 2. 方法：把算术从 LLM 手里拿走

遵循已被验证的 P1.5 哲学（确定性相对时间换算）：**LLM 负责语义理解，代码负责它不擅长的
确定性计算。**

当前的 `buildAggregationQaPrompt` 让模型同时做两件事 —— 枚举证据（Step 1）与求和/计数
（Step 2）。它两件都做错。把它们拆开：

### 2.1 改动

| # | 位置 | 内容 |
|---|---|---|
| 1 | `buildAggregationQaPrompt` | Step 2 不再要求求和/计数；只要求**每项一行** `- <item> | <value>`，末尾保留一行 `Answer:` 作为回退 |
| 2 | 新增 `parseAggregationItems(raw)` | 把条目行解析为 `AggregationItem[] = { label: string; value: number \| null }`；剥离日期与年份，使 `2023/05/12` 不被当作数值 |
| 3 | 新增 `aggregateItems(items, question)` | **确定性**聚合：COUNT 类题取 `items.length`，SUM 类题取 `sum(items.value)`；当问题类型不明或某个值缺失时返回 `null` |
| 4 | `parseAggregationAnswer` | 优先"解析枚举 → 确定性聚合"；当它返回 `null` 时，**完全回退**到现有逻辑（`Answer:` 标签 → 最后一个非空行），签名与行为对现有调用方保持不变 |

### 2.2 为何必须保守（安全边界）

误分类是灾难性的：把一道 COUNT 题当 SUM 来求和，会把答案 `3` 变成 `2023+2023`。因此只在
高置信度下启用：

- **SUM 题**必须命中金额/时间单位信号（`how much`、`$`、`how many hours/days/minutes`、
  `total money/cost`），**且**所有项都必须带有可用的数值
- **COUNT 题**必须命中计数模式（`how many <items/times/people/...>`），**且**条目结构必须
  一致
- 任一条件不满足 → 返回 `null` → 回退到 LLM 的原始答案，**绝不猜测**

### 2.3 范围之外

枚举错误（17–20%）—— 模型漏项或多项 —— 无法用确定性算术修复；它们需要更好的召回与枚举
提示，属于另一次迭代。

## 4. 验收标准

| # | 验收项 | 阈值 |
|---|---|---|
| 1 | TDD | 先写失败测试（red），再实现（green） |
| 2 | 单元测试 | 增加 ≥ 15 个用例：COUNT/SUM 分类、日期剥离、数值解析、`null` 回退、边界（空列表、混合值、null 值） |
| 3 | 覆盖率 | 四个维度均 **≥ 95%**（Statements / Branch / Functions / Lines），无 mock |
| 4 | 本地回归 | lint / format / typecheck / 完整测试套件 / build 全部通过 |
| 5 | MR 准确率 | 相对同一时刻对照**显著改善**（Welch p < 0.05），同日 3 次运行 |
| 6 | 无回归 | IE / TR / KU / ABS 均不得低于对照 −1.0pp |
| 7 | 回退安全 | 诊断日志中"确定性聚合返回 null 并回退"的出现率必须记录并复核，确认无误用 |
| 8 | 连续三次命中 | 连续 3 次运行达到阈值；单次命中不算成功 |
