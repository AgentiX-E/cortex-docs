# P34 — R4 现已可度量：合取分解实验臂已存在

**状态：** 已实现、已测试、已接入 `bench/run.ts`。**尚未度量** ——
该实验臂会在下一次调度时产出其报告。

## 1. 此前缺失的是什么

R4 已预注册（`p27-r4-prereg.md`），其预测 P1–P5 已固定，且其
离线反例扫描已通过（§3.5：合取队列中没有任何一道题依赖单个回合同时承载两个操作数）。
它**没有**的，是一种度量自身的方式。

测试 R4 的唯一方式，是就地修改 `buildQueryExpansionPrompt`，而这：

- 会改变**全部 500 道题**的查询扩展，而非那约 7 道合取题；
- 使效应**不可归因**，因为同一提交同时改动了提示词及其下游的一切；
- 不留对照实验臂，因此增量只能被读作同一不可复现端点两次运行之间的“改动前 vs 改动后”。

这正是 `p24-cap-verdict.md` §4 所记录代价的错误 —— 一个提交里两处改动，
事后需要一次专门运行来把它们分开。R4 被有意地挡在了这一命运之外（`p27-r4-prereg.md` §5）。

## 2. 构建了什么

| 组件 | 原因 |
|---|---|
| `buildQueryExpansionPromptWith(question, { decomposeConjunctions })` | 参数化构建器；`buildQueryExpansionPrompt` 以关闭该标志的方式委托给它 |
| `NaturalLanguageMemorySystem.queryExpansionPrompt` | 让单个实验臂无需触碰调用点即可替换指令 |
| `runQueryExpansionDecompositionAblation(...)` | 实验臂：`conjunction-fused` 对 `conjunction-decomposed` |
| `BenchmarkRunnerOptions.capabilities` | 按能力码限定实验臂范围 |
| `bench/run.ts` 接线 | 写出 `benchmark-conjunction-ablation-report.{md,json}` |

### 2.1 默认提示词逐字节相同

在实验臂被读取之前，评分路径不得移动。`buildQueryExpansionPrompt`
以 `decomposeConjunctions: false` 委托给新构建器，且这一同一性被**断言** ——
`buildQueryExpansionPromptWith(q, {})` 必须等于
`buildQueryExpansionPrompt(q)`，且默认提示词不得包含 `TWO OR MORE`。

### 2.2 该选项不能泄漏进时间路径

`expandQuestion` 从每个调用点接收一个显式的 `expansionPromptBuilder`，其中五个
传入它们自己的事件级构建器（`buildTemporalQueryExpansionPrompt`、MR/推导变体）。
若该新选项被无条件应用，它将**静默替换系统中的每一个扩展提示词**，
破坏时间实验臂却没有测试失败。

因此，仅当调用方传入**默认**构建器（按同一性识别）时，该选项才被应用：

```ts
const builder =
  promptBuilder === buildQueryExpansionPrompt
    ? (this.options.queryExpansionPrompt ?? buildQueryExpansionPrompt)
    : promptBuilder;
```

扩展缓存键此前已使用 `builder.name`，因此它现在以解析后的构建器为键 —— 两个实验臂
不会冲突，且一道在两个实验臂中扩展结果完全相同的题，绝不会被重新发送给提供方。

### 2.3 限定范围是关键，而非便利

该实验臂默认 `capabilities: ['ABS', 'IE']`。

该机制只影响少数几道合取题。在 500 道上取平均，+1pp 的效应是 5 道题，会淹没在模型噪声中 ——
这正是 TR 实验臂的零结果不具信息量的原因（P30 §3）。ABS 是目标人群；
IE 是单操作数题的最大集合，也正是分解必须**不造成损害**之处，因此它同时充当附带损害检查。

### 2.4 该指令保留了融合短语

> “为每一个列出单独的一条短语，**外加组合短语**”

离线扫描发现队列中没有任何一道题依赖单个回合同时承载两个操作数，因此保留它毫无代价，
并消除了唯一被识别出的回归风险 —— 即两个操作数确实在同一回合共现的语料。
这是 R4 对 P3（“无附带损害”）的回答：不是一种希望，而是一种构造。

## 3. 测试 —— 九项，以及真正重要的那两项

提示词层（5 项）：
- 默认提示词必须**不**携带该指令；
- 分解变体必须携带它；
- 它必须保留融合短语；
- 它必须是**恰好多出两行的严格超集** —— 这样消融比较的是一条指令，而非一个被重写的提示词；
- 标志关闭时与默认逐字节相同。

实验臂层（4 项）：范围、变体标签、温度/评判转发，以及两个实验臂都
**记录弃权**（P30 缺陷，同样钉在新实验臂上）。

那两项具有超出“字符串存在”之外力度的测试：

1. **严格超集测试。** 一个丢弃了某条共享指令的提示词重写，会用一处无关改动混淆比较。
   该测试计算两个提示词的差异，并要求恰好两行新增。
2. **实验臂发送不同提示词的测试。** 两个实验臂共享一个扩展缓存。若两个实验臂
   对那道合取题产出了*相同*的提示词，缓存就会把对照组的短语提供给处理组，
   增量便什么都测不到 —— 这正是本仓库已经命中过一次的那种遮蔽失效（`p5-pairing-verdict.md`）。
   该测试断言处理组的提示词包含 `TWO OR MORE` 而对照组的不包含，因此差分是被验证过的，而非被假定的。

该标志被失效处理（`=== true` → `false === true`），以确认提示词测试并非空转：
**3 项失败，3 项通过**。恢复后，全部通过。

门禁：**972 项测试通过**（cortex-eval 826）。覆盖率 99.84 语句 / 98.67 分支
/ 100 函数 / 99.84 行；任何位置的分支最低值为 97.26%。
