# P16 判决 — 不稳定桶分解为三种机制

**状态**：分析完成。识别出一个可执行的缺陷（违反弃权契约）；修复设计见 P17。三种机制中有
两种**不是**引擎缺陷，必须从引擎的错误预算中排除。

## 1. 背景

P14 §1 在 121 个 MR 问题中测得 30 个不稳定问题（8 次运行中正确 1–7 次），而 P14 §8 把"降低
运行间方差"列为剩余的最大奖品。那一排序基于该桶的*规模*。本判决通过按机制分解该桶，来检验
它是否*可执行*，因为一个由采样噪声驱动的桶与一个由可修复缺陷驱动的桶需要相反的应对。

## 2. 第一刀：是引擎在变化，还是只有模型在变？

对每个不稳定问题，我在全部 8 次运行中哈希了所构建的提示（`decision.retrieved`）。

| 8 次运行间的提示 | 问题数 |
|---|---|
| 逐字节相同 | **5** |
| 有变化 | **25** |

有五个问题在**逐字节相同的提示**上正确/错误翻转。对它们而言，检索、截断和阈值都是恒定的，
因此翻转只能来自 LLM 自身的输出。例如 `2788b940`（"How many fitness classes do I attend
in a typical week?"，gold `5`）：

| 运行 | 答案 |
|---|---|
| 0,2,4,5,6,7 | `4` |
| 1,3 | `5` |

该 gold 分解为 Zumba（周二、周四）= 2 + BodyPump（周一）= 1 + Yoga（周日）= 1 + Hip Hop Abs
（周六）= 1 = **5**，四个证据会话都在提示中。模型在八次运行中的六次回答 `4`。**没有任何
引擎变更能解决这个**；它是阅读器中的计数不稳定。

## 3. 第二刀：变化的是什么——答案，还是弃权？

按*差异是什么*对 25 个提示有变化的问题做细分：

| 变化的东西 | 问题数 |
|---|---|
| 答案文本本身 | 23 |
| **弃权 ↔ 作答，且答案本身始终正确** | **7** |

这七个是有趣的集合，因为模型在作答时*从不错误*：

| 问题 | 作答时给出的答案 | gold | 与 gold 相同 |
|---|---|---|---|
| `51c32626` | `February 1st` | `February 1st` | 是 |
| `80ec1f4f` | `2` | `2` | 是 |
| `a96c20ee` | `Harvard University` | `Harvard University` | 是 |
| `ba358f49` | `33` | `33` | 是 |
| `c18a7dc8` | `7` | `7` | 是 |
| `d3ab962e` | `8 miles` | `8 miles` | 是 |
| `gpt4_31ff4165` | `4` | `4` | 是 |

与 P14 §4 的四个始终弃权问题形态相同，但是*部分的*：模型在某些运行中弃权、在另一些运行中
正确作答。损失完全在于弃权，从不在于错误答案。

## 4. 第三刀：弃权是违反契约，而非一次判断

我按 `llmRaw` 的形态对全部 968 个 MR 决策中的每一次弃权做了分类：

| 弃权时的 `llmRaw` | 数量 |
|---|---|
| **裸 `UNANSWERABLE`，少于 40 字符，无推理** | **35** |
| 有推理的弃权（先枚举，再断定信息不足） | 27 |
| — 已作答 | 906 |

裸形态是一个 12 字符的字符串，没有 Step 1、没有 Step 2。但 `buildAggregationQaPrompt`
指示：

> Work in two steps.
> Step 1 — Enumerate every item matching the question's EXACT action, one per line
> Step 2 — Compute the final answer exactly as the question asks
> End your response with a single line in the exact form: `Answer: <final answer>`

**模型跳过了给它的协议。** 弃权条款提供了一个逃生舱——*"Respond with exactly
UNANSWERABLE ONLY if the context contains no relevant information at all"*——而模型
在未做本会揭示信息其实存在的那次枚举的情况下就使用了它。

最干净的单一案例是 `d3ab962e`（"total distance of the hikes I did on two consecutive
weekends"，gold `8 miles`）：

| | run0（失败） | run1（通过） |
|---|---|---|
| 提示哈希 | `dd2b1c7df5` | `dd2b1c7df5`（**相同**） |
| 扩展查询 | `['hike on first weekend','hike on second weekend']` | 相同 |
| 阈值取值 | `0.636338` | `0.605569` |
| `llmRaw` | `UNANSWERABLE`（12 字符） | `Step 1 … 5-mile hike … 3-mile loop … Step 2 … 5 + 3 = 8 miles` |

注意失败的那次运行拥有**更高**的阈值分数，因此数值守卫不是原因。引擎交给模型一段相同且完整的
提示，而模型拒绝去读它。八次运行中有七次产出了那个推导。

35 次裸弃权按问题汇总：

| 问题 | 裸弃权次数 | 备注 |
|---|---|---|
| `8e91e7d9` | 8 | 召回 — 证据缺失（已修复，`c4ab77b`） |
| `10d9b85a` | 4 | 召回 — 稀释（P13 §6） |
| `37f165cf` | 4 | 基准缺陷 — 不可满足的前提（P12） |
| `gpt4_31ff4165` | 3 | 违反契约 |
| `51c32626` | 3 | 违反契约 |
| `80ec1f4f`、`ba358f49`、`5a7937c8`、`1192316e` | 各 2 | 违反契约 |
| `6cb6f249`、`bf659f65`、`d3ab962e`、`c18a7dc8`、`gpt4_15e38248` | 各 1 | 违反契约 |

减去其弃权已有已知上游原因的这三个问题（`8e91e7d9`、`10d9b85a`、`37f165cf`），
**共 11 个问题因违反契约而损失运行**。

## 5. 三种机制及其处置

| 机制 | 问题数 | 可执行？ |
|---|---|---|
| 相同提示上的推理/计数不稳定 | 5 | **否** — 阅读器能力，而非引擎 |
| 答案不稳定（模型算出不同的值） | 23 | **大多否** — 阅读器能力与残余证据问题的混合 |
| **裸 `UNANSWERABLE` 违反契约** | **14（净 11）** | **是** — 一个提示契约缺陷，测试上是确定性的 |

## 6. 诚实的上限

- 那 5 个相同提示翻转确立了本基准、本阅读器上的一个**地板**：约 5/121 = 4.1% 的 MR 准确率
  是任何引擎变更都无法触及的。
- 那 23 个答案不稳定问题在此不被声称为可修复。其中一些可能仍是证据缺陷，但不稳定性本身不是
  这一点的证据，而我没有任何测量能把二者分开。
- 违反契约的计数（净 11 个问题）是影响的一个**上**界。移除逃生舱无法保证模型随后会正确枚举；
  它只能移除未读就拒答的选项。因此验收测试必须断言*机制*（在冻结案例上不再出现裸弃权），
  而非准确率。
- `37f165cf` 仍是一个基准缺陷，留在预算之外。`8e91e7d9` 与 `10d9b85a` 的上游原因已被修复
  或诊断，因此它们的弃权应当因独立原因而消失。

## 7. 方法说明

全部数字来自 8 个冻结的 `ab_rrf/run_*` 诊断加上 `/tmp/lme-data/lme.json`；未做任何实时模型
或嵌入调用，因此该弃权普查可从已提交的产物复现。裸弃权分类器刻意做成机械式的——`llmRaw`
以 `UNANSWERABLE` 开头且少于 40 字符——因此它无法被调到一个想要的计数上。
