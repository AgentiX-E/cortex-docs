# P5 计划 —— 在任何进一步特征工作之前确立测量噪声底

## 目标

P4 以一个无法据以行动的结果收尾：两个实验臂在两次运行中处于噪声底、方向相反，
而且 —— 远为更重要的是 —— **在一个逐字节相同的配置上，两次运行之间出现 25 道题
/ 5.0 pp 的漂移**（`34389565513` 对 `34492139716`）。最近每一份判决都在依据一个
*单次运行内*测得的 2 道题 / 1.57 pp 噪声底来推理。若运行间离散度真的是约 5 pp，
那个噪声底就错了一个数量级，且任何 ≤25 道题的实验臂都不可解读。

因此本次迭代**不**构建特征。它测量噪声底。

验收不是“某个特征提高了准确率”。而是：**一个可辩护、有测试支撑的运行间离散度数字，
以及在那个尺度上重述的决策规则。**

## 为何这必须先行

现在设计第六个 TR 特征，会重复 P4 所揭示的确切错误：
产出绿色的运行，而其中的数字无法支撑从它们得出的结论。P4 的实验臂改变了 2 道题；
端点在各次运行之间移动 25 道。在这一点被定量之前，特征工作是不可度量的。

## 计划

### 1. 直接测量运行间离散度

**完全相同**配置的三次运行（不启用任何 P4 特征，因为两者默认关闭）、`limit=0`、
`deepseek-v4-flash`、`thinking=disabled`、
`temperature=0`、`runs=1`：

- `34558715449`、`34558717704`、`34558719936` —— 已调度。

结合 `34492139716`，这给出每个能力码 **4 次同配置观察**，这是至少要报告一个离散度
所需的最小值（也是 `cohensD`/`tTestPValue` 的最小值，它们在 n<2 时返回 0 而非撒谎）。

### 2. 添加一个真实的、有测试的分析库

`cortex-eval` 中新增 `src/variance.ts`，从包根导出：

- `summarizeVariance(observations)` → 按能力码与总体的
  `{n, min, max, mean, sd, range, spreadPp, minCorrect, maxCorrect}`。
  关心的量是**以题数计的极差与 sd**，因为那才是实验臂必须超过的东西。
- `compareQuestionVectors(a, b)` → 在*相同*配置的两次运行之间有多少题改变了状态
  （`stable`、`flippedIn`、`flippedOut`）。这是不一致对计数的同配置对应物，
  是端点不稳定性的直接度量。
- `requiredEffectSize(variance)` → 越过噪声底的最小实验臂效应，
  其推理被编码在类型里而非注释里。

一切先以题数报告、百分比其次：百分比会隐藏样本量，而样本量正是 P4 弄错两次的东西。

### 3. 接受判决并重述规则

把决策规则更新到运行间尺度，并明确陈述它使哪些过去的判决失效。
若某次过去的提升是依据旧噪声底下的单次运行比较，就如实说明。

### 4. 全程 TDD

实现前先写测试，覆盖每一个分支：空输入、n=1、n=2、
全稳定、全翻转、非对称翻转，以及与现有
`aggregate`/`cohensD` 辅助函数的交互。四个维度均 ≥95%。

## 验收标准

1. 四次同配置运行绿通过并产出产物。
2. `variance.ts` 交付并带测试；**语句、分支、函数、行覆盖率 ≥95%**，
   无跳过、不 mock 统计量本身。
3. 按能力码与总体的量化运行间离散度（题数与 pp）。
4. 决策规则在一份文档中以运行间尺度重述，并写明它现在要求实验臂越过的那个数字。
5. `pnpm build` + `pnpm check` 绿通过；以 `Lambertyan` 提交，提交信息为英文，
   注释/文档全程英文。

## 明确的非目标

- 提升任一 P4 特征。两者都保持默认关闭：两者都未越过噪声底，而噪声底刚刚移动了。
- 构建任何新的 TR 特征。
- 改动评分路径。本次迭代是测量基础设施；已发布的数字必须逐位相同。

## 风险

- **若端点随时间劣化，四次运行就并非真正相同。** 缓解：既按聚合也按时间顺序
  报告这些运行，使单调趋势（漂移）可与平稳噪声区分开。漂移与噪声意味着不同的修复。
- **n=4 对 sd 而言是小样本。** 缓解：把极差作为主要数字（小 n 下稳健）、
  sd 作为次要，且不计算 n=4 无法支撑的置信区间。
