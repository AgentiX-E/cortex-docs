# P4 运行 34479855027 —— 调度缺陷，而非特征结果

**判决：无效运行。** 下面的 `+0.00%` 增量是调度参数的产物，而非 P4 特征的性质。
不得从本次运行得出任何关于时间窗口标注或引擎改进的结论。

## 观察到了什么

| 实验臂 | 数据集 | n | 基线 | 特征 | Δ | 不一致对 |
|---|---|---|---|---|---|---|
| 引擎改进 | `longmemeval-tr-deterministic` | 8 | 87.50% | 87.50% | +0.00% | 0 / 0 |
| 时间窗口标注 | `longmemeval-tr-annotated` | 8 | 87.50% | 87.50% | +0.00% | 0 / 0 |
| 主 TR（引擎消融） | `longmemeval-tr` | 8 | 87.50% | 87.50% | +0.00% | 0 / 0 |
| KU 双时间 | `longmemeval-ku-temporal` | 1 | 100% | 100% | +0.00% | 0 / 0 |

每个实验臂都报告**零不一致对**，包括那个历史上报告 +11.02 pp 的*主* TR 消融。
四个独立实验臂上出现真正的零结果是不可能的；处处零不一致对意味着这些实验臂
根本无法移动。

## 根因

本次运行以 `LIMIT=60` 调度。`sampleInstances` 按 `sampleBucketKey`
（每种问题类型为 `IE:*`，否则就是裸能力码）在能力桶间轮转，因此一个 60 实例的样本
被稀薄地摊在五个能力码上。TR 收到了 **8** 个实例，其中只有 **8** 个
带有 `question_date` —— 恰好就是喂给两个 P4 实验臂的那 8 个。

对比 P3b 运行 `34389565513`，它以 `limit=all` 调度：

```
Running benchmark on 500 instance(s) (limit=all, ...)
- Dataset: `longmemeval-tr` (127 questions)
```

`limit=all` 产出 **127 道 TR 题**；`LIMIT=60` 产出 **8** 道。因此 P4 实验臂
只跑在可用 TR 信号的约 6% 上 —— 远低于任何能分辨效应的水平，
甚至低于此前测得的那 2 道题的同配置噪声底。

完整的 LongMemEval-S 普查，供参考：

| 能力码 | 题数 |
|---|---|
| IE | 150 |
| MR | 121 |
| KU | 72 |
| TR | 127 |
| ABS | 30 |
| **合计** | **500** |

在 `LIMIT=60` 下，轮转大致分配每个能力码 12 道，随后 TR 的带日期子集
（`capability === 'TR' && questionDate`）又把它砍到 8。

第二个相关的饥饿：`longmemeval-ku-temporal` 在这次调度下只收到一道题，
因此 KU 双时间实验臂同样不具信息量。

## 为何这值得记录

该失效模式是静默的。工作流变为**绿色**，每一步都通过，每份报告都渲染为
一张格式完好的消融表，带有置信区间和一个 McNemar p 值。输出中没有任何东西
说“n=8 太小，检测不到任何东西”。`0 / 0` 那一列不一致对是唯一的线索，
而它很容易被读作真正的平局。

这与早先 `benchmark.yml` 产物路径 bug 属于同一缺陷类别：运行*成功*，
却产出了无法支撑它所看似支撑的结论的证据。两者都只是通过阅读数字、
而非阅读退出状态才被捕获。

## 常设规则

每份消融报告都必须带着它的 `questionCount` 一起阅读，而一个样本太小、
无法超出所测噪声底的实验臂，必须在其增量被解读之前标记为不确定。
工作流绿色不是实验具有充分功效的证据。

## 补救

以运行 `34481475313` 重新调度，用 `limit=0`（完整 500 实例数据集），
这恢复了 127 道题的 TR 人群。两个 P4 实验臂随后报告了非退化结果
（见 `p4-verdict.md`）：分别为 4 对和 2 对不一致对，而在饥饿调度下为 0 和 0。

这一对比是对该缺陷最清晰的陈述。同样的代码、同样的工作流、同样的 LLM ——
只有样本量不同，而它把实验臂从“没有任何题能变化”带到了可测量地改变结果。
