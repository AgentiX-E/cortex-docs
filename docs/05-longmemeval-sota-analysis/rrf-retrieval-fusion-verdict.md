## 1. 两轮，一个修复

| 轮次 | 处理 | 结果 |
| --- | --- | --- |
| v1 (`e50c554`) | 仅 RRF 融合 | **拒绝** —— IE 弃权 3-4 → 每次运行 14-15，准确率 95.0% → 87.5%（44 次虚假的 `threshold` 弃权，cosine 0.41–0.50） |
| v2 (`afd5dd5`) | RRF 融合 + 弃权解耦 | **接受**（见下） |

v1 的回归是被根因定位的，而非被掩盖：RRF 按多查询一致性重排命中，
因此 `hits[0]` 不再是 cosine 最强的回合，而单会话路径把
`hits[0].score` 读作弃权置信度。该修复把两者解耦 —— RRF 决定顺序，
`maxHitScore(hits)` 决定置信度 —— 且 `retrieveTopKByQueries` 把每个命中的分数
重写为其跨查询的最大 cosine。

## 3. 归因

- **MR +5.25/次运行完全可归因于 RRF 融合**（`retrieveSessionsForQuestion` + `retrieveByQueries`）：MR 路径的弃权信号从未被改动（仍是对质心 cosine 的 `hits[0].score`），因此该增益是纯粹的召回顺序改善。
- **IE 回归由解耦修复**（`maxHitScore` + 分数=最大 cosine）：弃权回到 3-4 → 4-5，准确率回到噪声之内。
- **TR −1.00/次运行是噪声**，不是回归：在下降方向上的精确置换 p = 0.90，幅度低于运行内离散度（2–4 道题）。
- **KU/ABS 守卫保持**（n.s.）。

## 4. 为何这是正确的架构（对照 DCG 的负面结果）

早先的 DCG 实验拒绝了*在单个回合召回通道内部的排名折扣累加* ——
它让噪声较大的中等相关回合在单事实 MR 题上压过那单个强证据回合。
RRF 不同：它按排名融合*通道*（质心对扩展对词汇），
使跨通道一致性被计入，而不丢弃最强的单通道证据。MR 那 +5.25/次运行的增益
经验性地确认了这一区别。
