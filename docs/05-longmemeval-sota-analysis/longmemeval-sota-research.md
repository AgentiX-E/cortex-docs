## 2. 缺口在于阅读器 + 检索，而不在于提示词微调

排在我们之上的系统可拆成两档杠杆：

1. **阅读器模型。** 在相同架构下，Claude/GPT-5/Gemini 阅读器比 GPT-4o 级阅读器高出约
   6–12pp。我们受限于 DeepSeek，因此这一杠杆对我们而言基本关闭。
2. **检索架构。** 开源前沿方法对此毫不隐晦：
   - **EmergenceMem（86%）**：轮次级检索，然后 **NDCG 会话打分** +
     **交叉编码器重排** —— 整个*会话*由轮次排名检索而来，而非一个质心嵌入。
   - **AgentOS（85.6%）**："canonical-hybrid retrieval" + 一个**按类别的阅读器路由**
     （每个能力使用不同的阅读器配置）。
   - **HydraDB（90.79%）**：时间感知的版本化图 + 双键索引 + 混合 BM25/稠密 + 查询扩展。

共同线索是：**带重排与类别感知路由的轮次级粒度检索**，而非单次质心相似度。

## 4. 这对下一次迭代意味着什么

我们已经拥有部分前沿组件（轮次级召回通道、混合检索、查询扩展）。剩余的最高杠杆缺口是
**带重排/会话打分的轮次级粒度检索质量** —— 而这恰恰是驱动 MR 与 TR 的轴，它们是我们
最大的两个类别缺口，也是剩余错误属于检索/提取质量而非确定性算术的所在（正如上一份审计
所示）。

**建议（下一次迭代）：** 针对两项具体的前沿技术深度审计我们的 MR/TR 检索栈 ——
1. **NDCG 式会话打分**（以会话各轮次的排名给会话打分，而非用其质心嵌入），以及
2. 上下文组装前的**重排 / 轮次去重** ——

然后在 MR/TR 机制端点上对杠杆最高的一项做 A/B。这是一次检索架构迭代，而不是又一次单题
提示词修复。
