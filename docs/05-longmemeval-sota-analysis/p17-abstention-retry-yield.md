# P17 — 弃权重试：它实际值多少，以及如何认证它

**问题。** 上一次迭代交付了一个裸弃权重试（提交 `236ab1b`）。本次迭代回答：它买来多少 MR
准确率，以及什么实验能证明它？

**答案。** 大约 **+1.2 pp**（90% 区间 `[0.83, 1.65] pp`）。单次配对运行**无法**认证它——
功效为 0.4%。**8 次配对运行**达到约 98% 的功效（实测 97.7%）。该修复在结构上无损，因此交付
并测量它是安全的；但在一次运行上*宣告*它是不安全的。

---

## 1. 早先"+1.86 pp"这个数字为何是错的

上一次迭代报告了一个 +1.86 pp 的上界，其推导方式是数出"裸弃权与同一问题的正确答案共存"的
运行数。那个计算没有任何关于二者*为何*共现的模型。它回答的是"在多少次运行中恢复是可能的"，
而非"在多少次运行中重试会实际恢复"。

两个不同的错误：

- 它没有**重掷（reroll）**的概念。重试从同一提示再抽一个样本。那个样本可能再次落到裸弃权。
  一个忽略了这一点的界不是重试的界。
- 它是在它本要据以预测的**同一些抽样**上计算的。在同一个样本集上既拟合又评分，正是你制造
  乐观估计的方式。

## 2. 面板及其审计轨迹

8 次运行，`ab_rrf/run_34024{727400,729633,732117,734868,737250,740818,743185,745627}`。
每一次都带有含 121 个 MR 实例的 `benchmark-mr-diagnostics.json`。

在任何推断之前先行验证：

| 属性 | 值 |
|---|---|
| 运行数 | 8 |
| 每次运行的问题数 | 121（全部运行） |
| 各运行的问题 id 集合相同 | **是** |
| 决策数 | 968 |
| 逐次运行 MR 准确率 | 71.90 – 81.82 %，均值 **79.13 %**，离散度 **9.92 pp** |
| 稳定正确 / 稳定错误 / 不稳定 | **78 / 13 / 30** |

这个 78/13/30 的划分精确复现了早先 P14 的分析，这是一个有用的交叉检查，表明是同一个面板。

## 3. 翻转是模型侧的，而非输入侧的

对每一个（问题，运行），诊断都存有确切的 `retrieved` 上下文。哈希
`question + "\0" + retrieved` 得到一个提示指纹，因此弃权与正确答案之间的一次翻转可以被归类
为*相同输入、不同输出*或*不同输入*。

**14 个**裸弃权问题中有 **8 个**在**逐字节相同的提示**上翻转。例如：`d3ab962e`，指纹
`a10d18c64f77`，8 次观测：**1 次裸弃权，7 次正确**。

这是承重的事实。因为提示相同，差异来自采样。因为差异来自采样，重掷就携带信息——这正是重试
的全部前提，是测出来的而非假设的。

另外 5 个（`5a7937c8`、`10d9b85a`、`bf659f65`、`ba358f49`、`37f165cf`、`8e91e7d9`）按
指纹有变化，因此它们的翻转部分是输入驱动的，不是干净证据。

## 4. 六个估计量，以及哪些有效

重试的期望增益为 `E = Σ_g bare_g · θ_g · p(correct | answered, g)`，其中 `g` 遍历所有曾
产生裸弃权的提示分组。争论完全在于 `θ_g`：一次重掷*作答*而非再次弃权的概率。

| # | 估计量 | 增益 | 有效？ |
|---|---|---|---|
| M0 | 朴素合并（拟合抽样 == 评估抽样） | 7.71 pp | **否** — 同一批抽样既拟合又评分 |
| M1 | 逐组 MLE `ans/(ans+bare)` | 4.37 pp | **否** — 样本内；全裸组的 θ 静默为 0 |
| M2 | 逐组 Laplace `(ans+1)/(n+2)` | 4.26 pp | 已软化，但仍为样本内 |
| CV-a | 留一次运行，**观测值** | 1.03 pp | **有效**，但保守 |
| CV-b | 留一次运行，**预测值** | 2.11 pp | **有效** |
| SIM | 机制模拟，4 次拟合 + 4 次留出运行 | **1.22 pp** | **有效** — 即点估计 |

### 4.1 为什么 CV-a 是一个下界

CV 只有在*训练*运行显示出该组的一次正确抽样时，才把一次留出裸事件记为可恢复。一个在留出运行
和训练运行中都是裸的事件会被记为 0——即使一次重掷很可能修复它。**35 次**裸事件中有 **16 次**
恰好处于这一位置。CV-a 看不到它们，因此它偏低。

### 4.2 为什么模拟是点估计

SIM 在 4 次运行上按组拟合结果分布（裸弃权 / 正确 / 错误），随后对每一次留出裸事件从该分布中
重采样——这正是一次重掷实际所做的事。它诚实地处理全裸组：它们拟合出的分布是 `bare: 1.0`，
因此它们产出 0，而这是*关于证据的一个陈述*，而非一个假设。

```
per held-out run: 1.48 recovered  (90% PI [1, 2])
                = 1.22 pp MR accuracy (90% PI [0.83, 1.65] pp)
```

（用 `node analysis/scripts/p17_reproduce.mjs analysis` 复现；RNG 已设种子，因此点估计稳定
在 1.48。）

`|A| = 10, |B| = 0, |C| = 4`——十个问题可认证（在某些运行中裸弃权、在另一些中正确），零个
是"从不损失"，四个是不可能的（在任何运行中都不正确）。那四个不可能的问题携带了 **35 次**裸
事件中的 **17 次**，这就是为什么朴素估计大约是诚实估计的两倍。

## 5. 改变计划的结果：对称噪声摧毁功效

我最初用 `p_loss = 0` 模拟功效，在 8 次运行上得到 98%。那是一个假设，不是一次测量，而值得
明确指出它所掩盖的失效模式。

模型为 `b ~ Bin(R·n, p_gain)`、`c ~ Bin(R·n, p_loss)`，其中 `p_gain = 1.22 pp`，随后对
`b | b+c` 做精确 McNemar。McNemar 的功效来自**不对称性** `b − c`。若 `p_gain = p_loss`，
则 `E[b−c] = 0`，于是：

| R 次运行 | p_gain = 1.22%, p_loss = 0 | p_gain = p_loss = 1.22% |
|---|---|---|
| 1 | 0.4 % | 0.2 % |
| 3 | 28.5 % | 2.0 % |
| 5 | 74.7 % | 2.6 % |
| **8** | **97.7 %** | 3.0 % |
| 10 | 99.7 % | 3.0 % |
| 20 | 100.0 % | 3.7 % |
| 30 | 100.0 % | 3.7 % |

对称列**在约 α 处进入平台**。再多的运行都无济于事，因为在期望为零的量上，更多运行只能买到
精度。这就是陷阱：一个不稳定的模型与自身相比，产生出一个无法认证的修复，无论它看起来多么
干净。

### 5.1 为什么引擎尽管如此仍处于增益仅有的区间

若重试可能**丢失**一个对照答对的问题，对称行就会适用。从结构上讲，它不能：

- 重试**仅**在第一次通过是裸弃权时触发；
- 重试**仅**在解析出一个非弃权答案时才被接受；
- 一次正常的第一次通过答案**从不**被重新提问。

因此 `p_loss = 0` 是构造使然，不是假设，且增益仅有的那一列主导。这值得作为一个设计属性来
陈述：**重试是单向的，而这正是它可测量的原因。** 一个无条件重新提问的重试，将是一次没有可
认证平均效应的方差再分配。

## 6. 认证协议

| 协议 | 运行数 | 功效 | 判决 |
|---|---|---|---|
| 单次配对运行 | 1 | 0.4 % | 无价值 — 不要报告 p 值 |
| 3 次配对运行 | 3 | 28.5 % | 功效不足 |
| **8 次配对运行** | **8** | **97.7 %** | **推荐** |
| 10 次配对运行 | 10 | 99.7 % | 充裕 |

两个实验臂，MR 子集，**仅**在 `enableAbstentionRetry` 上不同。两条硬性约束：

1. **分离的答案缓存。** `runner.ts` 在基线系统与特性系统之间共享一个 `answerCache`，并指出
   约 447/500 次调用被复用。若两臂共享它，处理臂会复用对照的缓存裸弃权，重试从不触发，而
   实验会报告一个干净的、完全虚假的 0.00 pp。
2. **两臂都保留。** 比较是按问题配对的；一个聚合对聚合的差会被 9.92 pp 的运行间离散所淹没。

因为重试大约在每次运行的 121 个 MR 问题中的 4 个上触发，所以*触发计数本身*在小 R 时是一个
比准确率 delta 更有信息量的诊断：一个显示零次重试触发的臂是坏的，而不是中性的。

## 7. 本文件未了结的问题

- **第二次**重试是否值得。收益递减很可能存在——全裸组显示出至少四个问题，模型反复拒答——但这
  个面板无法区分"拒答两次"与"不幸地只拒答一次"。- 四个 type-C 问题（`8e91e7d9`、
  `10d9b85a`、`37f165cf`、`bf659f65`，17 次裸事件）。它们在任何运行中都**不**正确，因此它们
  根本不是重试的目标；它们是召回或推导失败。它们属于残余召回工作流，不属于这里。
- 该效应是否在 TrainTicket / SockShop 上成立。本面板只是 OnlineBoutique 风格的 LongMemEval。

## 8. 方法说明

上文每一个数字都可从 `ab_rrf/*/longmemeval-s-report/benchmark-mr-diagnostics.json` 复现，
无需任何 API 调用。那个错误的估计量（M0，7.71 pp）之所以错，是因为它对拟合和评分使用了同一
个样本集；它被刻意保留在表中，作为有效估计量必须落在其下方的上界——而它们确实如此。
