## 0. 结论先行

1. **领域状态**：记忆的"外存"（存、检）在 2026 已基本解决；"大脑"（何时记、记什么、如何忘、
   怎么用、能不能说）才刚破题。权威综述把 memory automation、RL 集成、多模态、多智能体、
   可信性列为五个前沿空白 `[文献]`。
2. **定位**：Cortex 不是"又一个向量记忆库"，而是**价值驱动的认知记忆层**，并把**"这条能不能
   离开设备"**作为一等公民 —— 后者是 2026 年唯一被量化证伪到不能交给模型的决定（§5.3）。
3. **复刻 ≠ 融合**：Mem0 的通用抽取、Letta 的 Agent 自主、Zep 的时序图谱、A-MEM 的自组织、
   Mem-π 的参数化是五条**相互排斥**的架构赌注。Cortex 选"检索式可溯源 + 价值驱动 + 异步巩固"
   为主线，其余以可插拔策略实现。
4. **复刻对象已收敛到一个**：Exabase M-1 —— 用比竞品小 4–6 倍的阅读器拿到 LongMemEval
   **96.4%** `[厂商]`，且主动披露基准噪声底。它证明**管线 > 阅读器**，因此我们的资源投向
   数据结构而不是换模型。**注意：该结论对 cortex 自己的管线尚未验证**（§7 第 6 条）。
5. **当前读数（诚实版）**：采纳配置下名单均值 **405.0 / 500**（397–412，四次重复
   `[实测] 39367801501`），与同管线参考管线的 224 相比 IE/KU/ABS/TR 全面领先，**唯独 MR 落后
   约 20 题**（84.25 对 105）。**"超越所有竞品"因此不成立**，且不得对外宣称。
6. **设计阶段新增的三条产品事实**（都有 POC 支撑）：端侧能跑（OPFS 跨浏览器重启保数据、
   6 万条向量 22.3 ms p50 `[POC-1]`）；隐私不是承诺而是"数据不出去"；**知识卡片队列是主路径
   而不是异常路径** —— 规则层只裁决约**四分之一**的候选事实（60 条上 26.7%、1,467 条上 28.4%）`[POC-4]`、`[POC-6]`。
7. **测量本身要挑宿主**：两条被记为"不可能在本环境测量"的缺口，其实都是**宿主问题而非设计问题**
   —— Safari 在 macOS runner 上有，Hub 语料在 CI 里能取；真正的阻塞是**仓库可见性**。设为 public
   之后两条链一次跑通，Safari 26.6 与 3,000 条语料同时到手（§1.1、§7 第 9 条）。
8. **"多标 600 条"不是唯一的出路，但也不能被模型替代**：场上的权威基准（CIMemories）自己的
   share 标签就是 GPT-5 生成的；因此**模型标注可以扩 coverage，不能扩 false-share**。于是换问法：
   leak 不是 recall 的函数，而是"发布规则命中私有行"的频率 —— 任何"必然私有"的语料都能测。
   3,000 条那样的话给出 leak **1 条**（Wilson 上界 **0.19%**）、coverage **87.5%**，
   而在 1,467 条 persona 属性上 coverage 是 **28.4%**（与 60 条的 26.7% 一致）`[POC-6]`。
9. **共享侧几乎是空的**：把规则用在一次真实运行**实际展示给读者的 59,675 条轮次**上，只有
   **0.52%** 可共享，且 **63.6% 的问题共享窗口为空** —— 不是"证据更少"，是"一条都没有" `[POC-7]`。
   这条读数改写了拓扑 C/D 的产品叙事（§2.4）。
10. **边界优先于分数**：物理分离的代价已被定价 —— 只信规则时，共享任务只能看到 **4/8** 条
   本可共享的事实；完美确认卡片才能到 **8/8**；而把 `defer` 默认成共享，会立刻发布
   **3/12** 条私有事实且无法收回 `[POC-5]`。这就是"队列必须存在"的算术。
11. **端侧的承诺已由产品代码兑现，不再只是原型**：`cortex-storage/opfs` 在 Chromium 145 上跑
   的是**发货的那份代码**——2,000 行单事务写入 **12,763 行/秒**、读回 15.7 ms、**跨浏览器重启
   摘要逐位相同**；同一批数据**逐条提交只有 178 行/秒**（每笔 5.6 ms），因为该 VFS 的
   `journal_mode` 是 `delete`，每笔都是一次完整提交。**因此批量写必须走事务，这不是优化建议
   而是数量级**（02 §3.4）。

## 1. 产品定位

| 维度 | Cortex |
|---|---|
| **是什么** | TypeScript 优先的智能体记忆中间件，Node 与浏览器同一套核心算法 |
| **不是什么** | 不是数据库、不是向量库、不是 LLM 框架、不是垂直编码 Agent、不是云服务 |
| **核心价值** | 把"记忆的大脑"（选择、巩固、遗忘、弃权、冲突消解、时序、披露）做成可插拔、可溯源、可测量的认知层 |
| **差异化** | 嵌入式优先 + 远程可扩展 + **浏览器原生且真持久化** + 零外部服务依赖 + **披露决策不交给模型** |
| **目标用户** | 需要长期记忆与跨会话一致性的 Agent 构建者：编码 Agent、个人助理、多智能体系统、RAG 增强 |
| **不可让渡的约束** | 可溯源（每条记忆可指回原始轮次）；可证伪（每个声明有 run id 或 POC）；不静默降级（拒绝而非兜底） |

### 1.1 四种部署形态与信任模型

形态的分歧不在功能，在**数据在哪里、谁能看见**：

| 形态 | 引入 | 数据在哪 | 缺省行为 |
|---|---|---|---|
| **A 纯浏览器** | `cortex-storage/opfs` + `cortex-ai/remote` 或 `/local` | 只在用户设备 | 全私有；无共享知识 |
| **B 纯服务端** | `cortex-storage/sqlite` 或 `/pg` | 只在服务器 | 全共享；无跨设备 |
| **C 双端（读合并）** | A + B + `FederatedStorage` | 私有在本地，共享在远端 | 私有任务读两库；共享任务只读远端 |
| **D 双端（写分诊）** | C + 分诊层 | 同上，写入时按卡片决定去向 | `defer` 一律落本地 |

三条定位声明，每条都有实测支撑：

1. **端侧能跑，两个引擎都测了，而且产品代码也测了**：SQLite-WASM + OPFS 在 Chromium 里跨
   **浏览器进程重启**保住 10,000 行，摘要逐位相同（`128079214`），写入 56,850 行/秒，
   checkpoint 0.8 ms，主键点读 0.047 ms `[POC-1]`；在 **Safari 26.6** 上 `opfs-sahpool`
   句柄池可用，写 1,000 行 72 ms（13,889 行/秒）、checkpoint 1 ms `[POC-1]`。两件事不同：
   前者是**重启后仍在**，后者是**句柄池能装上、能读写**（WebDriver 会话没有重启测试）。
   **实现阶段第 3 步把原型换成了发货代码**：`cortex-storage/opfs` 在 Chromium 145 上，
   2,000 行单事务 157 ms（**12,763 行/秒**）、全表读回 15.7 ms、跨重启摘要一致；
   逐条提交只有 178 行/秒 `[实测]`（02 §3.4、04 §9.6）。
2. **隐私是"数据不出去"，不是"我们承诺不看"**：私有事实默认落本地，共享写入需要用户点一下；
   而"点一下"之前，规则层已经把 12 条私有事实全部拦住 `[POC-4]`、`[POC-5]`。
3. **不把"该不该说"交给模型**：外部基准实测前沿模型在该判断上属性级违规最高 **69%**、
   随使用累积（0.1%→9.6%→25.1%）、加隐私提示词更差 `[文献]`。分工是**模型抽取、规则披露、
   用户盖章**。

### 1.2 与竞品的定位差异

- **Mem0** = 记忆的 MySQL：通用、便宜、认知浅，作用域四维（user/agent/run/app）值得照抄。
- **Letta/MemGPT** = 记忆的操作系统：唯一把写入权交模型，工程最重、每次分页额外一次 LLM 调用。
- **Zep/Graphiti** = 时序知识图谱：把"什么时候为真"做对了，但把"谁能看"留给了应用。
- **A-MEM / HeLa-Mem** = 自组织与赫布动力学：学术最强，无生产化。
- **Exabase M-1** = 管线工程的最佳样本：三阶段重建式检索 + 一致性重排，小阅读器登顶。
- **Cortex** = 认知层 + **披露层**：前者的护城河是数学（巩固、弃权、双时态），后者的护城河是
  **把不可靠的判断从模型手里拿走**。

#### 2.1.1 为什么复刻 M-1 而不是 ASMR

M-1 的 96.4% 出现在 **top-50** 而不是 top-200（top-200 反而 95.4%），说明**排序有效**，
不是靠堆上下文；它用统一提示词、不按题型定制，并主动披露基准含至少 4 道错题。

ASMR 的 98.6% 来自"8 条专家 prompt 并行、任一路答对即算对"——**真实部署里没有这个裁判**，
且成本 ×8。**复刻 M-1 的方法，不复制 ASMR 的择优。**

M-1 最值得抄的是第三阶段：**用重要性 / 时序链解析 / 跨记忆一致性重排**，使上下文"不仅相关，
而且内部自洽且顺序正确"。cortex 当前**完全没有重排**，这是复刻清单的第一项。

> **一次必须记录的自我否定**：重排被列为 P0 之后，两臂实测 Δ 为 **+1.33 / −1.33 pp**
> （p 均 0.7539，MR 0 vs 0）`[实测]`。诊断（63.08 pp 排序损失）成立，处方（重排能回收它）
> 不成立 —— 归因显示真正可回收只有 **11 题 = 2.2 pp**，其余 259 题已被阅读器吸收。
> 于是"补重排"从 P0 降级，**改为默认关闭**。这条否定留在白皮书里，因为它示范了本文档
> 要求的方法：**诊断与处方是两件事，前者不蕴含后者**。

| 路线 | 代表 | 主张 | Cortex 取舍 |
|---|---|---|---|

### 2.3 我们自己的位置（唯一可执行的对照）

竞品表里每个数字都来自**各自的读取器、提示词、裁判**，只能用于"谁在什么能力上强"，
不能用于"我们差多少"。本项目自己的对照是同一份裁判、同一份数据、同一条参考管线：

| 能力 | 参考管线（单次） | Cortex（四次均值） | 区间 | 并集（单次） |
|---|---|---|---|---|
| IE 信息抽取 | 2/150 | **134.25** | 133–135 | 135 |
| KU 知识更新 | 0/72 | **62.5** | 60–64 | 64 |
| ABS 应弃答 | 30/30 | 29.25 | 29–30 | 30 |
| **MR 多会话推理** | **105/121** | **84.25** | 81–88 | 109 |
| **TR 时序推理** | 87/127 | **94.75** | 94–95 | 108 |
| 合计 | 224 | **405.0** | 397–412 | 446 |

三条读法：

1. **TR 领先参考管线约 8 题，MR 落后约 20 题**，且 MR 是唯一净负的能力 —— 对外叙事必须
   围绕这一点，而不是总分。
2. **并集 446 是单次读数，不是承诺**。它表示"两条管线合起来覆盖过 446 题"，其中 39 题可回收
   （MR 25、TR 13、IE 1）。**目标线是 446，不是"把 405 提到 94"**。
3. **两条结构性差异已被测掉**：本 arm 只检索用户轮（采纳后占比 100%、窗口 144→174 turn），
   参考管线窗口只有 24,000 字符（本 arm 48,000 已用尽边际）。且**本基准的 gold 恰有一半在
   助手轮**（`totalAll/total = 2.0`），所以"只读用户轮"按构造丢掉一半 gold 而准确率不降 ——
   丢掉的那半边是复述 `[实测]`。

### 2.4 共享侧究竟有多少东西可分享（`[POC-7]`）

前面几节都在问"私有会不会漏出去"。反过来那一问同样重要，而且此前没人回答：**如果记忆被真的
分成两库，共享任务还剩什么可读？**

把规则表用在一次真实运行**已经展示给读者的** 59,675 条轮次上（500 题，`39699987781` 的产物）：

| 量 | 读数 | 含义 |
|---|---|---|
| 可共享轮次 | **310 / 59,675 = 0.52%**（95% CI 0.46–0.58%） | 共享库几乎是空的 |
| 共享窗口为空的问题 | **318 / 500 = 63.6%** | 这些题在共享任务里**一条证据都没有** |
| 至多一半轮次可共享的问题 | 500 / 500 | 共享任务永远在信息不足下工作 |
| 发布规则命中 | 413 条，其中 **103 条（24.9%）** 被更早的私有规则否决 | 顺序的价值，在真实文本上量出来 |

**这不是"规则太严"，是语料性质**：LongMemEval 是个人助理式对话，用户谈的是自己的身体、钱、
家人、日程，很少谈"我们团队/这个项目"。所以读数必须带边界：**在个人助理负载上，共享侧是空的；
在工作协作负载上会不同，但那份语料本仓库还没有。**

**它改写了一条产品叙事**：共享知识不能靠"从私有证据流里过滤出来"，那会得到 0.52%；它必须是
**卡片写出来的** —— 用户明确说"这条可以共享"，才产生一条共享事实。于是卡片队列不只是
"规则没判的那 3/4"，它还是**共享库的唯一来源**。02 §6.3 的读侧策略据此改写。

## 3. 调研覆盖矩阵

规则：**每个技术域必须写清"现状 / 借什么 / 不借什么及原因 / 复刻落点"**。没有落点的域，
要么列入缺口，要么明确排除并给理由。这是本白皮书唯一可被检查的完备性声明。

| # | 技术域 | 关键现状（出处） | 我们采用 | 我们拒绝（原因） | 复刻落点 |
|---|---|---|---|---|---|
| D1 | **浏览器存储引擎** | DuckDB-Wasm 2026-09 起支持 `opfs://`，但 npm `latest` 曾"建了文件从不写入"，须锁版本 `[文档]`；PGlite 的 OPFS-AHP 在 Safari 撞 252 句柄上限 `[文档]`；官方 SQLite-WASM 提供 `opfs` 与 AHP 两种 VFS `[POC-1]` | SQLite-WASM + AHP 作记录层 | DuckDB 作记录层（OLAP 与点写相反）；PGlite 作默认（整库入内存 + 每次查询整文件刷盘） | F1 → 02 §3 |

## 5. 创新主线（每条都带状态）

### 5.1 价值驱动写入 + 主动弃权

**超越对象**：Mem0（无弃权）、Mem-π（有弃权但黑盒）、Letta（自主但贵）。
**机制**：把"是否写入 / 是否检索 / 是否作答"统一为带效用的决策；弃权 = 效用低于校准阈值。
**实际状态**：阈值式弃权在评测路径上，**拿到 29.25/30**（参考管线 30/30，即这项我们略输）；
效用决策与 Platt 校准**未接线**。**护城河是设计，不是交付**。

### 5.2 异步巩固 + 检索即巩固

**超越对象**：A-MEM（同步巩固、贵）、HeLa-Mem（未生产化）、Mem0/Zep（无独立巩固通道）。
**机制**：后台 worker 做赫布边权 → FSRS 衰减 → OT 约束的跨层蒸馏 → TD(λ) 信用分配。
**实际状态**：`consolidate()` 只做三件事（FSRS 状态更新、共激活边强化、阈值遗忘）；
`sinkhorn` 已导出**从未被调用**且其收敛检测器曾恒报"已收敛"（04 §4 #6）；**TD(λ) 全仓不存在**。
**因此本节不构成护城河声明**，只构成路线。

### 5.3 披露边界：把"该不该说"从模型手里拿走

**超越对象**：所有把记忆当"前缀文本"注入的产品 —— 它们的上下文窗口越大，泄漏越严重。
**机制**：四层分诊（确定性规则 → 本地 NER 脱敏预览 → 模型提议卡片 → 用户盖章），
物理分离的两库，读侧只读允许的库。
**实际状态**：**这是唯一有端到端实测的新主线**。`[POC-4]` 规则层 0/12 false-share
（Wilson 上界 24.2%）、覆盖 26.7%、10 轮逐条一致；`[POC-5]` 端到端 0/12，并在故障注入下
证明守卫真的会拦（guard off 时同一注入落到窗口里）。
**它的价值不在提高分数，而在消除一类不可逆错误** —— 因此判定用绝对阈值（>0 即失败）。

**在 1,467 条真实候选事实上复核**（`[POC-6]`，10 个 persona、10 个领域）：coverage **28.4%**
（95% CI 26.1–30.7），与 60 条标注集上的 26.7% 一致 —— 说明"规则只决定约四分之一"不是小样本的
偶然。同一轮里发现并修掉一个真实缺陷：健康规则对生理测量完全沉默（"blood pressure 138 over 86"、
"liver function test 的 ALT 28"、"每晚 7.5 小时睡眠"），补上 vitals 词族后 coverage 24.9% → 28.4%，
而 60 条标注集上的三项指标**一位未动**（0/12、26.7%、85.0%）。这是"新语料 → 发现缺陷 → 政策
可辩护的修补 → 无回归"的完整闭环。

**同一轮也否掉了一个诱惑**：在这份语料上 leak 是 **0/1,467**，看起来像"上界 0.26%"的漂亮数字。
实际上发布规则 `org-knowledge` **一次都没命中**（0/1,467），所以那个零是**结构性零** ——
语料根本没给规则出错的机会。报告里因此把 leak 写成 **NOT MEASURED**，而不是写成一个上界。

### 5.4 工程差异化

Node + 浏览器同一套核心算法；零外部进程依赖；嵌入式优先；全维度覆盖率 ≥95% 且**无 mock**；
CI 真实全绿（不允许 `continue-on-error` / `|| true`）。这些纪律本身构成壁垒：**它让"我们的
数字"可被复核**，而竞品的数字多数只是自报。

## 7. 风险与诚实边界

1. **"融合所有优势"是陷阱**：明确选主线，其余可插拔，不做架构杂糅。
2. **弃权阈值校准难**：需留出集 + 校准曲线 + 多次运行 + 显著性；单次命中不算。
3. **巩固通道的计算代价未知**：赫布 + OT 规模化后昂贵，且**目前根本没接线**，成本无法估计。
4. **竞品报告值不可直接采信**：Mem0/Zep/Letta 的分数来自单侧报告；我们的对标只在同管线上做。
5. **参数化路线不采纳**：与可溯源底线冲突。
6. **"管线 > 阅读器"在 cortex 自己身上尚未验证**：该结论来自 Hindsight 的跨阅读器对比
   （+7.8pp）与 M-1 的存在性证明，属于**外部证据**。要把它变成我们自己的知识，必须做一次
   受控换读者实验（同管线、同题集、只换读者），**且首次运行必须先"对照自身"测噪声底**。
7. **认知层可能被证伪**：`cortex-core` 的认知层从未在评测路径上运行过，净贡献**未知**。
   在完成消融前不应假设它带来增益 —— 图扩散激活的实测回滚（TR 77.95%→70.87%）是
   "理论上应当有效"却有害的先例。
8. **自研基准的固有风险是"配置无法抵达测量"**：链路横跨 TypeScript 与 Python、dispatch →
   workflow → CLI → 产物四层，任何一层静默丢弃都不报错。已出现多次，对策不是更谨慎，
   而是**双向断言闸 + 产物自审**（04 §3）。这也是我们与厂商自报在方法论上真正拉开差距的地方：
   **不是分数更高，而是分数的来源可复核**。
9. **测量宿主是被低估的变量，而且它真的只是宿主**：本轮两次"无法测量"都不是设计问题 ——
   Safari 缺的是 macOS，Hub 语料缺的是网络，而把仓库设为 public 之后**两条链一次跑通**。
   这条经验的用处不是"我们很能干"，而是：**下次看到"环境不支持"，先把它拆成"缺哪台机器/哪个
   权限"，再决定要不要放弃。**
10. **结构性零比噪声更容易骗人**：如果被测机制一次都没机会触发，零就不是上界而是空白。
    `[POC-6]` 的 leak 列因此显式写成 NOT MEASURED（§5.3）。
11. **披露层只覆盖约四分之一**（26.7% / 28.4%，两个语料一致）：另外四分之三靠人。
12. **端侧的"每笔一次提交"是产品约束，不是实现细节**：OPFS 这条 VFS 上 `journal_mode` 是
   `delete`（实测），所以一次 `put` 就是一次完整提交，约 **5.6 ms**。写记忆的调用点必须批量
   或走事务，否则单条写入的吞吐只有三位数。这条必须写进 API 文档，而不是留给使用者自己发现。
13. **降级层不做事务**：IndexedDB 的事务无法跨越 `await`（会提前自动提交），所以 `./idb` 上
   `transaction()` **抛错而不是假装原子**。用户落到降级层时，产品应当告知"本次运行没有事务"，
   而不是让他以为有。因此产品承诺只能是"私有事实默认不出设备"，
   不能是"系统知道什么该说"。输出侧泄漏（模型在共享任务里顺口说出私有事实）**本设计不覆盖**。
